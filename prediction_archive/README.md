# prediction_archive — 公開時点の予想を固定保存する場所

```
prediction_archive/YYYY-MM-DD/{race_id}.json
```

🔴 **ここのファイルは公開後に書き換えない。** これが商品の最大の信用材料
（Phase 4 §18・§19）。`src/product/archive.py` が上書きを拒否する
（`AlreadyPublished`）。テストで固定してある。

## なぜ `data/latest.json` では足りないのか

`latest.json` は**当日の refresh で上書きされる**。2026-09-19〜22 に実害が出ている
（遅延発火した refresh が翌日予想を巻き戻した）。したがって
「公開後に予想を変更していない」ことを読者に示すには、公開時点のファイルが
**別に永続する**必要がある。

## 何が入っているか

公開時刻・AI順位（AI+市場 / AI単独 / 適性）・市場人気・オッズ・印・見解・買い目・
推奨配分・レース信頼度・**入力の指紋（SHA-256）**。結果は `result` キーに**後から追記**する
（予想部分は1つも変更しない。`attach_result()` が検算して変わっていたら落ちる）。

## 外れた予想も消さない

§19 のとおり。的中だけを並べると景品表示法の優良誤認のリスクがあり、
そもそも「事前に公開していた」という事実自体が信用の源なので、
消すと商品価値そのものが消える。

## git 履歴も証拠になる

このディレクトリはリポジトリに含める（`.gitignore` しない）。
ファイルの内容とコミット時刻の両方が残るので、
「後から書き換えていない」ことを第三者が確認できる。
