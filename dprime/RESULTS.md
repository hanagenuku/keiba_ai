## 🟡 Step 1（1回目・2026-09-13 08:47 JST）— **ワイド盤は完璧・複勝盤のパースが壊れていた**

日曜（中山・阪神）の全12レースで初めて実測した（run 34726334544）。

### ✅ ワイド盤は3つとも完全に通った

```
Σワイド  3.815 / 3.826 / 3.891 / 3.868 / 3.819 / 3.878 / 3.868 / 3.865
         3.843 / 3.822 / 3.846 / 3.869          （理論値 3.871）
軸馬の決め方   見出し 100%（推測 0表）  ← 保険は一度も発動していない

組数           45 / 55 / 78 / 120 = C(10,2) / C(11,2) / C(13,2) / C(16,2)
```

実機の構造も確定した:
```
-- table[0] caption='1'                 ← 軸馬は caption に数字だけ
   [('th', '2'), ('td', '33.0 - 35.7')]  ← 行は [相手の馬番, 範囲]
```

### 🔴 複勝盤が **どのレースでも必ず「8頭」**になっていた

```
R01 8頭 組 45/28  Σ複勝 2.458   R03 8頭 組 120/28  Σ複勝 1.184
R05 8頭 組 55/28  Σ複勝 2.369   R12 8頭 組  78/28  Σ複勝 2.338
```
16頭立てでも10頭立てでも 8。**8 は枠の数**。
単複ページは **枠に rowspan** が付いていて（1枠に2頭）、2頭目の行は
先頭セルが1つ足りない。列位置をそのまま使うと2頭目が丸ごと落ちる。

🔑 **見出しから列を引いていても、行側がずれていれば意味がない。**
2026-08-03③（結果ページの列崩れ）を踏まえて「見出しで引くから安全」と
書いたが、それは列方向の話でしかなかった。

🔑 **頭数を複勝の件数から取っていたのも誤り。** そのせいで
「8頭立てなのに組が120」という矛盾した表示になり、一見**ワイド側が
壊れているように見えていた**。実際に壊れていたのは複勝のほう。
頭数はワイド盤（Σ で独立に検算できる）から取るように直した。

### 修正
- `expand_table()` で rowspan/colspan を展開してから列を引く
- `field_size_from_wide()` で頭数はワイド盤から取る
- `fuku_complete`（複勝が頭数ぶん揃っているか）を判定に追加
- 軸馬は caption のみから読む（行の `<th>` は相手の馬番なので誤読の元）
- プローブは単複盤の生構造も rowspan 付きでダンプする

回帰テストで、修正前の実装が16頭立てで **8頭** しか返さないことを再現済み。

## 🟡 Step 1・Step 2 — 計測を実装（2026-09-12）

`src/betting/wide_book.py` を新設し、`probe_wide_odds.py` から全レースで回す。
**次の自動実行（日曜 08:10 JST）で実データが出る。**

| 何を測るか | 判定 |
|---|---|
| 組が C(n,2) 通り揃っているか | 欠ければ Step 1 未通過 |
| Σ_A 1/o_A ≈ 3/(1−0.20) = 3.750（複勝） | ±15% を外れたら盤を疑う |
| Σ_pairs 1/o ≈ 3/(1−0.225) = 3.871（ワイド） | 同上 |
| Σ_A q_A = 3 の残差 | **代数的に自動成立するので、ズレたら実装が壊れている** |
| 全変動 Σ|d_A|/2、max|d_A| | min / max / 中点の3通りで出す |

🔴 **8頭立て以上に限定した**（`MIN_FIELD_SIZE = 8`）。
5〜7頭は複勝が2着払いなので恒等式の右辺が別物になり、混ぜると
実在しないズレを「不整合を発見した」と誤報告することになる。

🔴 **範囲表記が最大の交絡**。ワイドも複勝も min-max で出るので、
min / max / 中点の3通りとも同符号・同じ桁でなければ、それは
範囲表記の扱いの産物であって市場の不整合ではない。3通りとも出力する。

### 軸馬の読み方だけ、まだ実機で確認できていない

ワイド盤は「軸馬ごとに1テーブル・各行は [相手の馬番, オッズ範囲] だけ」という形で、
**軸馬の番号が行に書かれていない**。テーブルの並び順に依存すると取消馬が出た瞬間にずれる。

そこで軸馬は**見出し（caption/th）から引き、取れないときだけ
「その表の最小の相手番号 − 1」で補う**形にし、どちらで決めたかを
`axis_source` として必ずログに出す（推測が混ざったまま数字を出さないため）。
プローブは1レース目のワイド盤の**生の表構造をそのままダンプ**するので、
次の実行のログで見出しの有無が確定する。North Star #6。
