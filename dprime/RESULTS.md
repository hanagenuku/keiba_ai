### 券種は CNAME の4文字目で分かれていた

```
単勝・複勝  pw151ouS306202604030120260912Z/EE
枠連       pw153…Z/F6
馬連       pw154…Z/7A
ワイド      pw155…Z/FE      ← これ
馬単       pw156…Z/82
3連複      pw157…Z99/68
3連単      pw158…Z/8A
```

🔴 **suffix は券種ごとに違う**（EE / F6 / 7A / FE / 82 / 68 / 8A）ので、
単複の CNAME から文字列置換では作れない。単複ページの `<a>` から取ること。
3連複だけ `…Z99/68` と余分な `99` が付く。

### 返ってきた盤

```
--- ワイド (accessO.html) ---
  タイトル: ワイドオッズ（馬番順）　JRA
  table 12  組番 48  範囲 66  単値 132
    ['2', '5.9-6.6']  ['3', '20.5-22.1']  ['4', '98.6-103.3'] …
```

範囲 66 = C(12,2)。12頭立ての全組が**範囲表記**（min-max）で並ぶ。
馬連（単値66）・3連複（220）も同時に取れることを確認した。

🔑 2026-09-06 に否定した「CNAME の `Z` が券種の指定子」という仮説は正しく否定されていて、
入口は**単複ページのナビゲーションリンク**だった。方針変更（PR #231）が当たった。

## 🟡 Step 1・Step 2 — 計測を実装した。データ待ち（2026-09-12）

`src/betting/wide_book.py` を新設し、`probe_wide_odds.py` から全レースで回す。
**次の自動実行（日曜 08:10 JST）で実データが出る。**

| 何を測るか | 判定 |
|---|---|
| 組が C(n,2) 通り揃っているか | 欠ければ Step 1 未通過 |
| Σ_A 1/o_A ≈ 3/(1−0.20) = 3.750（複勝） | ±15% を外れたら盤を疑う |
| Σ_pairs 1/o ≈ 3/(1−0.225) = 3.871（ワイド） | 同上 |
| Σ_A q_A = 3 の残差 | **代数的に自動成立するので、ズレたら実装が壊れている** |
| 全変動 Σ|d_A|/2、max|d_A| | min / max / 中点の3通りで出す |

🔴 **8頭立て以上に限定した**（`MIN_FIELD_SIZE = 8`）。
5〜7頭は複勝が2着払いなので恒等式の右辺が別物になり、混ぜると
実在しないズレを「不整合を発見した」と誤報告することになる。

🔴 **範囲表記が最大の交絡**。ワイドも複勝も min-max で出るので、
min / max / 中点の3通りとも同符号・同じ桁でなければ、それは
範囲表記の扱いの産物であって市場の不整合ではない。3通りとも出力する。

### 軸馬の読み方だけ、まだ実機で確認できていない

ワイド盤は「軸馬ごとに1テーブル・各行は [相手の馬番, オッズ範囲] だけ」という形で、
**軸馬の番号が行に書かれていない**。テーブルの並び順に依存すると取消馬が出た瞬間にずれる。

そこで軸馬は**見出し（caption/th）から引き、取れないときだけ
「その表の最小の相手番号 − 1」で補う**形にし、どちらで決めたかを
`axis_source` として必ずログに出す（推測が混ざったまま数字を出さないため）。
プローブは1レース目のワイド盤の**生の表構造をそのままダンプ**するので、
次の実行のログで見出しの有無が確定する。North Star #6。
