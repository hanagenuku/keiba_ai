# オッズ時系列 検証の事前登録基準

**書いた時点: 結果を一切見ていない。** 以下は数字を見る前に確定させる。

## 問い

**最終オッズ（締切直前の水準）を統制した上で、オッズの「時間変化の経路」に追加情報が残っているか。**

「オッズが下がった馬は強い」という問いではない。それは 2026-08-03 に否定済み
（最も買われた10%は複勝回収58.2%で無作為80%より悪い）。
ここで問うのは **水準では表現できない情報が経路にあるか** の一点。

## なぜ今やり直すのか

前回（2026-08-28 O1）の予備測定は **AUC +0.0001** だったが、
観測が「朝 → 後刻」の2点で、3回以上取れたレースは405中55しかなかった。
「変動に情報が無い」と「2点しか持っていない」を区別できていなかった。

いまは 2分間隔・発走75分前〜0分・1レース約36観測点が自動で溜まる。

## データ

- 対象: `odds_snapshots` で観測点20以上のレース
- 現時点: **55レース / 2開催日（2026-09-05, 09-06）**
- 着順は `race_predictions.actual_place` から取得

## 🔴 N についての事前の申し合わせ

**55レース・2開催日では、この問いに「答えが出ない」ことを先に認める。**

- 日ブロックbootstrapはブロックが2つしかなく成立しない
- 700頭で検出できる相関は |r| > 0.075 程度。それ未満の効果は見えない
- したがって **基準未達を「否定」と読まない。「まだ測れていない」と読む**
- 逆に、**この N で何か大きく出たら、まずリークか計測器の故障を疑う**（North Star #8）

判断を確定させるのは N>=500レース（約2ヶ月）。North Star #7 に従うなら N>=2,000（約8.5ヶ月）。

## 特徴量（経路から作るもの）

ユーザーが挙げた7項目をそのまま実装する。すべて**締切前に手に入る情報のみ**。

| # | 名前 | 定義 |
|---|---|---|
| 1 | 変化率 | `log(final/first)`, `log(final/T-30)`, `log(final/T-10)` |
| 2 | 人気順位の変化 | `rank_first − rank_final`, `rank_T-10 − rank_final` |
| 3 | 相対的な変化 | その馬のlog変化 − レース内平均log変化（市場全体の動きを除去） |
| 4 | 締切直前の急変 | `log(final/T-5)` とそのレース内z-score |
| 5 | 変化のタイミング | 最大変化が起きた時点の `minutes_to_post` |
| 6 | 反転（下げて戻る） | 経路の最小値からの戻り幅 / 単調性（経路長 ÷ 直線距離） |
| 7 | 特異的な動き | 相対変化のレース内z-score、市場全体が動く中でその馬だけ動いたか |

## モデル（増分を測る）

| | 入る情報 | 意味 |
|---|---|---|
| **M1** | 最終オッズのみ（レース内正規化した市場示唆確率） | ベースライン |
| **M2** | M1 + 最初の観測点（2点） | **旧検証（2026-08-28）と同等** |
| **M3** | M1 + 経路特徴量すべて（36点） | 密な時系列 |
| **M4** | M1 + 本番AIの `cal_prob` | 実運用のベースライン |
| **M5** | M4 + 経路特徴量すべて | **実際に効くかどうかの本命** |

- 学習/評価は**レース単位の5分割CV**（同一レースが学習と評価にまたがらない）
- 目的変数は **3着内** と **1着** の両方
- ロジスティック回帰（N が小さいので木は使わない）

🔑 **M3 − M2 が「密にした意味があるか」の答え。** ここが前回測れなかった部分。

## 採用基準（すべて満たして初めて「効いた」と言う）

1. **AUC増分 >= +0.005**（M5 − M4、および M3 − M1）
2. 最終オッズを統制した**偏相関の95%CIが0を含まない**
3. **対照群を通ること**: 経路をレース内で馬にシャッフルした偽経路で、同じ増分が出ないこと
4. **複勝回収率**でも同方向（North Star #9。AUCが上がっても回収率が上がる保証はない）
5. **開催日をまたいで再現する**（現時点では2日しかないので、この基準は今回判定不能）

## 打ち切り基準

- N>=500レースの時点で、基準1〜3のいずれも満たさなければ**打ち切る**
- ただし N<500 の段階では打ち切らない（収集コストはほぼゼロなので回し続ける）

## 計測器の検算（結果を見る前に通す関門）

North Star #8 と 2026-08-25 の教訓（関門そのものが壊れていた）を踏まえ、以下を先に置く。

1. **最終オッズだけのAUCが 0.75〜0.85 に入るか**（入らなければ結合か正規化が壊れている）
2. **`Σ(1/最終オッズ)` が 1.20〜1.35 に入るか**（控除率20%。外れたら盤が壊れている）
3. **経路特徴量に NaN/inf が無いか**。`not (x <= t)` 形式で NaN も止める
4. **偽経路（シャッフル）の増分が 0 付近に落ちるか**（落ちなければ統制が効いていない）
5. **勝ち馬が1レース1頭であることを確認**（集計キーに race_id が入っているか）

# 【2026-09-07 更新】GPTとの議論で確定した設計

以下は**測定を実行する前**に確定させた。上の初版から変わった点を明示する。

## 変更点1：経路特徴量を14本 → 3本に絞る

実データの特徴量分布で検出力を較正した結果（ラベルは合成・実着順は未使用）：

```
特徴量の本数 | ノイズ床（真のシグナル=0のときの測定増分） | 標準偏差 | 必要な+0.0225は何σ上か
   14本      |            -0.0136                    | 0.0088  |  2.5σ
    6本      |            -0.0067                    | 0.0061  |  3.7σ
    3本      |            -0.0043                    | 0.0053  |  4.2σ
    1本      |            -0.0011                    | 0.0045  |  5.0σ
```

N=737頭では14本は雑音で自滅する。**3本に固定する：**

| 特徴量 | 定義 | GPTの分類のどれに対応するか |
|---|---|---|
| `rel_move_z` | (その馬のlog変化 − レース内平均log変化) のレース内z-score | 他馬に対する相対的な上昇・下降／最終局面での孤立した動き |
| `last_move_z` | log(final/T-5分) のレース内z-score | 発走直前だけの急落 |
| `wiggle` | 経路長 ÷ 直線距離（単調なら1、下げて戻ると大きい） | 下落後の反発 |

## 変更点2：🔴 判定は「0」ではなく「経験的ヌル」に対して行う

上表のとおり**ノイズ床はゼロではない**。無意味な特徴量を足すだけで測定増分は負に出る。
`M3 − M1` を 0 と比べると**偽陰性**になる（3本でも −0.0043 のバイアスがある）。

**必ずレース内シャッフル対照（経路を馬にランダムに振り直したもの）を同じ本数・同じ手順で回し、
その分布に対して実測増分がどこに位置するかで判定する。**

## 変更点3：合格線を経済的な大きさに置く

「統計的に有意」ではなく「**控除率20%を超えるだけの残差情報があるか**」で判定する。

```
必要な増分 = AUC +0.0225   （回収率 +4.1pt 相当。換算は 0.0055 AUC ≒ 1pt）
```

⚠ ただし測定0で現在地が ρ=1.01〜1.12 と判明したため、
**損益分岐に必要な改善は +4.1pt ではなく +12〜24pt 相当**（AUC +0.038〜0.075）。
+0.0225 は「打ち切らない最低ライン」であって「これで勝てる」ではない。

## 変更点4：GPTの層別テストを併走する（モデルを使わない確認）

モデル側の故障と切り分けるため、**予測モデルを一切使わない**確認テストを同時に回す：

```
最終オッズ帯を固定（例：最終3〜5倍だけ）
  → 経路タイプで分類（急落 / 緩やか下降 / 横ばい / 下げて戻る / 直前急落 / 早期急落）
  → 3着内率と回収率に差があるか
```

差が出なければ「経路情報は最終価格に対する追加情報をほぼ持っていない」という強い証拠になる。

## 変更点5：Nの扱いを訂正

初版では「55レースでは結論が出ない」と書いたが、**これは撤回する**。
検出力較正の結果、**経済的に意味のある大きさ（+0.0225）なら3特徴量・N=737頭で 4.2σ**。

🔑 判定の非対称性：

| 結果 | 何が言えるか |
|---|---|
| ヌルに対して有意な増分が出ない | ✅ **経済的に意味のある大きさの経路情報は無い。打ち切ってよい** |
| 有意な増分が出る | ⚠ **暫定。**2開催日しかないので開催日をまたいだ再現が必要 |

**null は決定的、positive は暫定。**
