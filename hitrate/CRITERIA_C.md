# 事前登録カード C: 「1番人気を超える根拠」で◎を差し替える

作成 2026-11-10（測定前）。ユーザー依頼:
「一番人気が1番一位になる可能性が高いのはわかるが、1番人気以外の馬が1番人気より
高い順位になるかもしれない根拠を考察し、その根拠が1番人気を超える可能性が高ければ
その馬を推奨するようなロジックにしたい」

🔴 **このファイルは測定前にコミットする。実行後は1文字も変えない**（検証の決まった手順）。
基準は §7（C-1）・§8（C-2）に書いたものだけで判定する。閾値・窓・目的変数を結果を見てから動かさない。

## 1. いま何が起きているか（機序・測定ではなく算術）

本番の順位 `AI+市`（= `rl_rank`）は残差学習の margin で並ぶ。

    raw_margin(馬) = base_margin(その馬の人気順位) + tree(その馬の129特徴量)
    ability_margin(馬) = raw_margin − base_margin          ← 「市場を見ないAIの評価」

`base_margin` は人気順位の Zipf 近似（`src/features/engine.py::_base_margin_from_popularity`）。
その値は**人気順位だけ**で決まるので、1番人気を追い抜くために必要な ability_margin の
差は固定の階段になる（14頭立て）:

| 相手の人気 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|
| 1番人気との base_margin 差 | 0.90 | 1.36 | 1.68 | 1.92 | 2.11 | 2.27 | 2.41 |

一方 ability_margin のレース内 SD は約 0.58（本番実測）。つまり

- 2番人気が1番人気を抜くには ability_margin で **約1.5σ** の優位が必要
- 4番人気なら **約2.9σ**
- 6番人気なら **約3.6σ**

これが「◎は予測時点の1番人気とほぼ常に同じ馬（本番15開催日で96〜100%・4番人気以下は
全日0本）」の原因である（`hitrate/RESULTS_A.md` §4）。**AIが遠慮しているのではなく、
土台の目盛りが木の出力より大きい。**

## 2. 「根拠」は既に計算されていて、既に見えている

本番18開催日・472レースの実測（`data/latest.json` 系列）:

- `AI単`（= `solo_rank` 1位 = ability_margin 最上位）が ◎ と**違う馬**になるレース: **281 / 472 = 59.5%**
- `AI単` 1位の馬の市場人気の分布: 1位 188 / 2位 99 / 3位 61 / 4位 36 / 5位 34 / 6位 16 / 7位 19 / 8位 4 / 9位 6 / 10位 9
- 市場1番人気の `AI単` 順位: 1位 188 / 2位 92 / 3位 56 / 4位 36 / 5位 32 / 6位 19 / …

つまり「AI自身の評価が1番人気と食い違う」ことは**6割のレースで起きている**。
`ability_breakdown`（カテゴリ別 SHAP）まで既に計算済みなので、
**根拠が無いのではない。足りないのは「その食い違いに従ったら当たるのか」の証拠**である。

## 3. 事前の見込み（結果を見てから書き足さない）

従ってはいけない、という方向の測定が既にある。**どれもこのカードとは形が違う**ことに注意する。

| 既測定 | 形 | 結果 |
|---|---|---|
| 2026-07-30 λ=0 | `base_margin` を**完全に**外す | 125頭の大穴を選び勝率0.8%。採用不可 |
| 2026-08-03 | `ability_margin` で並べ替え／「AI強気」度で帯分け | 回収率の傾きが**反転**。強気+6以上は複勝41.4%（過去市場の寄与も抜くと21.8%） |
| 2026-08-31 | corr(gap, 符号つき誤差) | **−0.1213** ＝ 市場と食い違うほどその方向にAIが間違っている |
| 2026-07-05/07-30/08-31 | `EV = AI確率 × オッズ` で選ぶ | 3回とも否定（EV>=1 は回収57.9%） |
| 2026-08-29 GAP | 素のAI推しで買う | 複勝33.9%・回収77.5%。避けた1番人気75.9%と区別できない |
| 2026-08-17 天井 | 市場のみ vs 129特徴量（AUC） | 0.8041 → 0.8050（**+0.0009**）＝ 順位情報の余地はほぼ無い |

🔴 **この表から素直に読める期待値は「不採用」である。** 特に 2026-08-17 の天井は、
「市場より良い順位を作る」余地が 0.001 AUC しか無いことを示している。

**それでも測る理由**は1つだけ。上の6件はすべて
「**平均して** AI の食い違いに従う」形（全レース／連続スコアで帯分け／EV 閾値）であり、
ユーザーの依頼は「**可能性が高ければ**その馬を推奨する」＝**較正した確率で絞った部分集合**の話である。
平均が負でも部分集合が正である可能性は、平均の測定では否定されない。
この形（直接のペアワイズ目的変数 + 較正確率の閾値）は**一度も測っていない**。

## 4. 測る腕

### C-1 市場アンカーの部分的な弱化（λスイープ）— 安い腕

    score_λ(馬) = λ · base_margin(人気) + tree(馬)        λ ∈ {1.0, 0.9, 0.8, 0.7, 0.5, 0.0}

λ=1.0 が本番（対照）。λ=0.0 は 2026-07-30 に測った「アンカー外し」で、
**再現しなければ測定器の不良**として停止する（§9 停止条件7）。

⚠ 学習は λ=1 の `base_margin` で行われているので λ<1 の推論は学習/推論パリティを
意図的に崩している（North Star #3）。これは「本番モデルの市場の重みを下げて見せる」
操作そのもので、ユーザーの依頼の最も安い近似である。λ ごとに再学習する形（C-1b）は
C-1 に非劣化域が見つかったときだけ走らせる。

**C-1 で得たいもの**: 「◎を1番人気から動かすには市場の重みをどこまで下げる必要があり、
その代償は何pt か」のトレードオフ曲線。1回の実行で全部出る。

### C-2 「1番人気を超えるか」を直接の目的変数にしたペアワイズ判定 — ユーザーの依頼そのもの

- **P1** = 予測時点の市場1番人気（本番と同じく `_apply_popularity_drift` 後の人気順位で決める）
- 各レースの **X ≠ P1** について目的変数
      y = 1  if 着順(X) < 着順(P1)      （両頭とも着順がある場合のみ。除外・中止はペアごと落とす）
- **特徴量 = 既存129特徴量の差分 Δx = x_X − x_P1 のみ。**
  🔴 `win_odds`・`pop`・オッズ由来の値を特徴量に入れない（North Star #1）。
  市場はここでも「**誰が P1 か**」という土台としてだけ入る（`base_margin` と同じ役回り）。
  この読みに同意できないならこのカードは走らせない。
- モデル: XGBoost binary:logistic。本番と同じ `max_depth=6 / lr=0.05 / min_child_weight=10 /
  subsample=0.8 / colsample_bytree=0.8 / reg_alpha=0.1 / reg_lambda=1.0 / scale_pos_weight=1.0 /
  n_estimators=4000 / early_stopping=50`。シード 42 / 7 / 2026 の3本平均。
- **内側ホールドアウト42日**で早期停止（評価窓を学習にも停止にも使わない）。
  🔴 起点は「学習期間に**実在する最後の日**」から42日前（`history.db` に
  2024-11-25〜2024-12-31 のレースが1件も無い・`docs/history_db_schema.md`）。
- **較正**: 内側ホールドアウトで Isotonic。較正後の確率を P̂(X が P1 を上回る) とする。
- **決定規則**:
      X* = argmax_X P̂(X)   を取り、 P̂(X*) >= τ のときだけ ◎ を P1 から X* に差し替える
      τ ∈ {0.55, 0.60, 0.65, 0.70}（事前登録。結果を見て動かさない）
  τ 未満のレースは**何もしない**（本番そのまま）。

### 窓（両腕共通・walk-forward・2025年が主）

| 窓 | 学習 | 評価 |
|---|---|---|
| W1 | ≤ 2024-12-31（実在最終日） | 2025-01-01 〜 2025-04-30 |
| W2 | ≤ 2025-04-30 | 2025-05-01 〜 2025-08-31 |
| W3 | ≤ 2025-08-31 | 2025-09-01 〜 2025-12-31 |

（`hitrate/CRITERIA_A.md` §3 と同じ扱い）。

## 5. 何で評価するか

レース単位で、◎（据え置き or 差し替え後）1頭について:

- **複勝率**（3着内率）
- **複勝回収率**・**単勝回収率** — `logic2026/eval.py::roi` を**再実装せずに import** する
  （「当たったが払戻が取れない」行は評価不能として落ちる既存の挙動を踏襲）
- **軸AUC**（3着内を正例とした順位の質）
- **◎ ≠ 市場1番人気 となったレースの割合**

🔴 **的中率と回収率は別物**（North Star #9）。的中率が上がって回収率が下がったら不採用。

## 6. 公表する予測の作り方（1つに固定）

margin の予測は `Booster.predict(..., iteration_range=(0, num_boosted_rounds()))`＝**全木**で出す
（本番の `engine.py` と同じ。`tests/test_predict_tree_count.py` で固定済み）。
`best_iteration` までの予測は副として併記するが、**両者が食い違ったら両方報告して採用しない**。

## 7. C-1 の合格基準（すべて満たしたときだけ「非劣化域あり」と書く）

ある λ < 1.0 が次を**同時に**満たすこと。

1. **◎ ≠ 市場1番人気** となるレースが評価窓の **10.0% 以上**
2. ◎の**複勝率**が λ=1.0 比で **−1.0pt 以内**（＝ −1.0pt より良い）
3. ◎の**複勝回収率**が λ=1.0 比で **−2.0pt 以内**
4. 1〜3 が **W1・W2・W3 の3窓すべてで同符号**
5. その λ で単勝回収率が λ=1.0 比 −3.0pt 以内（単複で逆を向いていないこと）

1つでも欠けたら **不採用**。「λ=0.9 なら惜しい」は書かない。

## 8. C-2 の合格基準（すべて満たしたときだけ採用を提案する）

ある τ ∈ {0.55, 0.60, 0.65, 0.70} が次を**同時に**満たすこと。

1. **較正が壊れていない**: 内側ホールドアウトと評価窓の両方で、P̂ >= τ の群の実測
   「P1 を上回った率」が **τ − 0.05 以上**。
   🔴 これが落ちたら「可能性が高い」と言えないので **2 以降は読まない**（§9 停止条件4）。
2. **差し替え発生率**が評価窓の **3.0% 以上**、かつ差し替えレースが **100レース以上**
3. 差し替えた馬の**複勝率** ≥ 据え置いた場合（P1）の複勝率 **+2.0pt**
4. 差し替えた馬の**複勝回収率** ≥ P1 の複勝回収率（**マイナスにしない**）
5. 3・4 が **3窓すべて同符号**
6. 対照群A・B（§10）が両方合格

1つでも欠けたら **不採用**。τ を動かして測り直さない。

## 9. 停止条件（結果より**先に**印字する）

1. 評価窓の**レース数**が 3,000 未満 → 停止。
   かつ **1レースあたりの平均ペア数が 10 未満**（＝頭数が異常に少ない）→ 停止。

   🔴 **訂正（2026-11-10・測定より前・1行も実行していない時点）**
   当初ここに「評価可能ペアが 50,000 未満 → 停止」と書いたが、**使える N を数えずに
   書いた線**だった。実行前に `history.db` で数えたところ 2025年の評価ペアは

       W1 14,910 ／ W2 15,283 ／ W3 13,694 ／ **プール 43,887**（3,442レース）

   で、この条件は**データの算術によって必ず発火する**。中止条件の役目は「少なすぎる
   データで結果を読まない」ことであり、判定の実質的な検出力は §8 基準1（較正）と
   §8 基準2（差し替えレース >= 100 かつ >= 3.0%）が担っている。そこで、
   **使えるペア数に合わせて線を下げるのではなく**、条件1を「母集団が大規模 OOS として
   成立しているか」（`danger/` や `logic2026/` と同じレース数の尺度）に置き換えた。
   §8 の合格基準は1つも緩めていない。
   （前例: 候補B で σ=1.0 が宣言した帯の外だったのを測定前に 1.8 に直した・
     候補A で内側HOの起点を 2024-12 の穴に当たらない形に直した。
     **合格線を下げて測り直すことはしない**・2026-10-21）
2. どの τ でも差し替えレースが 100 未満 → **「対象が存在しない」として停止**（候補Aと同じ形）
3. 内側ホールドアウトの行数が 1,000 未満 → 停止（2024-12 の穴に当たっている）
4. §8 基準1（較正）が不合格 → 以降の数字を読まない
5. 評価窓の 5% 超のレースで P1 を特定できない（予測時点のオッズ欠損）→ 停止
6. 対照群B（注入の復元）が復元しない → **測定器の不良**として停止
7. C-1 の λ=0.0 が 2026-07-30 の「大穴ばかり選ぶ」を再現しない → **測定器の不良**として停止

## 10. 対照群（North Star #11）

### 対照群A ＝ 並べ替え分布

**統計量**: 差し替え対象レース i について
`Δ_i = 1{差し替え馬が3着内} − 1{P1が3着内}`。実測は `mean(Δ)`。
**帰無**: Δ_i の**符号をランダムに反転**（ペアの符号反転）して 200 回。
**合格**: `|mean(Δ_shuffle)| < 2 · std(Δ_shuffle) / √200`。

🔴 **「ランダムに選んだ馬 − P1」を帰無にしない。** P1 に技量があると差は構造的に
負に寄るので、0中心にならない。この形の失敗は 2026-09-22 / 10-19 / 10-21 / 11-10 の
**4回**起きている（直近は `hitrate/RESULTS_B.md` の対照群A-2）。
**閾値はこの統計量の SE（= std/√N）より大きいか**を結果より先に印字する。

### 対照群B ＝ 注入の復元

Δx の1列に既知の信号 `z ~ N(0, σ²)`（σ = 1.8・単独 AUC の理論値 **0.6528**）を
`y` と相関する形で注入し、注入前後の AUC 差が **注入量と ±0.01 で一致**すること。
🔴 「注入後 ≈ 注入量」とは書かない。**注入後 − 注入前 = 注入量**で書く。
