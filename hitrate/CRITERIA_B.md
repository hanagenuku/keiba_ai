# 事前登録カード B: 学習の止まり方（early stopping）を直す

- 登録日: 2026-11-09
- 指示書: `hitrate/INSTRUCTIONS.md` §3（ユーザー指示「候補B → 候補A の順で実行」）
- 🔴 **このカードは測定前にコミットする。結果を見てから閾値・腕・期間・母集団・指標を変えない。**
- 🔴 **測定は1回。** 失敗したら「失敗した」と書いて閉じる（やり直して良い数字を拾わない）。

## 1. 問い

本番の残差学習は early stopping が **10〜11本目**で止まる。これが「信号の飽和」ではなく
**切片（intercept）の通過点**で決まっていると分かった（下記 §2）。
**止まり方を切片に邪魔されない形にすると、完全 OOS の順位付けは良くなるか。**

## 2. 既に分かっている機序（結果を見る前の事実）

`python3 hitrate/inspect_model.py`（本番モデルのファイルだけを読む。レース結果は使わない）:

```
xgboost 3.2.0 / 木の本数 61 / best_iteration 10 / scale_pos_weight 3.58
木ごとの一律の移動（先頭12本） 0.267 0.212 0.177 0.152 0.133 0.118 …
木ごとの馬間の差 SD（先頭12本） 0.057 0.038 0.032 0.027 0.025 0.022 …
  先頭 10本まで: 一律の移動の累計 +1.432 / 馬間の差SDの単純和 0.279
  先頭 61本まで: 一律の移動の累計 +2.675 / 馬間の差SDの単純和 0.920
predict() 既定 と 全木 の最大差 0.0        ← 既定は全木
predict() 既定 と best_iteration まで の最大差 1.687
```

1. `base_margin` は Zipf 近似の**勝率**スケール（レース内の合計が 1）。目的変数は**3着内**
   （合計 3）。モデルはまず全馬を一律に約 +1.3（logit）持ち上げる必要がある。
2. 目的関数には `scale_pos_weight ≈ 3.58` が掛かるので、最適な切片はさらに約 +1.25 上。
3. early stopping の指標は**重みなしの logloss**。切片が +1.3 付近を通過する瞬間（10〜11本目）
   が最良になり、その先は切片が行き過ぎるので悪化する → 50本後に停止 → **常に 61本**。

`python3 hitrate/synth_es.py`（合成データ）で「隠れ信号が 0 でも 0.6 でも best_iteration は
10〜11」を再現した。つまり記録にある「base_margin が土台を担うので10本で飽和する」
（2026-08-24・10-19 ほか）は**誤った説明**だった。

🔴 **ただし直せば良くなるとは限らない。** 合成データでは止まったあとの50本も信号を学ぶので
AUC の差は 0〜+0.003 しか出ていない。**事前の見積りは「小さいかゼロ」。**

## 3. 腕（この3つだけ。結果を見てから設定を足さない）

| 腕 | 設定 |
|---|---|
| **P0** | 本番と同一: `max_depth=6, learning_rate=0.05, subsample=0.8, colsample_bytree=0.8, min_child_weight=10, reg_alpha=0.1, reg_lambda=1.0, scale_pos_weight=(1-r)/r` |
| **P1** | P0 から `scale_pos_weight=1.0` に変えるだけ |
| **P2** | 既に記録にある cid82（`max_depth=5, learning_rate=0.02, min_child_weight=300, subsample=0.8, colsample_bytree=0.8, reg_lambda=5.0, reg_alpha=0.1, scale_pos_weight=1.0`・`mf2/RESULTS.md`）に `base_margin` を付けたもの |

- 3腕とも `residual=True` / **134列**（`f_popularity` を除外）/ ドリフト注入ON /
  **行・順序・`base_margin` 配列は完全に同一**（窓ごとに md5 を出す）。
- `objective='binary:logistic'` / `eval_metric='logloss'` / `early_stopping_rounds=50`。
- `num_boost_round=4000` を**3腕すべてに**使う。本番の既定は 500 だが、P0 は §2 の機序で
  10本付近で止まるので 500 と 4000 で結果は変わらない（best_iteration の印字で確認する）。
  P1 を 500 で打ち切ると「上限に当たった」という交絡が入るため、上限だけ揃えて外す。
- 🔴 **early stopping は学習期間の末尾42日（内側ホールドアウト）で行う。**
  評価窓は学習にも停止判定にも使わない。**P0 もこの形で測り直して比較する**
  （`logic2026/eval.py` と `retrain/ab.py` は評価窓で停止判定しており、止まり方を直すと
  評価窓へのリークになる）。内側HOの切り方は `mf2/mf2_eval.py` / `race_select/prep.py` と同一。

## 6. 評価指標と採用基準（5つすべて必要）

主指標は**プール AUC**（is_fukusho）。◎は「レースごとに予測最大の馬」（同値は馬番の小さい方）。
複勝の払戻は `horse_history.fukusho_payout`。**的中だが払戻が無い行は評価不能として分母から外す**
（`logic2026/eval.py::roi` をそのまま使う。3腕で扱いは同一）。

| # | 基準 |
|---|---|
| 1 | プール AUC: 腕 − P0 >= **+0.002** かつ **シード std の2倍以上**（2026-08-24 のアンサンブル検証と同じ線） |
| 2 | **3窓すべてで同符号**（窓ごとの3シード平均 ΔAUC が3窓とも正） |
| 3 | ◎の複勝的中率が **P0 を下回らない**（3シード平均） |
| 4 | ◎の複勝回収率が **P0 − 0.5pt を下回らない**（素の回収率と**3本抜き**の両方） |
| 5 | 対照群A・B（§7）が両方とも通る |

⚠ 基準3・4 は「的中率を上げても回収率を壊さない」ための**歯止め**であって主測定ではない。
評価窓は約740レースしかなく、回収率の揺れはこの N では大きい（North Star #7）。
**回収率が上がったことを成果として書かない。**

## 7. 対照群（North Star #11 の2つの形。それぞれ統計量ごとに帰無を決める）

**対照群A-1（並べ替え分布・ΔAUC）**: 統計量は「腕 − P0 のプール ΔAUC」。
3窓×3シード＝9個の対応のある差の**符号を全通り（2^9=512）入れ替えた厳密な並べ替え分布**を作り、
実測の平均 ΔAUC の並べ替え P 値を報告する。帰無は「腕と P0 が交換可能」。
（2026-10-21 の教訓「`F − P` を比べるなら並べ替えるのはアームの割り当て」に従う）

**対照群A-2（並べ替え分布・回収率）**: レース内で予測をシャッフルして軸を選ぶ操作を200回。
合格は帰無が0中心（`|mean| < 2*std/sqrt(200)`）。これは「無作為に軸を選んだ時の回収率」との
差を測る計測器の検査であって、無作為と同じという意味ではない。

**対照群B-1（注入の復元・算数の検算）**: 評価対象の全行に一律 +20.0pt を足し、
`注入後 − 注入前 = 20.0pt`（許容 1e-3）を確かめる。代数恒等式の検算なので許容は厳しくてよい。

**対照群B-2（注入の復元・本物があったら検出できるか）**: 市場が見ていない信号を1列だけ
注入する。`z = is_fukusho + N(0, σ)`、**σ = 1.8 に固定**する（理論値 AUC = Φ(1/(σ√2)) = 0.653。
z 単独の評価窓 AUC が **0.63〜0.68** に入ることを印字して確かめる）。
学習・内側HO・評価のすべての行に同じ作り方・同じ乱数系列（seed 固定）で入れる。
合格は **3腕すべてで ΔAUC（z あり − z なし）> 0**。
🔑 この対照群は「P0 の止まり方が本物の信号を取りこぼしているか」を直接測る形でもある
（P0 の回収が P1/P2 より明確に小さければ §2 の機序を支持する）。ただし**採否の判定には
使わない**（基準は §6 の5つだけ）。

## 11. 結果にかかわらずやること

- `RESULTS_B.md` に「`best_iteration` 10〜11 は切片で決まっていた」と機序を記録する
  （`inspect_model.py` と `synth_es.py` が根拠）。
- `requirements.txt` が `xgboost>=1.7` で版を固定していない。`Booster.predict()` が
  early stopping 後に使う木の本数は版によって扱いが違いうるので、`engine.py` の推論で使う
  本数を**今の挙動（全木）のまま明示**し、テストで固定する（**予想は1つも変えない変更**）。

## 12. やらないこと

- 腕を増やす・ハイパラを探索する（cid82 は既に記録にあるものをそのまま使う。新規探索はしない）。
- 本番モデル・較正器を測定中に差し替える（隔離ワークスペースで測る）。
- 閾値（`CONF_STRONG=66` 等）を動かす。
