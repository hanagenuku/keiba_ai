## 0. 結論（カード §9 に先に書いてあった文をそのまま使う）

> early stopping が切片で止まっていること自体は事実だが、止まり方を直しても
> 完全 OOS の順位付けは事前登録した幅では良くならなかった。**本番の学習設定は変えない。**
> 🔴 この結果は「学習設定に伸びしろが無い」ではなく「**この3つの腕では届かなかった**」である。
> 🔴 **候補Bが不採用なので、過去に閉じた検証（websig・oikiri・D-2 など）は開け直さない。**

加えて、**なぜ直しても効かないのかが分かった**（§3）。本番は `predict()` の既定が
**全木**なので、止まったあとの50本を結果的に使っている。順位の面では
**すでに「直った状態」で動いていた**。

## 3. 🔑 機序は完全に再現した（best_iteration は切片で決まっていた）

P0 の `best_iteration` は **3窓×3シードの9回すべてで 10**。
窓ごとに学習行数（153,561 / 157,937 / 161,555）も内側ホールドアウトも違い、
しかも**評価窓を停止判定に使っていない**のに、止まる場所が1本も動かない。

さらに **対照群B-2 で「市場が見ていない本物の信号」を1列注入しても P0 は 10〜11 のまま**
（9件で `[11,10,11,11,10,10,11,10,10]`）。一方 P1 は 79〜208、P2 は 325〜720 まで伸びる。
→ **止めているのは信号の有無ではなく切片**。`hitrate/synth_es.py` の合成データでの予告どおり。

🔴 したがって記録にある「`base_margin` が土台を担うので10本程度で飽和する」
（2026-08-24・10-19 ほか）という説明は**誤り**。`CLAUDE.md` §4 の該当行を訂正した。

### なぜ直しても順位が良くならないのか（この測定で分かった本体）

**本番は `Booster.predict()` の既定で予測していて、既定は `best_iteration` までではなく全木。**

| P0 の予測に使う木 | プール AUC | ◎複勝的中率 | ◎複勝回収 |
|---|---:|---:|---:|
| **全木 61本（本番の挙動）** | **0.7879** | 61.76% | 87.26% |
| `best_iteration`+1 = 11本まで | 0.7799 | 61.57% | 87.15% |

**差 +0.0080。** 止まったあとの50本が順位の信号を担っていて（`inspect_model.py` の
「木ごとの馬間の差 SD」の累計 0.279 → 0.920 がこれ）、本番はそれを使っている。
P1 / P2 の全木 AUC（0.7877 / 0.7886）が P0 の全木（0.7879）と並ぶのは、
**P0 が実質すでに61本ぶん学習して61本ぶん使っている**から。

🔴 **これは偶然に助けられている状態で、脆い。** `requirements.txt` は
`xgboost>=1.7` で版を固定していないので、将来の版で `predict()` の既定が
`best_iteration` までに変わると、**本番の AUC がこの 0.008 ぶん静かに落ちる**。
→ カード §11 のとおり `engine.py` の推論で使う本数を**今の挙動（全木）のまま明示**し、
`tests/test_predict_tree_count.py` で固定した（**予想は1つも変わらない**。
既定と明示が本番モデルで**ビット単位で一致**することをテストが確かめている）。
`shap_explain.py` の `pred_contribs` も同じ本数で計算するよう明示した
（違う本数で分解すると寄与の合計が `ability_margin` と一致しなくなる）。

## 4. 🟡 順位は動かないが、較正は本当に壊れている（採用根拠にはしない）

| 腕 | Brier | LogLoss |
|---|---:|---:|
| P0 | 0.1826 | 0.5461 |
| P1 | **0.1420**（−22%） | **0.4402**（−19%） |
| P2 | **0.1418** | **0.4394** |

切片が +1.3 を通過したあとも50本ぶん行き過ぎる（`inspect_model.py`: 10本で +1.43 →
61本で +2.68）ので、**確率の水準が系統的にずれる**。P1 / P2 はこれが無い。

🔴 **これを採用根拠にしない。** 事前登録した採用基準は §2 の5つだけで、
Brier / LogLoss は「印字する指標」であって基準に入れていない
（2026-08-28 の「数字を見た後に選んだ指標を採用根拠にしない」と同じ扱い）。

⚠ **実害の大きさは測っていない。** 本番は下流に Isotonic 較正器
（`xgb_calibrator.pkl`）を通して `cal_prob` を作るので、**単調変換で直せる水準のずれ**は
そこで吸収されうる。一方 `win_prob = softmax(raw_prob*10, T=3.5)` は
`raw_prob` の非線形変換なので、水準のずれは**レース内の分布の広がり**に効く
（＝穴マーク `pn>=0.15`・`conf`・買い目に効きうる）。
**この経路の実害はこの測定では測っていない。** 較正（C）は `CLAUDE.md` §3 のとおり
**手つかず**のままで、触るなら別カードを書いてから（`conf` の尺度が動くと
`CONF_STRONG=66` の意味が変わる）。

## 5. 対照群

| | 結果 | |
|---|---|---|
| **B-1 注入の復元（算数の検算）** | 注入前 87.04% → 注入後 107.04%  差 **20.0pt**（注入量と一致・許容 1e-3） | ✅ |
| B-1 独立検算（オラクル単勝） | R=1025.51% = 単勝払戻の平均/100（別経路で一致） | ✅ |
| **B-2 本物の信号を1列注入** | z 単独 AUC 0.6514 → ΔAUC は P0 **+0.0212** / P1 +0.0226 / P2 +0.0223。3腕すべて正 | ✅ |
| **A-1 ΔAUC の並べ替え**（対応のある9差の符号反転・2^9=512 通りの厳密分布） | P1: 平均 −0.00027・両側 **P=0.535**（区別できない）／ P2: 平均 +0.00086・両側 **P=0.047** | ✅ |
| **A-2 回収率の並べ替え**（レース内シャッフル200回） | 帰無の平均 **−11.92pt**（合格線 \|mean\| < 1.23）→ **通らない** | 🔴 |

🔑 **B-2 がいちばん重要な数字**。本物の隠れ信号を入れたとき、
**P0 は P1 / P2 の 94% を回収している**（+0.0212 vs +0.0226 / +0.0223）。
つまり「10本で止まることが信号を取りこぼしている」わけではない（§3 のとおり全木を使うから）。
**候補Bが不採用でも「過去の特徴量検証は学習設定のせいで不当に否定された」とは読めない。**

### 🔴 対照群A-2 は登録した形が成立していなかった（同型の失敗が4度目）

統計量が `ROI(無作為な軸) − ROI(P0)` なので、**P0 に実力がある限り帰無は負になる**のが当然で、
「帰無が0中心」という合格線は構造的に通りえない。
`logic2026/eval.py` の対照群Aをそのまま再利用したが、**そこに書いてある警告
（「帰無が0中心になるのは無作為と同じという意味ではない」）を読んだのに、
合格線だけ β係数用のものを流用した**。2026-09-22 / 10-19 / 10-21 と同じ family の失敗で、
今回が4度目。

**結果を見てから測定器を足し直していない。** 読める事実は
**「P0 は無作為に軸を選ぶより +11.92pt 上（並べ替え P=0.0950）」**まで。
基準5 が落ちているのはこの欠陥によるもので、**判定は基準1 に乗っている**（§2）。

🔑 次に並べ替え対照群を書くときは、**統計量ごとに「何の帰無か」を決めてから合格線を書く**。
A-1 のように「アームの割り当てを入れ替える」形なら帰無は構造的に0中心になる（実測 ±1e-6）。

## 6. この測定が触っていないもの

- **本番モデル・較正器は差し替えていない**（md5 `2e8e1f55…`×2 / `af805318…` 不変）。
- 閾値（`CONF_STRONG=66` / `CONF_LIGHT=55` / `CONF_GRADE_S=72` / `DANGER_MAX_POP=1` /
  `DANGER_MIN_SOLO=6` / `MIN_AXIS_FUKU_PROB=0.55` / `ALLOC_*`）は1つも動かしていない。
- 予想・買い目・記事・表示の数字は1つも変わらない（§3 の明示化は既定と**ビット単位で同一**）。
- 腕を増やしていない・ハイパラ探索をしていない（cid82 は `mf2/RESULTS.md` にある値をそのまま使った）。

## 7. この結果を次にどう使うか

- 🔴 **同じ3腕を定義・期間・推定仕様を変えて測り直さない。**
- 🔴 **2026-08〜10 のこの3窓はこの測定で読んだ。**
- ✅ 「切片で止まる」という事実の記録は残す（`inspect_model.py` / `synth_es.py` / 本文 §3）。
  次に `train_xgb` を触る人が「10本で飽和している」と誤読しないように。
- 🟡 唯一開いているのは **較正（C）**。順位は動かないが Brier は 22% 違う。
  ただし `conf` の尺度が動くと商品の閾値の意味が変わるので、**別カードを書いてからしか触らない**。
