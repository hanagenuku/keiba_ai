# 事前登録カード STAR: ☆を本番に出してよいかを**未読の窓**で決める

作成 2026-11-10（測定前）。`hitrate/RESULTS_D.md` §4 の宿題。
🔴 **測定前にコミットする。実行後は1文字も変えない。**

## 0. 背景と、なぜ未読の窓で測るのか

- ☆（＝1番人気を着順で上回る可能性が比較的高い馬の表示）は
  `hitrate/CRITERIA_C_RERUN.md` の5基準に **2025年で合格**している。
- しかし `hitrate/RESULTS_D.md` §2 で、**同じ τ での出現頻度が 2025年 3.6% →
  2026年 18.72%（約5倍）**になることが分かった。頻度が動くと商品としての意味が変わるし、
  記事に書く確率が当たらない恐れがある。
- 🔴 **判定の窓は 2024年**（この統計量では完全に未読）。理由は
  `websig/ADOPTION_STANDARD.md` §5 のユーザー決定:
  > 既読の窓で合否を決めると「結果を見てから基準を選んだ」ことになる。
  > **まだ読んでいない窓で1回だけ測って決める**
  2025年は `RESULTS_C_RERUN.md` で読み、2026年は `RESULTS_D.md` で
  （差し替え側の複勝率・単勝回収率を）読んでしまっている。
- 2026年は「**矛盾しないか**」の確認にだけ使う（基準7）。

⚠ 2024年を評価窓にすると学習期間が 2023年だけ（3,182レース・約41,000ペア）になり、
2025年の窓（78,889〜111,133行）より薄い。**この薄さは不利な方向に働く**ので、
ここで通れば 2025年・2026年の条件でも通ると考えてよい。逆に落ちた場合は
「薄い学習データのせいかもしれない」とは**書かない**（後出しの言い訳にしない）。

🔴 **◎は動かさない。** このカードが決めるのは ☆（表示）だけ。

## 1. 腕（2つ。事前に両方登録する）

| 腕 | 選び方 | 記事に書く確率 |
|---|---|---|
| **S-1 τ固定** | 各レースで `P̂` 最大の馬を取り、`P̂ >= 0.60` のときだけ ☆ | τ = 60% |
| **S-2 頻度固定** | 各窓で `P̂` 最大の馬の上位 **4.0%** のレースだけ ☆ | 選ばれた集合の `P̂` の**中位値** |

4.0% は 2025年の τ=0.60 の頻度（3.61%）に合わせた値で、**結果を見る前に決めた**。
S-2 は「頻度が期間で動く」問題への対処で、較正器を毎窓作り直しても分布が動くことへの保険。

## 2. 窓（判定は 2024年だけ）

| 窓 | 学習 | 評価 |
|---|---|---|
| U1 | ≤ 2023-12-31 | 2024-01-01 〜 2024-04-30 |
| U2 | ≤ 2024-04-30 | 2024-05-01 〜 2024-08-31 |
| U3 | ≤ 2024-08-31 | 2024-09-01 〜 2024-12-31 |

⚠ `history.db` に 2024-11-25〜2024-12-31 のレースが1件も無いので U3 は実質 11-24 まで。
内側ホールドアウト42日の起点は「学習期間に**実在する最後の日**」から取る。

モデル・特徴量・シード・較正はすべて `hitrate/eval_c.py` の C-2 と同一
（目的変数 `y = 1{着順(X) < 着順(P1)}`／129特徴量の**差分のみ**／オッズ・人気は特徴量に入れない）。

## 3. 🔴 集計の仕方を1つに固定する（前回の失敗の対策）

`RESULTS_D.md` §3 で、同じ量を2つの式で計算して 101.46% と 101.32% になった。
**このカードでは集計を1つだけにする:**

> **シードごとに3窓をプールして率・回収率を出し、その3シードを単純平均する。**
> 差し替えが0件のシードも分母に数える（落とさない）。窓ごとの値も同じ式で出す。

## 4. 合格基準（S-1 または S-2 が**すべて**満たしたときだけ ☆ を出してよい）

1. **較正**: プールの実測「P1を上回った率」が **宣言値 − 0.05 以上**、
   かつ3窓すべてで **宣言値 − 0.10 以上**
2. **的中率**: 複勝率（差替）− 複勝率（P1）が **3窓すべて正**、かつプールで **+10.0pt 以上**
3. **回収率ガード**（`websig/ADOPTION_STANDARD.md` §3-4 をそのまま写す）:
   複勝回収率が P1 より **2.0pt を超えて悪化しない**（**3本抜きでも**）
4. **頻度の安定**: ☆が出るレースの割合が **2024 / 2025 / 2026 の3期間で max/min <= 3.0**
   （S-2 は定義上 4.0% 固定なので自動的に満たす。S-1 はここで落ちる可能性がある）
5. **N**: 差し替えレースが **100 以上**
6. **対照群**: A（符号反転200回の帰無が0中心）／B-1（`roi(bonus=5)` が +5.00pt・±0.01）／
   B-2（`score + 1000·y` で AUC = 1.0000・±0.0001）
7. **2026年で矛盾しない**: 同じ腕で複勝率差（差替 − P1）が **正**

### 判定の順序（結果を見てから選ばない）

- S-1 が1〜7すべて合格 → **τ=0.60 固定で ☆ を出してよい**
- S-1 が**基準4だけ**落ちて S-2 が1〜7すべて合格 → **頻度固定（上位4.0%）で ☆ を出してよい**
- それ以外 → **☆ は出さない**

### 記事に書く確率

🔴 **τ（60%）ではなく、2024年の実測値を5%刻みで切り下げた値**を書く
（例: 実測 64.1% → 「60%以上」）。宣言値そのものを書かない。

## 5. 停止条件（結果より**先に**印字する）

1. 判定窓（2024）のレース数 < 2,500 → 停止
2. どの腕でも差し替えレース < 100 → 停止
3. 内側HO < 1,000行 → 停止（2024-12 の穴に当たっている）
4. P1 を特定できないレースが 5% 超 → 停止
5. 対照群 B-1・B-2 のどちらかが復元しない → **計測器の不良として停止**
6. 2025年を同じコードで再計算して `c_rerun_result.json` と **±0.01pt で一致しない** → 停止
   （§3 の集計式に揃えた値どうしで比べる。揃える前の値とは比べない）

## 6. 🔴 ついでに報告するだけの項目（合否は出さない・ユーザー判断用）

`websig/ADOPTION_STANDARD.md` v2（2026-11-11 ユーザー決定）は判定指標を
「的中率・順位精度」＋「回収率は −2.0pt を超えて悪化しないガード」に替えた。
C-2 の◎差し替えを**その線で読むと**別の読み方になりうる（2025年実測で
的中率 +25.35pt・複勝回収率 −0.47pt）。

**このカードでは◎について合否を出さない。** ただし 2024年（未読）で

- ◎を差し替えた場合の複勝率（差替 / P1）とその差
- ◎を差し替えた場合の複勝回収率（差替 / P1）とその差・**3本抜き**

を**報告だけする**。◎を動かすかどうかは**ユーザーの判断**であり、
動かすなら v2 の線を写した**別のカード**を書いてから測り直す
（このカードの結果で◎を動かさない）。
