## 1. なぜ再測が必要か（前回の失敗の内容）

`eval_c.py` は対照群Bの「注入量」を

    注入量 = mean(z 単独の AUC) − mean(素のモデルの AUC)
           = 0.6482 − 約0.683 = **−0.035**

として計算していた。z 単独 AUC はモデルの AUC より低いので、**この式は本物の信号が
あっても無くても負の値しか返さない**。注入で AUC が +0.0483 上がったのは正しい挙動で、
壊れていたのは合格線の定義である。

🔴 この種類の間違いは5回目（2026-09-22 / 10-19 / 10-21 / 11-09 / 11-10）。
**毎回「統計量」と「その帰無／期待値」を別々に定義し損なっている。**
今回の対策: **合格線は「閉じた式で注入量が分かる統計量」にしか置かない**（§3）。

## 2. 腕（前回と同一。再学習の設定を1つも変えない）

`hitrate/eval_c.py` の C-2 と**完全に同じ**:

- 目的変数 `y = 1{着順(X) < 着順(P1)}`、P1 = ドリフト後の人気1位（seed 12）
- 特徴量は129特徴量の**差分のみ**（オッズ・人気は1列も入れない・North Star #1）
- 本番ハイパーパラメータ・シード 42/7/2026・内側HO42日（起点は実在する最後の日）
- 内側HOで Isotonic 較正 → `P̂ >= τ`、τ ∈ {0.55, 0.60, 0.65, 0.70}
- 窓 = 2025年の walk-forward 3分割（W1 1〜4月 / W2 5〜8月 / W3 9〜12月）

## 3. 🔴 対照群B を**閉じた式で復元できる形**に置き換える

前回のように「モデルに列を足して AUC がどれだけ上がるか」を期待値と比べない
（**そこに閉じた式は無い**）。代わりに、**判定に使う統計量そのものに既知量を注入**して
厳密に復元させる。

### B-1 回収率の復元（基準④が使う統計量）

`logic2026/eval.py::roi(axis, pay, bonus=b)` は評価対象の全行に一律 b 円を足す。
分母は `n × 100` なので **ΔROI = b pt** が厳密に成り立つ（この bonus 引数は
`logic2026/eval.py` に対照群B用として元から用意されている）。

**合格**: b = 5 で `ROI(bonus=5) − ROI(bonus=0) = +5.00pt`（**±0.01pt**）。

### B-2 的中判定とラベル配線の復元（基準①③が使う統計量）

評価窓のスコアを `score' = score + 1000 · y`（y は真のラベル）に差し替えると、
正例が必ず負例より上に来るので **AUC は厳密に 1.0000** になる。

**合格**: `AUC(score') = 1.0000`（±0.0001）かつ
`AUC(score') − AUC(score) = 1 − AUC(score)`（±0.0001）。

これは「モデルに信号があるか」の検定ではなく、**AUC・ラベル・レースの対応づけが
正しく配線されているか**の検定である。前回壊れていたのはまさにここを測る線だった。

### B-3 差し替え集合の復元（基準③が使う統計量）

差し替え馬の選び方を「`P̂` 最大」から **「P1 を実際に上回った馬のうち `P̂` 最大
（居なければ `P̂` 最大）」** に差し替える（＝オラクル）。
このとき差し替え馬が P1 を上回る率は、**「P1 を上回った馬が1頭以上いるレースの割合」**に
厳密に一致する（閉じた式。評価窓から直接数えられる）。

**合格**: `オラクルの勝ち越し率 − 事前に数えた上記の割合` が **±0.005** 以内。

🔴 **3つとも、合格線を印字する直前に「本物が無いときこの式は何を返すか」を
同じ行で印字する**（B-1 は 0.00pt、B-2 は 0.0000、B-3 は 0.000）。

### 対照群A（前回と同じ。前回は合格している）

差し替え対象レース i の `Δ_i = 1{差し替え馬が3着内} − 1{P1が3着内}` を
**符号反転**して200回。合格は `|mean(Δ_shuffle)| < 2·std/√200`。
🔴 「ランダムに選んだ馬 − P1」を帰無にしない。

## 4. ☆マークを出してよいと判定する基準（すべて満たしたときだけ）

1. **対照群 B-1・B-2・B-3 がすべて合格**（§3）
2. **対照群A が合格**（帰無が0中心）
3. **較正が壊れていない**: ある τ で、内側HO と評価窓の両方で `P̂ >= τ` の群の
   実測「P1 を上回った率」が **τ − 0.05 以上**
4. **その τ で的中率差（複勝率）が 3窓すべてで正**
5. **その τ で差し替えレースが 100 以上**

1つでも欠けたら **☆を出さない**。τ を結果を見てから動かさない。

🔴 **基準に回収率を入れていない理由を明記する。** ☆は「この馬は1番人気を上回る
可能性が比較的高い」という**着順比較の表示**であり、買い推奨ではない。
回収率が上がらないことは `RESULTS_C.md` §2-2 で測って分かっており、
**☆を出すなら記事に「回収率は改善していない」と併記する**（§6）。
回収率の主張をしたくなったら、それは別のカード（`hitrate/CRITERIA_D.md`）の話。

## 5. 停止条件（結果より**先に**印字する）

1. 評価レース数 < 3,000 → 停止
2. どの τ でも差し替えレース < 100 → 停止
3. 内側HO < 1,000行 → 停止（2024-12 の穴）
4. P1 を特定できないレースが 5% 超 → 停止
5. **対照群 B-1/B-2/B-3 のどれかが復元しない → 停止**（計測器の不良。☆は出さない）
6. 前回（`c_result.json`）と**較正・的中率の数字が一致しない** → 停止
   （同じ設定・同じシードなので一致するはず。ずれたら再現性の問題）
