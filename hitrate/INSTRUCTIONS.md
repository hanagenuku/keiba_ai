## 1. 調査で分かったこと

### 1-1. ◎が市場とずれたレースで的中率を落としている（既読の数字・候補A）

`logic2026/RESULTS.md` §3（2026年・seed 42）:

| ◎の人気 | レース数 | 複勝的中率 | 複勝回収率 |
|---|---:|---:|---:|
| 1番人気（市場と一致） | 1,773 | 65.76% | 85.18% |
| 2〜3番人気 | 580 | 46.38% | 80.50% |
| 4番人気以下 | 303 | **23.43%** | **57.89%** |

- 4番人気以下のセルは**的中率も回収率も最悪**。ここだけは「的中率を上げると回収率が下がる」という通常の取引になっていない。
- 「AI が強気な側ほど悪い」は別の窓・別の測定器で5回再現している（07-30 / 08-03 / 08-31 / 09-27 / 10-21）。
- ⚠ ただし**このセルの数字は 2026年の窓で既に読んでいる**。同じ窓でルールを作って同じ窓で採点してはいけない（North Star #7）。
- 撤回表に「◎を市場側へ戻す」ルールの検証は無い（`gate/RESULTS.md` の G-3「新馬では軸を1番人気にする」が提案止まりで残っているだけ）。

### 1-2. 学習の early stopping が「信号の飽和」ではなく「切片」で止まっている（新しく分かった事実・候補B）

`python3 hitrate/inspect_model.py`（本番モデルのファイルだけを読む。レース結果は使わない）:

```
木の本数 61 / best_iteration 10 / scale_pos_weight 3.58
木ごとの一律の移動（先頭）  0.267 0.212 0.177 0.152 0.133 …   累計 +1.43（10本）→ +2.68（61本）
木ごとの馬間の差 SD（先頭）  0.057 0.038 0.032 0.027 0.025 …   61本の単純和でも 0.92
predict() は既定で 61本すべてを使う（xgboost 3.4.1）
```

機序:
1. `base_margin` は Zipf 近似の**勝率**スケール（レース内の合計が1）。目的変数は**3着内**（合計3）。モデルはまず全馬を一律に約 +1.3（logit）持ち上げる必要がある。
2. 目的関数には `scale_pos_weight ≈ 3.58` が掛かっていて、最適な切片はさらに約 +1.25 上にある。
3. early stopping の指標は**重みなしの logloss**。切片が +1.3 付近を通過する瞬間（＝10〜11本目）が最良になり、その先は切片が行き過ぎるので悪化する → 50本後に停止 → **どんなデータでも 61本**。

`python3 hitrate/synth_es.py`（合成データ・実データは使わない）で再現した:

```
隠れ信号  設定   best_it 木   AUC(市場) AUC(モデル)
  0.0    prod     10    61   0.7577   0.7553
  0.3    prod     10    61   0.7571   0.7624
  0.6    prod     11    62   0.7479   0.7755
  0.6    spw1     78   129   0.7512   0.7781
```

- 🔴 **信号がゼロでも大きくても best_iteration は 10〜11**。記録にある「base_margin が土台を担うので10本程度で飽和する」（2026-08-24・10-19 ほか）は**誤った説明**だった。止めているのは切片。
- ⚠ **直せば良くなるとは限らない。** 合成データでは、止まったあとの50本も信号を学ぶので AUC の差は 0〜+0.003 しか出ていない。実データ（134列・交互作用あり）でどうなるかは測らないと分からない。期待値は「小さいかゼロ」。
- ⚠ これまで「特徴量を足しても上乗せが無い」と閉じた検証（websig・oikiri・D-2 など）は、この学習設定のまま測っている。**候補Bが不採用なら何も開け直さない。採用になった場合だけ**、再測定するものをユーザーに相談する。
- ⚠ `logic2026/eval.py` は early stopping の検証データに**評価窓そのもの**を使っている。今は切片で止まるので実害が無いが、止まり方を直すと評価窓へのリークになる。候補Bでは必ず内側ホールドアウトを使う。

### 1-3. ユーザーの判断が要るもの（Claude Code は着手しない）

- **記事を作る時刻。** 朝の1番人気の勝率 26.5% → 直前の1番人気 34.9%（2026-08-03 実測）。記事は 08:50 のオッズで ◎ を決めて固定するので、午後のレース（9〜11R）ほどオッズが古い。午後のレースだけ昼に作れば的中率は上がる見込みだが、販売の導線が変わるので**ユーザーが決める**。
- 買い目の的中率（ワイドの点数を増やす等）は算数で上げられるが、配当が同じだけ縮む。2026-10-15・10-26 のユーザー決定（中穴を混ぜる・2コース）を変える話なので提案しない。

### 1-4. やらないこと（撤回表で否定済み）

conf のゲートを増やす（08-24）／EV で選ぶ（3度否定）／再学習でデータを足す（10-19）／アンサンブル平均（08-24）／web 指数を足す（09-25・10-22）／オッズ帯・券種で選ぶ（08-03）／市場フリーにする（08-28・10-21）。

## 3. 候補B: 学習の止まり方を直す（`hitrate/CRITERIA_B.md` → `RESULTS_B.md`）

**問い**: early stopping を切片に邪魔されない形にすると、OOS の順位付けは良くなるか。

**腕（この3つだけ。結果を見てから設定を足さない）**

| 腕 | 設定 |
|---|---|
| P0 | 本番と同一（`max_depth=6, lr=0.05, mcw=10, scale_pos_weight=(1-r)/r`） |
| P1 | P0 から `scale_pos_weight=1.0` に変えるだけ |
| P2 | 既に記録にある cid82（`max_depth=5, lr=0.02, mcw=300, reg_lambda=5.0, reg_alpha=0.1, spw=1.0, n_estimators=4000`・`mf2/RESULTS.md`）に `base_margin` を付けたもの |

- 3腕とも `residual=True`・134列・ドリフト注入ON・行と `base_margin` は同一。
- early stopping は**学習期間の末尾42日（内側ホールドアウト）**で行う。評価窓は学習にも停止判定にも使わない。P0 もこの形で測り直して比較する。
- 窓: `retrain/ab.py` と同じ3窓 walk-forward × seed 42 / 7 / 2026。

**基準（案。カードに確定してから測る）**
1. プール AUC: 腕 − P0 >= **+0.002** かつ シード std の2倍以上（2026-08-24 のアンサンブル検証と同じ線）
2. 3窓すべてで同符号
3. ◎の複勝的中率が P0 を下回らない
4. ◎の複勝回収率が P0 − 0.5pt を下回らない（3本抜きでも）
5. 対照群A・B（North Star #11 の2つの形）。対照群B は「市場が見ていない信号を1列注入して、P0 と腕のどちらが多く拾うか」を入れる

**中止条件**: 本番 `data/` の md5 が測定前後で変わる／P0 が記録（`best_iteration` 10〜11・`retrain/RESULTS.md` の AUC）を再現しない。

**採用になった場合だけ**（ならなければ本番は触らない）
- 較正器（`calibrate_xgb.py`）を当て直す。`model_registry.save_version` で旧版を残す。
- PR に実測を添えて報告（North Star #2）。過去に閉じた検証のうち再測定するものをユーザーに相談する。

**結果にかかわらずやること**
- `RESULTS_B.md` に「best_iteration 10〜11 は切片で決まっていた」と機序を記録する（`inspect_model.py` と `synth_es.py` が根拠）。
- `requirements.txt` が `xgboost>=1.7` で版を固定していない。`Booster.predict()` が early stopping 後に使う木の本数は版によって扱いが違いうるので、`engine.py` の推論で使う本数を**今の挙動（全木）のまま明示**し、テストで固定する（予想は1つも変えない変更）。

## 4. 候補A: ◎が4番人気以下になるレースの軸（`hitrate/CRITERIA_A.md` → `RESULTS_A.md`）

**問い**: `AI+市` 1位が4番人気以下のレースで軸を1番人気に替えると、的中率が上がり、回収率は下がらないか。

**ルール**
- R0: 現行（軸＝`AI+市` 1位）
- R1: `AI+市` 1位が**4番人気以下**のレースだけ、軸を1番人気にする
- R2: 常に1番人気（市場単独。比較用）

**窓**
- 🔴 **判定は 2026年の窓で行わない**（§1-1 のセルを既に読んでいる）。`train_end=2024-12-31` で学習し **2025年**で判定する。2025年でこのセル（P の軸×人気帯）を読んだ記録が無いことを `grep` で確かめ、カードに書く。読まれていたら別の窓を登録する。
- 2026年は「既読・参考」として並べるだけ。

**条件を本番に合わせる（North Star #10）**
- 「4番人気以下」の人気は**モデルが見ているのと同じ人気**（ドリフト注入後＝朝のオッズ相当）で判定する。確定人気で判定しない。
- 少頭数で複勝が発売されない行は `logic2026` と同じ扱い（評価不能として両ルールの分母から外す）。

**基準（案）**
1. 全レースの複勝的中率: R1 − R0 >= **+2.0pt**
2. 全レースの複勝回収率: R1 − R0 >= **0**（3本抜きでも同符号）
3. 前半・後半とも 1・2 と同符号
4. 軸が替わるレース数 N >= 300
5. 対照群A: 同じ本数のレースを無作為に選んで1番人気に替える操作を200回。実測の差を並べ替え P で報告。対照群B: 注入の復元
6. 市場ゲート: R2 も必ず並べる。**R2 が的中率・回収率とも R1 以上なら**「◎を AI で選ぶ意味が的中率の面では無い」という結論になる。その場合は採否を決めずにユーザーへ報告する

**あわせて数える（判定には使わない）**
- 軸が替わるレースのうち推奨レース（conf>=66）は何本か。有料記事にどれだけ影響するかの見積もり。
- 2〜3番人気のセルで同じ置き換えをした場合の的中率と回収率（回収率は下がる見込み。記録だけ）。

**採用になった場合だけ**
- 置く場所は**上流**（◎と軸を決める1箇所）。後付けで出力を書き換える層にしない。
- 🔴 ◎・軸・買い目・成績ページ・記事・`danger_log`・アプリの直前オッズ追従（2026-11-08 の PR #326・#327）が**同じ軸**を見るように、読む側を全部 `grep` して揃える（CLAUDE.md §3・2026-11-08② の再発防止）。
- 公開済みの `prediction_archive/` は書き換えない。
- 商品としての意味（◎が市場寄りになる）は `biz/` 側で別に論じる。この検証の文書に混ぜない。
