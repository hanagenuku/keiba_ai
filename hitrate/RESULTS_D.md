## 2. 🔑 副産物: τ の閾値は期間をまたいで移らない

| | 2025（探索期） | 2026（確認期） |
|---|---|---|
| τ=0.55 で ☆ が出るレース | 8.79% | **24.12%** |
| τ=0.60 で ☆ が出るレース | 3.6% | **18.72%** |

**同じ τ で、2026年は約5倍の頻度で「1番人気を超える」と言っている。**
較正器（Isotonic）は各窓の内側ホールドアウトで作り直しているのに、
**出力確率の分布そのものが期間で動いている。**

🔴 **これは ☆ マーク（`hitrate/RESULTS_C_RERUN.md`）に直接効く重大な注意点である。**
☆の合格判定は 2025年だけで行った。確認期の 2026年では

- 差し替え馬の**複勝率は 56.64%**（2025年の 56.91% とほぼ同じ＝claim 側は壊れていない）
- しかし **頻度が 3.9% → 18.7%** なので、「1レースに1本前後」ではなく
  「5レースに1本」出ることになり、**商品としての意味が変わる**

さらに **2026年の「P1 の複勝率」と「2026年の較正」はこの測定では出していない**
（カード §3 の主指標は単勝回収率なので、そこは測っていない）。
→ **☆を本番に出す前に、2026年で較正と複勝率差を確かめる必要がある**（§4）。

## 3. 🔴 中止条件が1つ発火した（原因は私の集計式の不統一）

印字: `探索期 τ=0.6 単勝回収率: 前回 101.46% → 今回 101.32%  差 0.149pt`（許容 ±0.01pt）

モデル・シード・データは同一で、`best_iteration` も前回と**完全に一致**している
（292 / 323 / 161 …）。ずれたのは**集計の重み付け**である。

- `eval_c.py` の `n_total` / `pool` は **窓ごとにシード平均 → 窓間で平均**。しかも
  「差し替えが0件だったシード」を平均から**落としている**ので、件数が**過大**になる。
- `eval_d.py` の探索期は **(窓, シード) をフラットに平均**している。

同じ量を2つの式で出していたので 101.46% と 101.32% になった。
**どちらかが間違っているのではなく、重み付けを揃えていなかった。**

### 影響範囲（確かめた）

| 量 | 過大な式（eval_c） | 正直な式 | 判定は変わるか |
|---|---|---|---|
| τ=0.55 の差し替え件数 | 303 | 302.7 | 変わらない（>=100） |
| τ=0.60 の差し替え件数 | 134 | **124.3** | 変わらない（>=100） |
| τ=0.65 の差し替え件数 | 96 | 93.0 | 変わらない（<100 で不合格） |
| τ=0.70 の差し替え件数 | 71 | 69.0 | 変わらない（<100 で不合格） |

**`RESULTS_C.md` と `RESULTS_C_RERUN.md` の判定はどれも変わらない。**
ただし両ファイルに書いた「134レース」は正しくは **124.3レース**（シード平均）であり、
**0件だったシードを落とした平均なので過大だった**。ここに訂正として残す。

候補D の不採用判定は**確認期（2026）だけで決まっており、探索期を1つも使っていない**ので、
この発火には依存しない。

### 次に同じ失敗をしないために

🔴 **同じ量を2か所で計算しない。** 集計は1つの関数に寄せ、
「0件のシードを落とすか落とさないか」を関数の引数ではなく**仕様として1つに固定**する。

## 4. 残っている宿題（☆を出す前に必要）
