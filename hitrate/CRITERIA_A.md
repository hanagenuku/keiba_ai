# 事前登録カード A: ◎が4番人気以下になるレースの軸

- 登録日: 2026-11-10
- 指示書: `hitrate/INSTRUCTIONS.md` §4（ユーザー指示「候補B → 候補A の順で実行」）
- 🔴 **このカードは測定前にコミットする。結果を見てから閾値・ルール・期間・母集団・指標を変えない。**
- 🔴 **測定は1回。** 失敗したら「失敗した」と書いて閉じる。
- 前提: 候補B は**不採用**（`hitrate/RESULTS_B.md`）。よって**本番と同じ学習設定**で測る。

## 1. 問い

`AI+市` 1位（＝◎・買い目の軸）が**市場4番人気以下**になるレースで、軸を**市場1番人気**に
替えると、**◎の複勝的中率は上がり、回収率は下がらないか。**

## 2. なぜこのセルか（既読の数字・結果を見る前に書いておく）

`logic2026/RESULTS.md` §3（2026年・完全OOS・seed 42）:

| ◎の人気 | レース数 | 複勝的中率 | 複勝回収率 |
|---|---:|---:|---:|
| 1番人気（市場と一致） | 1,773 | 65.76% | 85.18% |
| 2〜3番人気 | 580 | 46.38% | 80.50% |
| 4番人気以下 | 303 | **23.43%** | **57.89%** |

4番人気以下のセルだけ**的中率も回収率も最悪**で、「的中率を上げると回収率が下がる」という
通常の取引になっていない。「AI が強気な側ほど悪い」は別の窓・別の測定器で**6回**再現している
（07-30 / 08-03 / 08-31 / 09-27 / 10-21 / p4 の 09-08）。

## 3. 🔴 窓の選び方と、既にこのセルを読んでしまっている記録（grep で確認した）

指示書 §4 は「判定は 2026年の窓で行わない（§1-1 のセルを既に読んでいる）。`train_end=2024-12-31` で
学習し **2025年**で判定する。2025年でこのセルを読んだ記録が無いことを grep で確かめ、カードに書く。
読まれていたら別の窓を登録する」と定めている。

grep の結果（`人気帯|軸の人気|4番人気以下|人気>=4|◎の人気` を `*.md` / `*.py` 全体に）:

| 記録 | 窓 | 読んだ統計量 |
|---|---|---|
| `logic2026/RESULTS.md` §3 | **2026**（完全OOS） | **このルールの判定統計量そのもの**（軸の複勝的中率・回収率を人気帯別に） |
| `p4/RESULTS.md` §3・§4 | **探索期 2025 ＋ 確認期 2026** | 「AI1位=市場4番人気以下」の**レース全馬の AUC**（AI 0.7279 vs 市場 0.7635・探索差 −0.0382）。p4 は「ROI は測っていない」と明記 |
| `race_select/`（T1〜T3） | 2025-03/04・06/07・10/11 | 「AI1位＝市場1番人気か」を**レース選別モデルの特徴量**として使用（軸の置き換えは測っていない） |
| `danger/`（B期間） | 2025-01-05〜2026-10-12 | 市場1番人気 × `solo_rank` の3着内率・勝率（**軸の置き換えではない**） |

🔴 **したがって 2025 は「このセルの存在」については処女窓ではない。** p4 が探索期 2025 で
同じセルの AUC を読んでいる（符号も同じ向き）。
✅ 一方で**このルールの判定統計量（軸を置き換えたときの的中率・回収率）は 2025 で一度も読んでいない。**

**それでも 2025 を主判定窓に登録する。** 理由:
- `history.db` は 2023-01-07 からで、2年ぶんの学習期間を確保できる評価窓は **2025 と 2026 しかない**。
  2026 は判定統計量そのものを既読（上表1行目）なので、2025 のほうが明確に良い。
- 2024 を評価窓にすると学習が 2023 の1年だけになり、**AI 側が弱い状態で市場と比べることになる**
  （2026-08-18 実測: 1年学習 0.7651 vs 2年 0.7711）。これは R1・R2（市場へ寄せる側）に
  **有利に働く方向の偏り**で、採用判定を甘くする。主判定には使わない。
- ⚠ 制約は結果に明記する: **帯の境界（4番人気以下）は 2026 と 2025（p4）の両方を見たうえで
  決まったもの**で、こちらが独立に選んだ閾値ではない。
- 2024（`train_end=2023-12-31`）は**報告のみの確認窓**として並べる（基準には入れない。
  上記の偏りがあるため）。2026 は「既読・参考」として並べるだけ。

## 4. ルール（3つだけ）

| | 軸の決め方 |
|---|---|
| **R0** | 現行。レースごとに残差モデルの予測が最大の馬（同値は馬番の小さい方） |
| **R1** | R0 の軸が**4番人気以下**のレースだけ、軸を**市場1番人気**に替える |
| **R2** | 常に市場1番人気（市場単独。比較用） |

- 「人気」は **モデルが見ているのと同じ人気**（ドリフト注入後＝朝のオッズ相当）で判定する。
  確定人気では判定しない（North Star #10）。同値は馬番の小さい方。
- 🔴 **R1 は R0 の予測を1つも書き換えない。** 軸を選ぶ最後の1箇所だけを差し替える操作として測る。

- 予測は**全木**（`predict()` の既定＝本番 `engine.py` の挙動。`hitrate/RESULTS_B.md` §3）。

## 6. 評価指標

- **◎の複勝的中率** = 軸が3着内に入った割合。
- **◎の複勝回収率** = 軸の複勝を1点買った時の回収率。払戻は `horse_history.fukusho_payout`。
  **3本抜き**（上位3本の払戻を除いた回収率）も必ず並べる。
- **的中だが払戻が無い行は評価不能として分母から外す**（`logic2026/eval.py::roi` をそのまま使う）。
- 🔴 **R0 と R1 の比較は「両ルールの軸がともに評価可能なレース」に揃える**（共通集合）。
  軸が違うと評価不能になる行が片側だけ落ちて分母が食い違うため。
  各ルール単独の素の数字も並べて出す。

## 7. 採用基準（6つすべて必要・主判定窓 M だけで判定）

| # | 基準 |
|---|---|
| 1 | 全レースの複勝的中率: R1 − R0 >= **+2.0pt** |
| 2 | 全レースの複勝回収率: R1 − R0 >= **0**（素の回収率と**3本抜き**の両方が同符号） |
| 3 | **前半（1〜6月）・後半（7〜12月）とも** 基準1・2 と同符号 |
| 4 | 軸が替わるレース数 **N >= 300** |
| 5 | 対照群A・B（§8）が両方とも通る |
| 6 | **市場ゲート**: R2 を必ず並べる。**R2 が的中率・回収率とも R1 以上なら**「◎を AI で選ぶ意味が的中率の面では無い」という結論になる。その場合は**採否を決めずにユーザーへ報告する**（こちらで決めない） |

⚠ 基準1 は「全レース」での差。軸が替わるのは全体の 1割強なので、置き換えたレース内での差は
その約9倍になる。**置き換えたレース内の差を全レースの差として書かない。**

## 8. 対照群（North Star #11 の2つの形）

**対照群A（並べ替え分布）**: 軸が替わるレースと**同じ本数 K** を無作為に選んで1番人気に替える操作を
**200回**。統計量は「全レースの複勝的中率の差（置換後 − R0）」。
帰無は「どのレースで替えても同じ」。実測の差の並べ替え P 値を報告する。
🔑 これは「替えること」ではなく「**このセルを選んで替えること**」に意味があるかを測る。
合格は「帰無の分布が無作為置換の期待どおりに出る（＝分散がゼロでない・実測と比較できる）」こと。
**1回の引きの大小比較は書かない。**

**対照群B-1（注入の復元・算数の検算）**: 評価対象の全行に一律 +20.0pt を足し、
`注入後 − 注入前 = 20.0pt`（許容 1e-3）を確かめる。

**対照群B-2（注入の復元・本物があったら検出できるか）**: 軸が替わるレースで軸を
**実際の1着馬**に置き換える（オラクル）。そのレース内の複勝的中率が **100%**（評価可能行で）
になり、全レースの的中率の上がり幅が **K / N × (1 − 元の的中率)** と一致することを確かめる。
🔑 計測器が「本物の改善」を検出できることの確認。

## 10. あわせて数える（判定には使わない）

- 軸が替わるレースのうち**推奨レース（conf>=66）**は何本か（有料記事への影響の見積もり）。
  🔴 `conf` は本番の `race_confidence`（Harville の `top3_prob`）を再現して出す:
  `total = raw_prob*10` → `src.models.predict.softmax_probs(T=3.5)` → `src.features.engine.calc_harville_probs`。
  ⚠ 本番はこの後に相対ブレンド10%・pace_bonus が乗る（`error_tags` は既定OFF）ので**近似**。
  近似であることを結果にも書く。
- **2〜3番人気のセル**で同じ置き換えをした場合の的中率と回収率（回収率は下がる見込み。記録だけ）。
- 置き換えで軸が変わらないレース（AI 1位が既に1番人気）の本数。

## 12. 採用になった場合だけやること

1. 置く場所は**上流**（◎と軸を決める1箇所）。後付けで出力を書き換える層にしない。
2. 🔴 ◎・軸・買い目・成績ページ・記事・`danger_log`・アプリの直前オッズ追従（PR #326・#327）が
   **同じ軸**を見るように、読む側を全部 `grep` して揃える（`CLAUDE.md` §3・2026-11-08② の再発防止）。
3. 公開済みの `prediction_archive/` は書き換えない。
4. 商品としての意味（◎が市場寄りになる）は `biz/` 側で別に論じる。この検証の文書に混ぜない。
5. PR に実測を添えて報告。**的中率だけを成果として書かない。**

- 本番モデル・較正器・閾値を測定中に差し替える。
