## 2. 🔴 中止条件3 が落ちた。この測定は「出荷物が良くなるか」には答えていない

カード §6-3 は「OLD の ECE が実測 0.0682 と同程度（±0.01）。離れていたら fit 側の
再現に失敗している」と登録していた。実測 **OLD 0.0210** で**大きく離れた**。

意味するところは明確で、**OLD アームは出荷されている `xgb_calibrator.pkl` を再現していない**。
したがってこの A/B が答えたのは「**CSV 全行に当て直すとき、確定人気とドリフト注入でどちらが
良いか**」までで、「**`calibrate_xgb.py` を直せば出荷物が良くなるか**」には答えていない。

再現しない理由は構造的で、ドリフトとは無関係:

| | 出荷物を作った実際の `run_xgb_calibration` | この測定の両アーム |
|---|---|---|
| fit の母集団 | `history.db` の行（engine 経路で特徴量を作る） | `horse_features.csv` の行 |
| 期間 | 直近30日を除いた全期間（`_split_train_test(test_days=30)`）＝モデルにとって**OOS の行を含む** | 〜2026-06-30 ＝モデルにとって**in-sample** |
| 特徴量 | 推論時の値（`f_track_cond` が 0 など） | 学習時の値 |

⚠ **自分の作りの欠陥を記録する**: ハーネスは中止条件3 を**最後に印字する**作りだったので、
ECE を見た後にこの条件の不通過を知った。条件2 は手前で止める作りにしてあったのに、
条件3 は止める作りになっていなかった。**次に中止条件を書くときは、全部を ECE より手前に置く。**
ただし基準2・4 が落ちているので、**どちらの読み方でも結論は同じ（差し替えない）**。

## 4. 🔑 副産物: B の問いより大きいものが出た（**実装しない**）

**出荷されている較正器は、9/15 以降の完全OOSで水準が 4.3ポイント低い**
（予測 0.184 / 実測 0.226）。一方、CSV 全行に素直に当て直すと**どちらのアームでも +0.003**。
ECE も 0.0425 → 0.0210（OLD）/ 0.0134（NEW）。

→ **効いているのはドリフトのパリティ（ECE で +0.008）ではなく、当て直すこと自体
（水準で −0.043 → +0.003）。** 桁が一つ違う。

🔴 **これはカードBが登録した問いではないので触らない。** 「当て直せば良くなる」は
上の §2 のとおり fit の母集団・期間・特徴量の経路が3つとも違う比較の副産物であって、
`calibrate_xgb.py` を直した結果ではない。**別カードが必要**で、そこでは
①どの経路の差が効いているのか（母集団／期間／特徴量）を1つずつ切り分ける
②較正器を学習期間内の in-sample な raw_prob に当てている問題（両アームともそうなっている）
を先に片付ける必要がある。

⚠ 当て直しても**買い目も商品も1ミリも動かない**（カード §2）。動くのはアプリの `cal_prob` 表示と
`race_predictions.cal_prob`（分析用）だけ。急ぐ理由はない。
