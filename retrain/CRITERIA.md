## 1. 問い

本番モデル（学習 〜2026-06-30・作成 2026-09-15）に、その後溜まった実データを足して
再学習すると、**完全 out-of-sample で精度は上がるか**。

⚠ これは「キャリブレーション」の問いではない。較正器（`xgb_calibrator.pkl`）は別物で、
B として分けてある。モデルが変われば較正はやり直しが必要になる、という依存だけがある。

## 2. なぜ事前の見積りが「ほぼ±0」なのか（結果を見る前に書いておく）

- 2026-08-18 の実測で**レース数は2年で飽和**している（1年 0.7651 → 2年 0.7711 →
  3年 0.7710 → 3.5年 0.7706）。本番モデルは既に 3.5年ぶん（155,187行）で学習済み。
- 足せるのは最大 +11,216行（+7.2%）。飽和の先にこれを足して伸びる根拠が無い。
- 2026-08-28 に `f_recent` のバグ修正後に再学習したときも ΔAUC = **−0.0000**（引き分け）で
  差し替えていない。
- 市場ベースラインKPI（2026-10-19 集計）でも劣化は見えない:
  完全OOS 34日 delta +0.0079 に対し、直近12日は **+0.0050**。

→ **それでも測る理由は「止まっている状態そのものの解消」**。引き分けでも
「4ヶ月ぶんの新データでも伸びなかった」という記録になる。

## 3. アーム

## 4. 検定窓（3窓・walk-forward）

| 窓 | N の学習期間末 | N の学習行数（P比） | 検定窓 | レース | 行 |
|---|---|---|---|---|---|
| W1 | 2026-07-31 | 158,807（+3,620） | 2026-08-01〜08-31 | 347 | 4,595 |
| W2 | 2026-08-31 | 163,402（+8,215） | 2026-09-01〜09-30 | 228 | 3,001 |
| W3 | 2026-09-30 | 166,403（+11,216） | 2026-10-01〜10-18 | 159 | 2,139 |

**どの検定窓も P・N の両方にとって完全 OOS**（P の学習は 2026-06-30 まで）。

- **主測定 = 3窓をプールした walk-forward**（各行をその日より前で学習した N が予測する。
  合計 **9,735行**）。1窓ずつだと 2,139行まで落ちて雑音が勝つため。
  ⚠ 9,735行は過去のA/B窓（6,368〜9,728行）と同規模にそろえた。
- 副測定 = 窓ごとの内訳。**主測定が基準を満たさない限り、副測定で良い窓を拾わない。**
- シード: N は **42 / 7 / 2026** の3本。P は既存の学習済み1本。

## 5. 採用基準（4つすべて満たす場合のみ「本番差し替えを提案」）

2026-08-24（シードアンサンブル）・2026-08-26（f_maturity/f_rotation）で使った基準と
**同じものを流用する。新しく作らない。**

1. **3シードすべてで N > P**（悪化シードゼロ）
2. 3シード平均の **ΔAUC >= +0.002**
3. ΔAUC が**シード標準偏差の2倍以上**
4. **Brier と LogLoss も同方向**（3シードとも改善）

⚠ 回収率は測らない。AUC が上がっても回収率が上がらないことは North Star #9 で確定済み。

## 6. 中止条件（本データの ΔAUC を読む前に全部通す）

🔴 **1つでも落ちたら ΔAUC を読まずに破棄する。**

1. **隔離の検算**: 本番 `data/xgb_fukusho_model.pkl` / `xgb_calibrator.pkl` /
   `xgb_feature_cols.json` の md5 が測定の前後で**不変**。
   （2026-09-15 に「隔離した」はずのワークスペースがシンボリックリンクでリポジトリを
   貫通し、`train_xgb` の保存が本番モデルを書き換えた事故が実際に起きている）
2. **ハーネスの検算**: P を **2026-07-01〜2026-09-15（740レース / 9,728行）**で評価すると
   `xgb_feature_cols.json` の記録 **val_auc 0.7846** を再現する（±0.002 以内）。
   この窓が記録の `n_val: 9728` と行数まで一致することは登録前に確認済み。
3. **行順と base_margin の同一性**: P と N は**同一の行・同一の順序・同一の base_margin 配列**で
   評価する。ドリフトは行ごとに乱数を引くので行順が違うと別の乱数列になり AUC が
   0.0016 動く（2026-09-15 に実測）。1つのハーネスで両方を評価し、
   base_margin 配列の md5 が P・N で一致することをログに出す。
4. **特徴量列の一致**: N の列集合が P の 134列と完全一致（集合としても順序としても）。
   増減があれば「データを足した効果」ではなくなる。

## 8. この測定が答えない問い

- **較正**（B）: `calibrate_xgb.py` が base_margin を確定人気から作り、ドリフトを
  注入していない学習/推論パリティ違反。cal_prob の OOS ECE は 0.0682（13,143頭）。
  ⚠ ただし影響範囲はアプリの穴マーク（`cal_prob>=0.15`）と表示だけで、
  **商品の印・買い目・`conf`・複勝率列には届かない**（`src/product` は `cal_prob` を読まない）。
- **商品が出す数字の較正**（C）: `conf` と複勝率列は `softmax(T=3.5) → Harville` で、
  較正器が入らない経路。軸の `fuku_prob` は OOS ECE 0.0484、10月は実測が予測を +0.100 上回る。
  ここは `conf` の尺度が動くと `CONF_STRONG=66` / `CONF_LIGHT=55` の意味が変わるため、
  **別のカードを書いてから**しか触らない。
- **月次自動再学習の再開**: cron は 2026-08-03 に停止。止めた理由（GitHub側 history.db が
  Colab側の半分）は **2026-08-05 のマージで解消済み**だが、ワークフローのコメントと
  閾値（`AUC_THRESHOLD=0.75`）は当時のまま。このカードでは触らない。
