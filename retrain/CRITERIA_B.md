## 1. 直す欠陥（コードで確認済み）

`src/tools/calibrate_xgb.py::_predict_fukusho_probs` は base_margin を
`horse_history.popularity`（**確定人気**）から作る。一方:

| | base_margin の土台 |
|---|---|
| `train_xgb`（学習） | 確定人気 **＋ 実測ドリフト注入**（`simulate_serving_popularity=True`・seed 11/12）|
| `engine.calc_all`（本番推論） | **朝オッズ**の昇順から導いた人気 |
| `calibrate_xgb`（較正） | **確定人気（ドリフトなし）** ← ここだけ鋭い |

→ モデルは「ぼやけた土台」で学習し、較正器は「鋭い土台」で当てられ、本番は
「ぼやけた土台」で動く。`_predict_fukusho_probs` の docstring 自身が
「base_margin の作り方は engine.py の推論経路と同一にすること。ここがズレると
較正が本番と違う分布に対して当たってしまう」と書いており、**意図は明示されていて
実装が追いついていない**。

実測（2026-10-19・完全OOS 13,143頭の本番予想）: cal_prob の **ECE 0.0682**。
全体の水準は合っている（予測 0.226 / 実測 0.228）のに両端が外に開く**傾きの誤差**で、
較正時の記録 Test ECE 0.0097 の7倍。月別は 0.0476 → 0.0550 → 0.0423（8月以降）で
**経年劣化ではなく構造**。

## 3. 修正の方針

`_predict_fukusho_probs` の base_margin に、`train_xgb` と**同じ関数**で
同じドリフトを注入する（`load_popularity_drift` / `_apply_popularity_drift`）。
自前で書き直さない。seed は 11/12 と衝突しない **13** を使う（分布を合わせるのが
目的で、特定の引きを再現したいわけではない）。

⚠ **採らなかった案**: `race_predictions` の実朝オッズで較正器を当てる案のほうが
条件は忠実だが、①データ源を変える大きな変更 ②N が 13,948行に減る
③`cal_prob` が表示専用である以上、釣り合わない。**今回は最小の修正に留める。**

## 4. 測定の設計

- **評価行**: `race_predictions` のうち `date > 2026-06-30`（本番モデルにとって完全OOS）
  かつ `actual_place` 非NULL。**base_margin は `race_predictions.popularity`＝
  engine が朝オッズから導いた実際の値**を使う（シミュレートしたドリフトではなく本番の条件）。
- **学習行**: `horse_features.csv` の `date <= 2026-06-30`（評価行と重ならない）。
- **アーム**:
  - **OLD**: base_margin を確定人気から作って当てた較正器（現行実装の再現）
  - **NEW**: base_margin にドリフトを注入して当てた較正器（修正版）

- 両アームとも**同一の評価行・同一の raw_prob** に対して transform を当てる。

## 9. 🔴 v2 改訂（2026-10-19・**ECE を1つも読む前に**記録）

### 何が起きたか
`retrain/calib_ab.py`（`c06da93` / 修正 `43ab849`）を1回走らせたところ、
**自分で書いた中止条件2が自分を止めた**:

```

中央値差 0.02002  → 🔴 不通過（ECEを読まずに破棄）
```

カード §6 の指示どおりハーネスは ECE を読まずに破棄した。**OLD/NEW の ECE は

### 診断（中止条件が落ちた後の計測器の調査）
🔴 **再構成が間違っていたのではなく、中止条件2が構造的に通りえない設計だった。**

| 月 | N | 中央値 \|再構成 − 保存\| |
|---|---:|---:|
| 2026-07 | 3,405 | **0.18959** |
| 2026-08 | 4,560 | 0.01581 |
| 2026-09 | 2,986 | 0.00623 |
| 2026-10 | 2,121 | **0.00283** |
| **9/15 以降** | **3,594** | **0.00309** |

この階段は**本番モデルの世代交代の指紋**。保存されている `cal_prob` は
**その日に動いていたモデルと較正器**が出した値で、いま `data/` にあるものとは別物:

- 〜2026-08-20: **129特徴量**モデル（PLレーティング搭載前）→ 7月の 0.190
- 2026-08-21〜09-14: 134特徴量・8月21日版 → 8月の 0.016
- **2026-09-15〜**: いまの `xgb_fukusho_model_residual.pkl`（`trained_at 2026-09-15`・
  `val_auc 0.7846`）→ 0.003

つまり「中央値差 0.002 以内」は、**別世代のモデルが出した値を現行モデルで再現せよ**
と要求していた。正しい計測器でも通らない。2026-09-17 に自分で書いた
「対照群の合格基準を書いたら、その閾値が統計量自身の SE より大きいかを先に確かめる」
——**その手前の「そもそも達成可能か」を確かめていなかった**。同型の失敗。

✅ **本当に危なかった箇所は通っていた**: `_n`（出走頭数。base_margin の分母）は
CSV 側の頭数と **13,072行すべてで一致（1.0000）**。頭数がズレると base_margin が
丸ごと狂うので、ここが合っていることが再構成の健全性の主たる証拠。

⚠ 9/15 以降でも 0.003 残るのは既知の学習/推論パリティのズレ（`f_track_cond` が
推論時つねに 0.0／PLレーティングθは週次更新／`member_level_cache`）で、**B とは
無関係**。ゼロにはならない。

### 評価行を 9/15 以降に絞らない理由（SE で決めた）
絞るほうが検算は綺麗だが、**それをやると §5 の基準2 が機能しなくなる**。
上表のとおり ECE の検出限界は N=13,072 で ±0.0033、N=3,594 で ±0.0059。
基準2 の「改善幅 0.010 以上」は前者なら**約3倍の余裕**があるが、後者では
**1.7倍しかなく**、2026-09-17 の「SE より小さい閾値は何も判定できない基準」に
近づく。よって**評価行は全13,072行のまま**にする。

これが正当なのは、評価行の raw_prob は**両アームで完全に同一**で、
アームの違いは較正器だけだから。再構成に一定のズレがあっても
**アーム間の差を作ることはできない**（水準の読み方には効くので、
ECE の絶対値は「現行 pkl 比」として読む）。

### ⚠ この改訂の弱点（正直に書く）
2b の数字（0.0035 / 0.0059）は**この改訂を書く前に測った**。
「達成可能な床を先に測ってから線を引く」という手順そのものは 2026-09-17 の
教訓に沿っているが、**線を引いたのは床を見た後**である。読む側はその分だけ
割り引くこと。割り引いても残るのは ①`_n` 100%一致 ②0.0682 の独立再現
③世代交代で階段が説明できること の3つで、これらは線の引き方に依存しない。
