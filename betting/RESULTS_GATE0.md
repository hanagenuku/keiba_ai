## 1. 🔴 対照群A が計測器の欠陥を1つ捕まえた（これが今回いちばんの収穫）

**1回目の測定で 0-d が落ちた。**

```
1回目  mean(ρ_shuffle) = +0.01758 / std 0.00693 / 合格線 0.00098   🔴 落ちた
```

T をレース内でシャッフルしているのに ρ が 0 に戻らない＝**計測器が偽の相関を出していた**。

### 機序（合成例で確認してから直した）

事前登録では「同値のタイブレークは**馬番の昇順**」としていた。これが原因だった。

- 適性 T が同値の馬では、順位が**必ず馬番順**になる
- 能力側も初出走馬（θ=0）の同値を馬番順で割る
- → 両方の順位に**共通の馬番成分**が入り、T をシャッフルしても消えない

本データを触らずに合成例で機序を確認した:

| 同値の入り方 | 強制タイブレーク（旧） | 平均順位（新） |
|---|---:|---:|
| 同値なし | +0.005 | +0.005 |
| a に4頭同値 | +0.004 | +0.003 |
| **t に4頭同値** | **+0.090** | **−0.002** |
| 両方に4頭同値 | −0.032 | −0.002 |
| **t が全頭同値** | **+1.000** | **未定義(NaN)** |

### 直した内容

**同値は平均順位（tie-aware）にした。** Kendall も tau-b（同値補正つき）に直した。

⚠ これは**閾値・構成列・符号・重み・期間・母集団の変更ではない**。
「🔴 着順を絶対に使わない」という当初の意図は、**恣意的なタイブレークを置かない
平均順位のほうがより厳密に満たす**。

🔑 **対照群Aが無ければ、この偏りを乗せたまま 0-a の数字を読んでいた。**
偏りは +0.0176 で 0-a の判定（0.49 vs 合格線 0.80）は動かないが、
「小さいから良い」ではなく「**計測器が0を返すべき場所で0を返さなかった**」ことが問題。
2026-09-15（市場残差のセル平均が構造的に0しか返せなかった）と同じ型を、
今回は**入る前に**捕まえられた。

```
2回目  mean(ρ_shuffle) = +0.00053 / std 0.00693 / 合格線 0.00098   ✅
```

### 0-a 縮退検査

```
ρ̄ = +0.4931    合格線 < 0.80   ✅
ρ の分布  5% −0.059 / 25% +0.329 / 中央 +0.531 / 75% +0.702 / 95% +0.898
平均絶対順位差            2.959
|順位差| >= 3 の馬の割合    44.6%
並べ替え P                0.0000
```

🔑 **0.79 と 0.81 の間に本質的な境界は無い**ので、分布として読む。
ρ は 5%点で負、95%点で +0.90 と**レースによって大きく違う**。
「能力と適性が一致するレース」と「大きく食い違うレース」が両方ある。
**馬の44.6%で能力順位と適性順位が3つ以上ずれている。**

並べ替え P = 0.0000 は「ρ̄ が偶然の0ではない」ことだけを言う。
**大きさの判定は閾値のほうで行う**（North Star #11: 有意性ではなく大きさ）。

#### 🔴 列ごとの単独 ρ̄ ← ここが一番重要

| 列 | ρ̄（能力との縮退） | τ̄（条件感応・低いほど反応する） | レース数 |
|---|---:|---:|---:|
| `f_course_fit_score` | **+0.7273** | **+0.9114** | 1,762 |
| `f_dist_vs_optimal`(−│·│) | +0.1906 | **−0.0630** | 1,747 |
| `f_style_course_fit` | +0.1713 | +0.8845 | 1,771 |
| `f_speed_x_shortening` | −0.0373 | +0.5170 | 1,520 |
| `f_stamina_x_extension` | −0.0484 | +0.6152 | 1,471 |

🔴 **`f_course_fit_score` は「両方で最悪」。** 能力との相関が最も高く（+0.73）、
かつ今回条件を差し替えてもほとんど動かない（τ̄ +0.91）。
これは**構築式から予想できたこと**で、

```python
f_course_fit_score = 5 * (stamina_demand · f_stamina_score + speed_demand · f_speed_score)
```

の `f_stamina_score` / `f_speed_score` は**その馬の能力水準そのもの**。
強い馬はどちらも高いので、コースの要求が何であれ高く出る。
＝ **「適性」の顔をした能力の掛け算**。

🔵 逆に `f_speed_x_shortening` / `f_stamina_x_extension` は ρ̄ ≈ 0 で
**能力から完全に独立**している。ただし距離が変わるレースでしか定義されず
（1,520 / 1,471 レース）、変化がない側は 0 に潰れる。

🔵 `f_dist_vs_optimal` は **τ̄ = −0.063** で唯一「条件を変えると順位がまるごと変わる」。
今回距離を差し替えれば最適距離からの外れ方が変わるので当然だが、
**5列のうちこれだけが素直に「今回条件への適合度」の形をしている**。

## 4. 🔴 読み方の注意（Step 1 に持ち越す）

1. **合格したが、合格の中身は均質ではない。**
   T は5列の等重み平均だが、能力に寄っているのは `f_course_fit_score` 1列。
   これを外せば ρ̄ はさらに下がるはずだが、**外していない**
   （事前登録した構成列を結果を見てから変えない）。
   ⚠ **Step 1 で「適性が効いた」という結果が出たら、まず
   `f_course_fit_score` だけで説明がつかないかを確かめること。**
   つかないと示せるまで「適性が効いた」と書かない

2. **0-a が通ったことは「適性が結果を当てる」ことを一切意味しない。**
   Gate 0 は目的変数を使っていない。測ったのは**特徴量の幾何だけ**

3. **`f_course_fukusho` 系（条件付き能力）は最初から除外してある。**
   もし将来それらを T に戻すなら、Gate 0 をやり直すこと
   （`HORSE_ABILITY_DESIGN.md` §9）

4. **馬場適性4列は除外したままにする。**
   `f_track_cond` が推論時つねに 0.0 なので、学習データで作った規則が
   予測時に再現できない

5. 🔴 **Step 2（能力×適性 → 市場残差）は最後まで記述のみ。**
   「このセルは市場残差が良いから Step 3 で買う」は**禁止**。
