## ① 評価した確率（コードで確認した1つだけ）

```
XGB(134特徴量・residual) → predict(output_margin=True) = raw_margin
ability_margin = raw_margin − base_margin(当日の市場人気)
e0 = sigmoid(ability_margin + _flat_base_margin(頭数))
★ ev_tan_pct = Isotonic_win(e0)        ← これを測った（画面の「AI勝率」）
```

🔴 順位用の `tan_pct`（softmax T=3.5 → Harville・レース内合計1.0）とは**別物**で、
今回は一切混ぜていない。`sim_ev`・`cal_prob` も対象外。

⚠ `ability_margin` には `f_pop_last` 等**過去の市場評価**が入る。「市場フリー」ではなく
**当日の現在オッズを直接使わない確率**。

## ⑥⑦ Calibration と Resolution の分解（Murphy・11帯）

`BS = REL − RES + UNC`（REL は小さいほど良い＝較正／RES は大きいほど良い＝識別）

| 腕 | REL | RES | UNC | **RES/UNC** | BS |
|---|---|---|---|---|---|
| E0 未補正 | 0.01202 | 0.00430 | 0.06736 | 6.4% | 0.07508 |
| **E1 Isotonic** | **0.00005** | 0.00417 | 0.06736 | **6.2%** | 0.06324 |
| 参考M 市場 | 0.00007 | **0.00672** | 0.06736 | **10.0%** | 0.06071 |

🔑 **Isotonic は REL を 0.01202 → 0.00005（240分の1）にする一方、RES は
0.00430 → 0.00417 とほぼ動かさない。** 較正と識別が完全に分離して見えている。

🔴 **そして RES で市場に 1.6倍 負けている。** これが Resolution の不足。

## Q1〜Q7

**Q1 現在のAI勝率は実際の勝率に対してどの程度正確か**
→ **かなり正確**。ECE 0.0069、N≥200 の全帯で **±1.6pt 以内**。
予測平均 6.84% に対し実測 7.26%（全体で 0.42pt の過小）。

**Q2 どの確率帯で過大・過小評価が発生しているか**
→ **校正前は全帯が過大評価**で、**上の帯ほどひどい**（0-5%帯 −4.18pt → 50-60%帯 −21.15pt）。
校正後に残るのは 10-15%帯の **+1.58pt 過小**と 30-40%帯の +4.43pt 過小（N=165）だけで、
**過大評価は1帯も残っていない**。

**Q3 Isotonic で安定して補正できるか**
→ **できる**。ECE 0.1067 → 0.0069（15分の1）。較正器が一度も見ていない期間でも
CV 0.0075 / OOS 0.0069 とほぼ同じで、帯ごとのズレの符号も 6/7 一致。過学習していない。

**Q4 校正後のAI確率は十分な Resolution を持っているか**
→ **持っていない**。RES/UNC 6.2%（基準10%）。市場の 10.0% に 1.6倍 負ける。
**「勝率30%以上」と言える馬が 32,904頭中 172頭（0.52%）しかいない**（市場は 2,328頭）。
1レースあたり「20%以上」は AI 0.28頭 / 市場 1.06頭。必ず1頭が勝つのに名指しできていない。
✅ ただし**順序は完全に正しい**（0-5%帯 1.98% → 30%以上 37.21% で単調・18.8倍）。

**Q5 校正後のAIは市場より馬の強弱を正確に区別できるか**
→ **できない**。AUC 0.7647 vs 市場 0.7932。実オッズの部分集合でも 0.7508 vs 0.8091。
PR-AUC も 0.1829 vs 0.2409 で負ける。

**Q6 AIが市場と異なる場合、その独自判断に情報価値はあるか**
→ **ほとんど無い。あるのは"向き"だけで、大きさは完全に外している**。
実オッズ対照で **6帯すべて市場が近く、4帯では市場が ±0.81pt 以内**。
唯一の情報は、AIが+10pt以上強気な馬の実測が市場より +2.62pt 高いこと。
だがAIはそれを +13.12pt 高いと言っている（18.57% vs 5.45%）。
市場を統制した上乗せは **+0.0025 AUC**（本番モデルの既知 +0.0009 と同じ桁）。

**Q7 最終結論**
→ **「確率としては校正されているが、市場を上回る Resolution が無い」**。後者の状態。

```
A 確率として正しいか        ✅ ほぼ完全（ECE 0.0069・市場より良い）
B 強弱を区別できるか        🔴 不足（RES/UNC 6.2% / 基準10%）
C 市場を上回るか           🔴 負け（AUC 0.7647 vs 0.7932）
D 馬券として儲かるか        既測で 73.7%（全部買う73.1%）
```

**画面の「AI勝率 12%」は額面どおり読んでよい。12%前後で実際に勝つ。**
**だが「どの馬が12%でどの馬が30%か」を市場より上手く言い当てているわけではない。**
絶対確率として必要オッズを計算する用途には**使える**が、それが儲けにつながらないのは
較正が悪いからではなく **Resolution が足りないから**、と今回で切り分けが付いた。

🔑 **これは「直すべき欠陥が見つかった」ではない。** 較正は既に成功しており、
Resolution は入力情報そのものの限界（129特徴量で市場に +0.0009、Phase 2/②-A/展開/回顧が
すべて同じ壁に当たっている）。**較正をさらに磨いても Resolution は1ミリも増えない**
（今回 REL が240分の1になっても RES は 0.00430→0.00417 と動かなかった）。

## 🔴 この検証で見つけた自分の defect（記録）

事前登録 §6 の「関門を1つ壊して実際に止まるか確認する」を実行したところ、
**自分の書いた NaN 関門が素通りした**。

```
assert dev <= t          dev=NaN → 失敗（止まる）  ✅ 正しい
assert not (dev > t)     dev=NaN → 通過（素通り）  🔴 私が書いた形
```

2026-08-25 の教訓は `if not (x <= t): raise` という**raise形**についてのもので、
`assert` は真偽が逆なので同じ字面をそのまま持ってくると意味が反転する。
✅ リポジトリ側の本番コード（`scripts/eval_odds_anchor.py:243`）は raise形で正しく、
今回の defect は私の検証スクリプトだけ。修正して、実際に止まることを再確認した。

🔑 **関門は「置いた」ではなく「壊して止まるか試した」で初めて関門になる。**
