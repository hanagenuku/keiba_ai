# AI勝率の品質評価（較正 × 識別）— 結果を見る前に固定する

ユーザー指示（2026-09-11）。目的は **EV閾値やROIの最適化ではない**。
「確率として正しいか(A)」と「強弱を区別できるか(B)」を**分離して**測る。

## 1. 評価する確率を1つに確定する

コードで確認した本番の経路（`src/betting/app_json.py`）:

```
XGB(134特徴量・residual) → predict(output_margin=True) = raw_margin
ability_margin = raw_margin − base_margin(当日の市場人気・Zipf近似)
e0 = sigmoid(ability_margin + _flat_base_margin(頭数))     ← 土台を中立化
ev_tan_pct = Isotonic_win(e0) × 100                        ← ★ これを測る
ev_fuku_pct = Isotonic_fuku(e0) × 100
need_odds  = 1.2 / ev_tan_pct
```

🔴 **混同しないもの**（今回は測らない）:
`tan_pct` / `fuku_pct` = `softmax(total, T=3.5)` → Harville。
レース内合計が 1.0 / 3.0 になる**順位付け専用**の量で、絶対確率ではない。
`sim_ev` も、`cal_prob`（市場アンカー込み）も別物。

⚠ `ability_margin` には `f_pop_last` / `f_pop_avg` / `f_beat_market_rate` という
**過去の市場評価**が入っている。「市場フリー」ではなく
**当日の現在オッズを直接使わない確率**である。

主目的は **単勝（1着）**。3着内は副表として併記する。

## 3. 測るもの（全部、事前に列挙する）

**A 較正**: ECE（①ユーザー指定の固定11帯 ②10等頻度ビン の両方）/ Brier / LogLoss /
帯別 N・平均予測・中央値予測・実測・差(実測−予測)・Wilson 95%CI

**B 識別**: AUC / PR-AUC / 予測確率の標準偏差・分布 / 帯を上がるにつれ実勝率が
上がるか / 最上位帯と最下位帯の実勝率比

**A と B の分解**: Murphy の Brier 分解 `BS = REL − RES + UNC`（ユーザー指定の11帯で）

**腕**: E0 未補正 `sigmoid(ability+flat)` / **E1 Isotonic** / 参考M 市場
（人気×頭数帯の実測表。AIと**同じ較正trainで作る**）

**C 市場比較**: 同じ最終OOSで上記すべて。加えて logit の相関 R² と、
市場を統制した上でAIの順位に情報が残るか

**⑨ 乖離帯**: `AI確率 − 市場確率` を pt で -10以下 / -10〜-5 / -5〜0 / 0〜+5 /
+5〜+10 / +10以上 に切り、各帯の実勝率と両者の予測を比べる（**補助分析**）

## 4. 判定の書き方も先に固定する

- **A（較正成功）と言う条件**: 最終OOSで ①ECE(10等頻度) ≤ 0.010
  ②N≥200 の全帯で |実測−予測| ≤ 2.0pt ③較正val と最終OOS で帯ごとのズレの符号が一致
  → 3つ**すべて**満たしたときだけ「較正できている」と書く
- **B（Resolution十分）と言う条件**: Brier分解の RES が UNC の 10% 以上、
  かつ最上位帯の実勝率が最下位帯の 5倍以上
- **C（市場を上回る）と言う条件**: 最終OOSで **AUC が市場を上回る**こと。ECEでは判定しない
- **D（ROI）は今回測らない**。既測（必要オッズ超えだけ買って 73.7% / 全部買う 73.1%）

🔴 A が成功しても B・C・D は別問題。B が高くても A が悪ければ絶対確率には使えない。
**この4つを混ぜて1つの結論にしない。**

## 5. 禁止事項（ユーザー指示）

EV閾値の最適化 / ROI最大条件探し / 人気帯の細分化による条件探索 /
多数のセルから最大を拾う / 結果を見てから都合の良い条件を採用する — **全部しない**。
⑨の乖離帯分析から条件を拾って採用することも**しない**。

🔑 「較正は成功したが Resolution が足りない」も**十分な成果**として、そのまま報告する。

## 6. 関門（結果を見る前に置く・実際に止まるか確認する）

1. **検算**: `ability` が base_margin の取り方に依存しないこと（±3 振ってズレ < 1e-4）
2. **NaN で止まる**こと（`not (x <= t)` 型の比較。2026-08-25 に関門自体が壊れていた）
3. **行数の一致**: 各ブロックの頭数が §2 の表と一致すること
4. **市場表のリーク無し**: 市場表は較正trainだけで作り、最終OOSは使わない
5. **int の溢れ**: 目的変数を int8 のまま集計しない（2026-09-09 に実際に踏んだ）
