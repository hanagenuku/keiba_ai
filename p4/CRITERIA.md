# 事前登録: Phase 4 — AIが得意なレース条件の探索

作成 2026-09-08。ユーザー指示書「Phase 4：AIが得意なレース条件の探索」に対応。
**数字を見る前に確定させる。**

## 何を測るか（指示#1）
「AIが市場に勝てるか」ではなく **「AI − 市場 の差が、どのレース条件で変化するか」**。
この段階で買い条件を作らない。ROI も測らない（指示#17）。

## モデルを固定する（指示#3）
市場フリー cid82（M-1 で選抜）。学習コードは `mf1/fit.py` と同一手続き
（内側ホールドアウト42日で early stopping と Isotonic 較正・外側の窓は評価専用）。
Layer 1 に市場情報を入れない: `f_popularity` / `f_pop_last` / `f_pop_avg` /
`f_beat_market_rate` を除外した131列。

## 窓（時系列OOS・指示#14）
| | 窓 | 用途 |
|---|---|---|
| 探索期 | T1 2025-03-01〜04-30 / T2 2025-06-01〜07-31 / T3 2025-10-01〜11-30 | 条件を眺める |
| 確認期 | W1 2026-07-04〜09-06 / W2 2026-05-02〜06-28 / W3 2026-03-01〜04-26 | 再現するか見る |
ランダム分割は禁止。3シード(42/7/2026)の平均確率で評価する。

## 母集団（M-1 の教訓）
**市場と比べるときは必ず「人気が取れている行だけ」に揃える。**
揃えないと W2（`f_popularity` 充足 72.8%）で AI を全行・市場を部分行で並べることになる。

## 指標（指示#4・#13）
第一 3着内AUC差 / 第二 1着AUC差 / 第三 LogLoss差。
LogLoss は AI・市場とも**同じ内側ホールドアウトで Isotonic 較正した後**の値で比べる。
N（race数・horse数・平均頭数）を必ず併記する（指示#5）。
確認期はレース単位ブートストラップ300回で95%CIを出す。

## 判定
- **A** = AI−市場差が正、かつ探索期・確認期で同符号、かつCI下限>0
- **B** = 差は負だが全体基準線（確認期 −0.0197）より小さく、探索期でも同方向
- **C** = 全体基準線より明確に悪い
- 条件は R>=60（探索期・確認期とも）を満たすものだけ集計する

## 多重比較（指示#16）
65条件を見るので、個別セルの大小は根拠にしない。**決め手は
「条件別の差の順位が探索期→確認期で持ち越すか」**（Spearman ρ + 並べ替え検定2000回）。
2026-08-24 は同型の検査で r=−0.001（まったく持ち越さない）だった。そこと比較する。

## やらないこと
- ROI・買い条件（Phase 5以降）
- 条件を細分化して偶然の好成績を拾う（指示#17⑤）
- Layer 1 に市場情報を戻す
