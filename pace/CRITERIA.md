# P' ペース補正（pace_bonus）は本物か — 事前登録

## 何を測るか

`calc_all()` は残差学習モデルの出力のあとに、**ルールベースの手書き加算**を乗せている:

```python
pace_bonus = (自馬のf_pace − レース平均f_pace) × (P(スロー) − P(ハイ)) × 0.5
total = モデル素点×0.9 + レース内相対×0.1 + pace_bonus
```

レース内相対の混合は単調変換なので順位を動かさない。**順位を動かしているのは
pace_bonus だけ**である（本日23レース304頭で13.8%の馬が動き、最大5つ）。

🔴 この層は、記録を見る限り**一度も検証されていない**。
- 2026-08-17: 展開の同時分布 → 三連複+0.35%（必要+33.3%）で打ち切り
- 2026-08-27: 展開系29特徴量を全部抜いても AUC −0.0001
- 2026-08-24 E-1: 「`pace_bonus` は CSV に `f_front_adv`/`f_back_adv` が無く再現できていない」
  として**ゲート検証の対象から外されていた**

つまり展開という次元は2回否定されているのに、この手書き加算だけが本番の
順位・「推」印・軸選びに効いたまま残っている。

## きっかけ（記録しておく）

2026-09-13 中山R11 で7番ジャスティンシカゴ（10番人気35.5倍）が1着。
分解すると モデル素点は**11位**、pace_bonus +1.42 で**6位**に上がり、
その結果「推」印の条件（RL ≤ 人気−3）を満たしていた。
🔴 **N=1。これは仮説の出どころであって根拠ではない。**

## Step 1 — 順位づけの精度（取り込み基準）

3着内(y3) と 1着(y1) を目的に、レース内順位を予測子として AUC / LogLoss / Brier。

**取り込み基準**（この層をコードに残す条件）:
- 3着内AUC で P1 ≥ P0（悪化していない）

**採用基準**（この層を「効いている」と書く条件）:
- 3着内AUC で **P1 − P0 ≥ +0.002** かつ
- 期間を3分割（1-3月 / 4-6月 / 7-9月）して**3窓とも同符号**

❌ 取り込み基準すら割ったら「pace_bonus は順位を悪くしている」と記録し、既定OFFを提案する。

## Step 2 — 押し上げられた馬は本当に来るのか（本題）

`Δ = P0順位 − P1順位`（正なら pace_bonus が押し上げた）で層別し、
**3着内率**と**複勝回収率**を出す。Δ ≤ −3 / −2..−1 / 0 / +1..+2 / ≥+3 の5層。

### 🔴 先に置く対照群（結果を見る前に固定）

| 対照 | 何を潰すか | 通過条件 |
|---|---|---|
| **人気を揃える** | 押し上げられた馬は人気薄に偏るので、favorite-longshot bias で回収率が上下する | 同じ人気帯の中で比べても Δ≥+3 が有利 |
| **符号反転** `−pace_bonus` | 「ペースという軸が効く」のか「符号が正しい」のか | 反転腕は Δ の効果が消える／逆向きになる |
| **レース内シャッフル** | レース内の分布だけの効果 | 上乗せが消える |
| **f_pace そのもの** | pace_bonus ではなく素の f_pace が効いているだけではないか | pace_bonus の方が f_pace 単体より説明力がある |

⚠ プラセボはリーク検出には使えない（North Star #8）。ここでは
   「レース単位の構造だけで説明がつくか」を潰すためだけに使う。

## Step 3 — 「推」印の実績（ユーザーの関心の中心）

「推」= `RL順位 ≤ 人気−3` かつ `RL順位 ≤ 8` かつ `EV(=pn×オッズ) ≥ 1.2`（EV上位2頭）。

⚠ **history.db の `win_odds` は全年0%充足**なので、EV は人気からの Zipf 近似で
   代理するしかない。**代理であることを数字に必ず併記する**。

さらに 🔴 **この印の EV は3回否定された指標**である
（2026-07-05 / 07-30 / 08-31。本番8,546頭で EV≥1.0 は回収57.9%・買わない側75.0%）。
したがって Step 3 は「印が当たるか」ではなく
**「pace_bonus が無ければ付かなかった印」だけを取り出して、それが対照群を超えるか**を見る。

## Step 4 — 回収率（North Star #9）

Step 2/3 で有望な層が出た場合のみ。事前登録した5基準（**すべて満たさなければ不採用**）:

1. N ≥ 300頭
2. 複勝回収率 > 100%
3. 前半・後半とも > 100%
4. 上位3本の配当を抜いても > 100%
5. 日ブロック bootstrap の 95%CI 下限 > 100%

## Step 1b（追記 2026-09-13・**結果を見た後に足した事後探索**）

Step 1 で「P0 > P1 > シャッフル > 符号反転」という並びが出た。
つまり**向きは正しいが係数が大きすぎて、信号より雑音を多く足している**可能性がある。
そこで倍率 α を掛けた腕 `P(α) = 0.9×P0 + 0.1×相対 + α×pace_bonus` を調べる。

🔴 **これは結果を見てから足した問いなので、探索期と確認期を完全に分ける。**
- 探索期 2026-01-01〜04-30（ここ**だけ**見て α を選ぶ）
- 確認期 2026-05-01〜09-06（選抜に一切使わない）

**基準（走らせる前に確定）**:
1. 確認期で `AUC(α*) − AUC(P0) ≥ +0.002`（3着内）
2. 確認期でも符号がプラス
3. α* が 0 に潰れていない（潰れたら「補正は要らない」が答え）

❌ 満たさなければ「係数を下げても救えない」と記録し、既定OFFの提案に戻る。
⚠ ここで通っても回収率の話にはならない（North Star #9）。Step 4 が別に要る。

## Step 0b（追記・計測器の減衰チェック）

CSV から再構成した pace_bonus は本番の値と r=0.862（Step 0）。
再構成が雑音を含むぶん、pace_bonus の効果は**過小に**測られる（回帰希釈）。
実生成結果が残っている 415レースで「観測値を使った腕」と「再構成を使った腕」の
AUC差を並べ、結論が再構成の雑音で作られていないことを確かめる。
