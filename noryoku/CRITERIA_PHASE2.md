## 0. 設計の出発点（Phase 1b で確定している事実）

| | |
|---|---|
| 最大の同義群 | 8列・gain **16.19%**（`f_last1_rank` / `f_pl_rating` / `f_recent` / `rl_f_pl_rating` / `rl_f_pl_rating_rank` / `rl_f_pl_rating_z` / `rl_f_recent_rank` / `rl_f_recent_vs_field`）|
| `x` と その相対版の対 | **17対**（Phase 1b で数えた「8対」は |r|>=0.80 のものだけだった。ここでは17対すべてを対象にする）|
| 死んだ列 | 情報が無いのは `f_early_speed`（定数36.0）の1列だけ。他3列は別列と数学的に同一 |

### 🔑 コードを読んで最初に分かったこと（実測の前に確定している構造）

**(a) 最大gain群の「8列」は、独立した8つの量ではない。絶対量は3つしかない。**

```
f_last1_rank            = 前走の着順そのもの（生の着順。頭数で正規化していない）
f_recent                = 直近5走の着順を 10-(p-1)*10/15 で点数化し 0.75^i 重みで平均
                          （頭数・クラス・相手を一切見ない。着順だけ）
f_pl_rating             = Plackett-Luce θ（相手の強さを考慮した潜在能力）
rl_f_recent_rank        = f_recent のレース内順位
rl_f_recent_vs_field    = f_recent − レース平均
rl_f_pl_rating          = f_pl_rating − レース平均
rl_f_pl_rating_z        = 上記 / レース内 sd
rl_f_pl_rating_rank     = f_pl_rating のレース内順位
```
→ **3つの絶対量 + そのうち2つのレース内相対表現5つ**。
しかも `f_recent` の重みは 0.75^i なので、先頭項の比率は
`1 / (1+0.75+0.5625+0.4219+0.3164) = 0.328`。
**`f_recent` の32.8%は `f_last1_rank` の線形変換**である。

したがって P2-A の本当の問いは
「**`f_pl_rating`（相手の強さ）は、着順ベースの2列と別の能力なのか**」
と「**レース内相対化は固有の情報を足しているのか**」の2つに絞られる。

**(b) `vs_field` は定義上そのまま「レース内中心化」であり、`_rank` はレース内順位である。**
`engine.py: add_relative_features` の実装は
```python
xf[prefix + '_vs_field'] = sign * (vals[i] - mean_v)   # mean_v はレース平均
xf[prefix + '_rank']     = レース内順位
```
→ **中心化も順位化もレース内では単調変換なので、`x` と `x_vs_field` の
レース内順位は数学的に完全一致する。** 「相対化でレース内の新しい順位が生まれた」は
測るまでもなく **起こりえない**。

残るのは between-race 成分だけである。
```
x = m_r + c        m_r = そのレースの平均、c = 中心化された値
{x, c} を渡す  ⟺  {m_r, c} を渡す
```
つまり「絶対値と相対値を両方入れる」ことは、
**「今日のメンバーの平均的な強さ m_r を追加で渡す」ことと厳密に等価**。
P2-B はこの m_r に情報があるかを測る問いに還元される。

⚠ ただし目的変数 `is_fukusho` のレース内平均は **3/n で固定**されている。
メンバーが強かろうが弱かろうが3着内に入るのは3頭。
よって m_r が効くとしたら「頭数の代理」か「クラスの代理」としてであり、
**能力軸の話ではない**。この区別を結論に必ず書く。

## 1. P2-A — 最大gain群（8列）の分解

### A-1 何を測っているか
上記(a)の式をそのまま記録する。判定なし。

### A-2 本当に同じ能力を測っているか
**レース内中心化してから**相関を取る（8列中5列が既にレース相対なので、
生の相関は「レース間の差」と「レース内の差」を混ぜてしまう）。

| |r| | 扱い |
|---|---|
| >= 0.90 | 同一とみなす |
| 0.70〜0.90 | 強い重複 |
| < 0.70 | 別の情報を含みうる |

### A-3 それぞれ固有の情報を持っているか
各列を**他の7列で OLS 回帰**し、残差を取る。
- 残差比 `1 − R²` … その列のうち他で説明できない割合
- 残差単独の `is_fukusho` に対する AUC（レース内で中心化した残差を使う）

**事前登録の判定**
| 条件 | 判定 |
|---|---|
| 残差比 >= 0.20 **かつ** 残差AUC >= 0.520 | 固有情報あり |
| 残差比 < 0.20 | 他列でほぼ説明できる＝冗長 |
| 残差比 >= 0.20 だが 残差AUC < 0.520 | 固有だが**予測に効かない**ノイズ成分 |

### A-4 1つにまとめても情報を失わないか（本番同型 A/B）
| アーム | 列数 |
|---|---|
| **P0** 現行 | 134 |
| **P1** 8列 → 合成1列（8列の第1主成分・レース内中心化後） | 127 |
| **P2** 8列 → 絶対量3列だけ残す | 129 |
| **P3** 8列 → `f_pl_rating` 由来1列 + 着順由来1列 の2列 | 128 |

本番同型（residual・**ドリフト注入ON**・3窓 × 3シード、
W1 2026-07-04〜08-16 / W2 2026-05-02〜06-28 / W3 2026-03-01〜04-26）。
**3アームとも同じ行・同じ行順**で回す（base_margin のドリフトは行ごとに
乱数を引くため、行順が違うと別の乱数列になる。2026-09-15 に踏んだ罠）。

**事前登録の判定**
| 条件 | 結論 |
|---|---|
| P1 − P0 の平均 ΔAUC >= −0.001 かつ 悪化窓 <= 1 | **8列は実質1軸**。まとめてよい |
| P1 が落ち、P3 − P0 >= −0.001 | **2軸**（相手の強さ / 着順）|
| P3 も落ち、P2 − P0 >= −0.001 | **3軸**（絶対量3つが別物）|
| P2 も落ちる | 相対表現そのものに情報がある（A-5 へ）|

### A-5 複数の概念が混ざっていないか
「基礎的な競走能力」「近走状態」「相手関係」が混ざっているなら、
**層によって3つの絶対量の順位が食い違う**はずである。
層: キャリア走数（1-2 / 3-5 / 6-9 / 10+）・クラス（未勝利 / 1勝 / 2勝以上 / OP）・
中何週（連闘〜2週 / 3-8週 / 9週以上）。

各層で `f_pl_rating` × `f_recent` のレース内 Spearman ρ を出す。
**判定**: 全体の ρ に対し、ある層で **0.15 以上落ちる**なら
「その層では別概念として振る舞う」＝混在の候補として記録する。
⚠ これは観察であって採用根拠ではない（Phase 2 の結論は P2-C で出す）。

## 2. P2-B — `x` と `x_vs_field`（17対）

### B-0 まず数学から確定していることを書く
上記(b)のとおり、**レース内順位は定義上同一**。
よって「相対化で新しい順位情報が生まれたか」は測らない（答えは0で確定）。

### B-1 レース平均 m_r にどれだけ変動があるか
各対について
```
ICC = var(m_r) / var(x)      m_r = レースごとの x の平均
```
**判定**（「意味がない」と「差が出ていないだけ」を分ける唯一の物差し）
| ICC | 読み |
|---|---|
| < 0.05 | レース間でほぼ揃っている ＝ **現在のレース構成では差が出ていないだけ** |
| >= 0.20 | レース間に十分な差がある |

### B-2 本番同型 A/B（3アーム）
17対に対して
| アーム | 内容 |
|---|---|
| **B-abs** | 絶対値のみ（`*_vs_field` 17列を落とす）|
| **B-rel** | 相対値のみ（元の絶対値17列を落とす）|
| **B-both** | 現行（134列）|

同じ3窓 × 3シード・同じ行順。

**事前登録の判定**
| 条件 | 結論 |
|---|---|
| B-both − B-rel の平均 ΔAUC < +0.002 | 絶対値は追加情報を持たない |
| B-both − B-abs の平均 ΔAUC < +0.002 | 相対値は追加情報を持たない |
| 両方 < +0.002 | **対は片方だけで足りる**（重複整理の対象）|
| ICC >= 0.20 なのに両方 < +0.002 | **構造的に意味がない**（レース平均に情報が無い）|
| ICC < 0.05 で両方 < +0.002 | **いまのレース構成では差が出ていないだけ**。将来再検証の余地あり |

⚠ m_r が効いた場合は、それが**頭数・クラスの代理でないこと**を確認する
（`f_career_runs` / 頭数 / クラスを統制した上で m_r の増分を測る）。
統制すると消えるなら能力軸ではない。

## 3. P2-C — 独立した情報の塊はいくつあるか（Phase 2 の本体）

人間が分類表を作らない。**データから因子数を決める。**

### C-1 前処理
- 生きている全列（`f_early_speed` と完全重複3列を除いた130列）
- **レース内中心化**してから（本体モデルの実質の仕事はレース内の順位付けなので、
  レース間の水準差を持ち込むと因子が「レースの種類」を拾ってしまう）
- 列ごとに標準化

### C-2 因子数の決定（並行分析）
- 相関行列の固有値を出す
- **対照群A**: レース内で各列を**別々にシャッフル**（馬と列の対応を壊す）した偽データを
  100回作り、その固有値分布の95%点を出す
- **本物の固有値がその95%点を超えた個数 = k**

### C-3 事前登録した停止規則（← これが Phase 2 の出口）
| k | 扱い |
|---|---|
| **1** | **能力分解という筋をここで閉じる**。以後この方向の提案はしない |
| 2〜5 | その軸を Phase 3 以降の語彙として採用する |
| 6 以上 | 累積寄与70%までで丸め、丸めた個数を軸とする |

### C-4 軸の中身
k 因子で回転（varimax）し、各因子の高負荷列（|loading| >= 0.4）を列挙する。
因子間の相関が |r| >= 0.5 なら「独立した軸ではない」として統合する。

### C-5 年跨ぎ（持ち越すか）
- **前期 2023-01〜2024-12** で loading を推定
- **後期 2025-01〜2026-08** に射影し、後期で推定した loading と突き合わせる
- **判定**: 因子数が一致し、対応する因子の loading 相関 **ρ >= 0.7** なら「持ち越す」。
  持ち越さない因子は軸にしない

## 4. P2-D — 一般化ゲート（A/B で改善が出た場合にのみ適用）

`NEXT_PHASE_PLAN.md` の共通ルールをそのまま使う。
**AUC が通っても、以下を満たさなければ「一般的な能力軸」とは呼ばない。**

| | 出すもの | 基準 |
|---|---|---|
| 効果量 | 平均 ΔAUC と シード std | ΔAUC >= シード std の2倍 |
| 効果の分散 | 会場×馬場×距離帯セルごとの ΔAUC | 改善セルが過半 |
| 上位依存性 | 寄与上位セルを1・2・3個抜いて測り直す | 1つ抜いて消えるなら不採用 |
| 年跨ぎ | C-5 の loading 持ち越し | ρ >= 0.7 |
| OOS | 3窓すべて train_end より後 | 例外なし |

**採否の扱い**（`NEXT_PHASE_PLAN.md` の表と同じ）
- AUCゲート通過 × 効果が分散 → 軸として採用
- AUCゲート不通過 → **説明用の語彙**として残すが本番モデルには入れない
- AUCゲート通過 × 1〜2条件に集中 → **軸にしない**。条件付きの記録として残す

## 5. 対照群B — 計測器が本物を検出できるか（本データを読む前に通す）

North Star #11。対照群Aは「偽の因子が出ないか」しか見てくれない。
**本物の2因子があったときに、C-2 が本当に 2 を返すか**を先に確かめる。

合成データ:
- 実データと同じ行数・レース構成
- 因子 F1・F2 を独立に生成し、65列を F1 に・65列を F2 に割り当て、
  負荷 0.6、残りをノイズにする
- C-2 の並行分析をそのまま流す

**判定**: k == 2 を返せば計測器は正常。
**返さなければ本データの結果を印字せず中止する**（2026-09-16 に
「関門を置いたら壊れ方を1つ作って実際に止まるか確かめる」と決めた手順）。
