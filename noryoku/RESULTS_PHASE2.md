## P2-A — 最大gain群（8列・gain 16.19%）

### A-1 コードを読んで確定した構造（実測の前）
```
f_last1_rank         前走の着順そのもの（頭数で正規化していない生の着順）
f_recent             直近5走の着順を 10-(p-1)*10/15 で点数化し 0.75^i 重みで平均
                     → 先頭項の比率 1/(1+.75+.5625+.4219+.3164) = 0.328
                     ＝ f_recent の 32.8% は f_last1_rank の線形変換
f_pl_rating          Plackett-Luce θ（相手の強さを考慮した潜在能力）
rl_f_pl_rating       f_pl_rating − レース平均
rl_f_pl_rating_z     上記 / レース内sd
rl_f_pl_rating_rank  f_pl_rating のレース内順位
rl_f_recent_vs_field f_recent − レース平均
rl_f_recent_rank     f_recent のレース内順位
```
🔑 **絶対量は3つしかない。** 残り5列はそのうち2つのレース内相対表現。

### A-2 レース内中心化してからの相関
```
rl_f_pl_rating      × f_pl_rating   r = 1.000   （定義どおり完全に同じ列）
rl_f_recent_vs_field× f_recent      r = 1.000   （同上）
rl_f_pl_rating_z    × f_pl_rating   r = 0.965
f_pl_rating         × f_recent      r = 0.839
f_recent            × f_last1_rank  r = −0.819
```
→ 8列は**中心化した時点で実質4つ**（`f_last1_rank` / `f_pl_rating` / `f_recent` / 2つの順位列）。

### A-3 固有情報（他列で回帰した残差）
8列まとめて回すと4列が R²=1.0000（完全重複のため）。**絶対量3つだけ**で測り直した:

| 列 | 他2列で説明できない割合 | 残差だけの is_fukusho AUC | 事前登録の判定 |

| `f_pl_rating` | 0.295 | **0.5325** | 固有情報あり ✅ |
| `f_recent` | 0.197 | **0.5595** | 残差比が **0.197 < 0.20** で**基準を僅差で外す**が、残差は明確に効く |
| `f_last1_rank` | 0.326 | **0.5047** | 固有だが**予測に効かない**（ノイズ成分）|

🔑 **前走の着順そのもの（`f_last1_rank`）は、`f_recent` と `f_pl_rating` の上に何も足していない。**
単独では AUC 0.6851 あるのに、他2列を差し引いた残りは 0.5047＝コイン投げ。

⚠ 私が事前登録した「残差比 >= 0.20」は `f_recent` を 0.003 差で落とす。
**基準の線引きが効果の実体と合っていなかった**ので、そのまま報告する
（基準を後から緩めることはしない。判定は A-4 の A/B で行う）。

## P2-B — `x` と `x_vs_field`（17対）

### B-0 数学から確定していること（測るまでもない）
`engine.py: add_relative_features` の実装は
`vs_field = val − レース平均`、`_rank = レース内順位`。
どちらも**レース内では単調変換**なので、**`x` と `x_vs_field` のレース内順位は完全一致**する。
「相対化でレース内の新しい順位が生まれた」は起こりえない。

残るのは between-race 成分だけ:
`x = m_r + c` なので、`{x, c}` を渡すことは `{レース平均 m_r, c}` を渡すことと厳密に等価。

### B-1 レース平均にどれだけ変動があるか（ICC = var(m_r)/var(x)）
```
f_blood            0.9604   ← 異常値。後述
f_speed_fig_max    0.4979    f_speed_avg        0.4810    f_speed_fig_avg 0.4756
f_weight_load      0.4388    f_speed_fig_last   0.3730    f_late_speed    0.3653
f_speed_last       0.3573    f_pace_fit         0.2776    f_style_total_fit 0.2340
f_recent           0.2071    f_recent_fukusho   0.1963    f_style_course_fit 0.1740
f_dist_fukusho     0.1701    f_trainer          0.1566    f_jockey        0.1131
f_course_fukusho   0.1122
```
**ICC < 0.05 の対は1つもない** ＝「レース間で揃いすぎていて差が出ない」わけではない。

### B-2 本番同型 A/B（同じ3窓・3シード）
| アーム | 列数 | ΔAUC（W1/W2/W3） | 平均 |
|---|---:|---|---:|
| **B-abs 相対17列を落とす** | 117 | −0.0005 / +0.0006 / −0.0004 | **−0.0001** |
| **B-rel 絶対17列を落とす** | 117 | +0.0000 / +0.0001 / −0.0004 | **−0.0001** |

事前登録の判定にそのまま当てはめると:
**ICC >= 0.20 の対（8対）でも A/B が無反応 → 「構造的に意味がない」**。
レース平均（＝今日のメンバーの平均的な強さ）に、3着内を当てるための情報が無い。

🔑 機序も筋が通る: **`is_fukusho` のレース内平均は 3/n で構造的に固定**されている。
メンバーが強かろうが弱かろうが3着内に入るのは3頭。
だから「レース平均の水準」は原理的に目的変数を動かしにくい。

→ **17対は片方だけで足りる。17列は削れる**（削っても −0.0001）。

### 🔴 副産物: `f_blood` はレース内でほとんど馬を区別していない
```
ICC 0.9604  ＝ 分散の96%がレース間
全馬が同じ値のレース          44.0%（5,293 / 12,017）
レース内 std の中央値 0.0474 （全体 std 0.7261 の 6.5%）

```
`sire` の充足が 0.8%（2026-09-02 に確認済み）なので、ほとんどの馬が汎用値になり、
**`f_blood` は実質「距離・馬場の関数」＝レース条件の列**になっている。
gain 0.565% はレース内の馬の差ではなく、レース間の差を説明しているだけ。

## P2-C — 独立した情報の塊はいくつあるか

### 対照群B（本データより先に通した）
既知の2因子（130列を65列ずつ、負荷0.6）を注入 → **並行分析は k=2 を返した**。
固有値は 24.39 / 24.06 / 0.74 …。計測器は動く。

### 本データ
- 生きている130列のうち、**レース内で動く列は122**。
  動かない8列は `f_track_cond` `f_class_level` `f_dirt_turf_start` `f_course_hill_diff`
  `f_course_corner_tight` `f_pace_prob_fast` `f_pace_prob_slow` `f_course_speed_demand`
  ＝ **すでに「今日の条件」の列が8本ある**（ただし単独ではレース内順位を動かせない）
- レース内中心化 → 標準化 → 相関行列の固有値 vs レース内シャッフル100回の95%点

```
実固有値 top20 : 23.29 10.94 7.60 6.69 4.11 3.92 3.59 3.41 3.21 2.74 2.49 2.37 ...
帰無の95%点    :  1.056 1.053 1.051 1.049 1.048 ...
→ k = 26      累積寄与 70% は 18本目
```

🔴 **ここで計測器が degenerate している。** n=164,915 では帰無の95%点が 1.05 まで下がり、
並行分析は実質 Kaiser 基準（固有値>1）と同じになる。**弱い因子を止める力が無い。**
事前登録した停止規則（k>=6 なら累積70%＝18本を軸とする）を字義どおり適用すると
**18軸**になるが、これは「軸が18個ある」ではなく「この n では並行分析が効かない」という
計測器の限界である。**基準を後から緩めるのではなく、限界としてそのまま報告する。**

## P2-D（補強）— 「情報の塊」は目的変数に対して何本必要か

並行分析が止まらないので、**分散ではなく3着内を当てる力**で本数を測り直した。
因子は **2026-03-01 より前**（全検定窓より前）だけで推定して射影。
学習期の単独AUC順に因子を足していく。本番同型・3窓 × 2シード。

```

因子  2本        0.7566      ← 増やして下がる
因子  3本        0.7575
因子  4本        0.7591

因子  6本        0.7601
```

### したがって
1. **「能力を分解して本番モデルの精度を上げる」という筋は閉じる。**
   実質1軸 + 薄い尾。18本使っても +0.0027 で、控除率にも分解能にも届かない
2. **Phase 3・4 の語彙としては 8ブロックを採用する。**
   F1 近走・PL / F2 生タイム / F3 脚質×展開 / F4 接戦・キャリア /
   F5 騎手・調教師 / F6 斤量・年齢・血統 / F7 スピード指数 / F8 コース・距離適性
3. **重複整理は実行可能**（ただし Phase 2 の約束どおり本番モデルは触らない）:
   死んだ/完全重複 4列 + 17対の片側 17列 = **21列削っても AUC −0.0001**
4. **`f_blood` は馬の列ではなくレース条件の列になっている**（44%のレースで全馬同値）。
   血統を能力軸として使いたいなら、先に `sire` を溜めるしかない（2026-09-02 の結論と同じ）

### Phase 3 に持ち越す注意
- 「今日の条件」の列は**すでに8本あり、レース内では全馬同値**。
  つまり条件は**交互作用でしか効かない**。木は元から交互作用を作れる状態にあり、
  2026-09-02（道悪 × 型を明示的に手渡して −0.0008）で一度その壁に当たっている
- よって Phase 3 は「AUC を上げる」を出口にしない。
  **説明・表示・レース選択**のどれを出口にするかを、測る前に決めること
