## 問い（ユーザー / GPT・2026-09-09）

> 「AIが来る馬を当てられるか」ではなく「**AIが来ないと判断した馬をどれだけ高い確率で切れるか**」。
> とくに「**来る可能性が高い馬がいて、なおかつ来ない可能性が高い馬が多数いるレース**」を識別できないか。

> **重要：最初からROIを探さない。** まず「AIの予測 → 実際の着順」だけで検証し、
> 探索期間・確認期間の両方で安定して確認できた場合に初めてROIへ進む。

この順序はこのプロジェクトの事故（2026-07-27 / 07-30 / 08-29）を踏まえて正しい。
**本ファイルではROIを一切見ない。**

## 🔴 着手前に確定した事実（実測・2026-09-09）

本番の `race_predictions` 753レースで `fuku_prob` のレース内合計を測った:

```
中央値 3.000 / std 0.014   （win_prob は 1.000、cal_prob は 3.17±1.48）
```

⇒ **本番の `fuku_prob` は Harville で合計3に固定されている。**
したがって本番の画面上では

    切り馬の合計確率 = 3 − 上位3頭の合計

で、両者は**同じ量の裏返し**（相関 −1.000）。ユーザー提案の
「上位馬の強さ ＋ それ以外に残っている確率」は、本番の数字のままでは
**2つの情報にならない**。

✅ ただし本検証で使う Isotonic 較正確率は合計が固定されないので、
   残余は独立な情報を持ちうる。**そこは測って確かめる。**

🔑 そこで、裾の「広がり」を1つの数字にする指標を先に定義しておく:

    N_eff = (Σp)² / Σp²      （有効頭数 / inverse participation ratio）

同じ残余確率でも、5頭に薄く散っているのか15頭に散っているのかを区別する。
これは「上位3頭の合計」とは独立な自由度。

## 測ること（ユーザーの4問に対応）

### Q1. AIの「切り馬」性能（較正）
- 予測確率が **5% / 10% / 15% / 20% 以下**と判定した馬の**実際の3着内率**
- 予測確率の10分位ごとの **予測平均 vs 実測**（較正曲線）と ECE
- 🔴 3腕すべてで同じ表を作る。**AIがMKTより低く正しく切れているか**が本題

### Q2. 「切れる馬」が何頭いるレースか
- 各閾値での頭数分布（レース単位）
- 切り馬が多いレースほど**軸(AI1位)の3着内率**が高いか
- 🔴 **頭数で統制する**（`race_select/PRECHECK_cut.md` で cut_n と頭数の相関 +0.643）
- 🔴 MKT側の同型量でも同じ表を作る

### Q3. 「強い軸 ＋ 切り馬多数」（本命）
探索期で**1つだけ**条件を決め、確認期では変更しない。

見る量:
- 軸(AI1位)の3着内率
- AI上位3頭それぞれの3着内率
- 🔑 **AI上位3頭のうち何頭が実際に3着内に入ったか（0〜3の平均）**
  無作為の基準は `9/頭数`（n=14なら0.64）
- 逆側（難解レース: 上位が団子・切り馬が少ない）も同じ表で出す

### Q4. 切り馬の合計確率 / 裾の形
- 残余確率（上位3頭以外の合計）と上位3頭合計の**相関**
  （Isotonic較正確率で −1.0 に張り付くなら情報は1自由度しかない）
- `N_eff` を加えたときに、上位3頭合計だけの場合より説明が増えるか

## 判定基準（事前登録）

Q3 の条件が「本物」と言えるのは、**次を全部満たすとき**:

1. 探索期で、条件を満たすレースの軸3着内率が全体より **+5pt 以上**
2. **確認期でも +5pt 以上**（再現）
3. 確認期3窓（W1・W2・W3）すべてで**同符号**
4. 🔴 **MKT側で同じ形に作った条件を上回る**
5. **頭数で統制しても残る**（頭数帯ごとに符号が反転しない）

❌ どれか1つでも欠けたら不採用。とくに **4 が欠けたら「市場が切っているだけ」** と記録する。

### 結果ごとの結論（先に固定）

| 結果 | 記録する結論 |
|---|---|
| 1〜5すべて通る | 🔑 **切り馬構造には情報がある。次段階（ROI）へ進む** |
| 2 が通らない | 探索期の偶然。**この方向は閉じる** |
| 4 が通らない | 切り馬構造は実在するが**市場も同じものを見ている** |
| 5 が通らない | 正体は頭数（`PRECHECK_cut.md` の再現） |
