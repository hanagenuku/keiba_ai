# 事前チェック: 「切る馬」「読みやすいレース」で的中率は上がるか

⚠ **これは採用の根拠ではない。** 探索期/確認期を分けずに本番686レースを1回見た
実現可能性・直交性の確認だけ。判定は ②（`race_select/CRITERIA.md`）で行う。
2026-09-09 実施。

## 問い（ユーザー）

> 切る馬が数頭いる。来る確率の高い馬が数頭いる。レース展開を読みやすい。
> などの条件でレースを選択できれば、的中率はぐんとあがるのでは？

## ✅ 前半は正しい。的中率は本当に上がる

本番の実予想 686レース・22開催日（8頭以上・Σ(1/o)<=1.65 の健全な盤のみ）。

| 軸オッズ帯 | 的中率(軸の複勝) | 当たりの平均配当 | 回収率 |
|---|---|---|---|
| Q1（中央値 1.9倍） | **72.4%** | 1.17倍 | 84.5% |
| Q2（2.8倍） | 65.6% | — | 88.6% |
| Q3（3.7倍） | 50.0% | — | 76.9% |
| Q4（5.7倍） | **33.7%** | 2.21倍 | 74.3% |

的中率に **2.15倍**の差がある。「読みやすいレースを選べば当たる」は事実。

## 🔴 後半は成立しない。配当がちょうど打ち消す

```
的中率 2.15倍 × 配当 0.529倍 = 1.137倍
実測の回収率比               84.5 / 74.3 = 1.137倍   ← 完全に一致
```

最良の Q1（84.5%）から100%に届くには 1.18倍 必要で、そこにも足りない。

🔑 これは市場の非効率の問題ではなく **パリミュチュエル方式の構造**。
固定オッズなら「的中率を上げる」は直接勝ちにつながるが、JRAでは
**当たりやすい馬を選ぶ操作が同時に配当を縮める**（North Star #9 の機序）。

## 「切れる馬の数」は新しい軸だった（直交性は確認できた）

`cut_n` = そのレースで `fuku_prob < 0.10` の頭数（＝自信を持って切れる馬の数）。
既存の軸は分布の**上端**（軸の確度・上位集中度）を見ており、下端は見ていなかった。

| 相手 | 相関 |
|---|---|
| 軸の3着内確率 | +0.409 |
| AIのエントロピー | −0.651 |
| **市場側の集中度 (M_top1)** | **−0.202** |
| **市場側のエントロピー** | **+0.071** |
| 🔴 頭数 | **+0.643** |

市場側とはほぼ無相関＝**市場が見ていない量**。ただし**頭数との相関が高い**。

## 🔴 5基準を1つも通らなかった

```
cut_n Q4（8頭以上切れる） N=91 / 17開催日   回収 102.3%
  → 3本抜きで          78.0%      （高配当1〜3本に依存）
  → 前半 114.9% / 後半  90.0%      （持ち越さない）
  → +だった日           6/17       （過半に届かない）
  → 95%CI(日ブロック)   [81, 126]  （下限が100%未満）
  → 的中率 Q1 55.2% → Q4 54.9%     （🔴 まったく動いていない）
```

**最後の行が決定的。** 的中率が動かず回収率だけ上がったのは、この軸が
「当たりやすさ」ではなく**配当の大きさ**を選んでいたから。
軸のオッズ中央値は Q1 2.8倍 → Q4 3.8倍。
つまり **「切れる馬が多い」＝「多頭数」＝「軸のオッズが長い」**。

頭数で統制すると符号が安定しない:

| 頭数 | cut_n 多い | cut_n 少ない | 差 |
|---|---|---|---|
| 8-12頭 | 72.9% | 81.7% | **−8.8pt（逆転）** |
| 13-15頭 | 94.9% | 61.0% | +33.9pt |
| 16-18頭 | 106.4% | 76.8% | +29.6pt |

## ⚠ 自分への注記（多重比較）

この一連で**約35セル**を見ている。2026-08-31 の帰無シミュレーションでは
25セル中 **3.7個**が偶然100%を超える。観測2〜3個は期待どおりで、
「100%を超えるセルを見つけた」は何の証拠にもならない。

## 判定

- 「レース選択で的中率が上がる」は**正しく、既に効いている**
- 効かないのは**的中率の改善が回収率に変換されないこと**で、券種の構造の問題
- `cut_n` / `cut_frac` は市場側と直交しているので **② の腕Jの特徴量に追加する**。
  686レース・分割なしでは何も言えないが、3,969レース・探索期/確認期を分けた
  ②の枠組みなら決着がつく
