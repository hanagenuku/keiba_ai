以後、確認期の数字を見てから**閾値・特徴量・モデル・買いレース数・判定基準を

## なぜ「セル探索」をやめたか（ユーザー合意・2026-09-09）

当初案は12軸を組み合わせて条件セルを探索するものだったが、両者の合意で取り下げた。
理由は既存の実測にある:

| 既存の結果 | 何を示すか |
|---|---|
| 2026-08-24 F-4: 条件別Δの順位が前半→後半で **r = −0.001**（並べ替え検定 P=51%） | **ROIでは条件の順位が持ち越さない** |
| 2026-09-08 Phase 4: 同じ問いを **AUC** で測ると ρ=+0.483（P=0.0000）で持ち越す | 差は**測っている量**。AUCは滑らか、ROIは配当の裾に支配される |
| 2026-08-15②: 25マスで事前登録5基準を満たすセル **ゼロ** | 多重比較 |
| 2026-08-31: 緑セルの枚数は帰無の期待3.7個に対し観測5個＝**真ん中** | 同上 |
| 2026-08-28: 条件別に特徴量を抜く選抜の持ち越し **10%**（偶然なら50%） | 選抜が反予測的 |

🔴 さらに機序が逆向き: Phase 4 の `corr(市場AUC, AI−市場差) = +0.537`。
**AIが相対的に強いのは市場も当てているレース**＝配当が縮んでいるレース。

したがって②は**探索ではなく3つの数字の比較**にする。セルを1つも列挙しない。
⇒ 多重比較が構造的に発生しない。

## 3つの腕

| | 中身 | 位置づけ |
|---|---|---|
| **腕R** | 軸(RL1)の `top3_prob` **1変数だけ** | 現時点で唯一、大規模で単調性が確認された軸（E-1: Q1 72.9% → Q5 83.9%、3,969レース） |
| **腕J** | 下記18特徴量を全部入れた **1本のモデル** | ユーザーの12軸案をまとめたもの |
| **腕M** | **市場由来の特徴量だけ**で作った同型モデル | 🔴 必須の対照群 |

🔴 **腕M が必須な理由**: レース選別の利得が市場側に落ちることが2回実測されている。
- 2026-08-24 E-3(馬連): AIで選ぶ 60.5% vs 素直に人気順で選ぶ **71.4%**
- 2026-09-01(不人気馬): AI 72.9% vs 同じ帯の市場人気最上位 **73.0%**（完全に同じ）

腕R も腕J も腕M を上回らなければ、AIはレース選別に寄与していない。

### 腕Jの特徴量（**探索期に入る前に確定・以後追加しない**）

市場由来（腕Mにも入る）:
1. 市場1番人気の市場示唆確率（集中度）
2. 市場示唆確率のエントロピー
3. 市場示唆確率の上位2頭の差
4. 出走頭数
5. 距離 / 6. 芝ダート / 7. 競馬場 / 8. クラス / 9. 馬場状態
10. オッズ分布の歪み（上位25%平均 ÷ 下位25%平均）

AI由来（腕Jのみ）:
11. **軸の `top3_prob`**（＝腕Rと同じ量。入れないと不公平になる）
12. 軸の `win_prob`
13. AI上位3頭の確率合計
14. AI 1位と2位の確率差
15. AI1位＝市場1番人気か（0/1）
16. AI上位3頭と市場上位3頭の一致数（0〜3）
17. gap = 軸の市場人気順位 − RL順位
18. 脚質構成: 過去走から推定した逃げ馬・先行馬の頭数
19. **`cut_n`**: `fuku_prob < 0.10` の頭数（＝自信を持って切れる馬の数）
20. **`cut_frac`**: 同上を頭数で割った割合

⚠ 19・20 は 2026-09-09 のユーザー提案（「切る馬が数頭いる条件で選別できないか」）を受けて追加。
`race_select/PRECHECK_cut.md` のとおり **市場側の集中度とほぼ無相関(−0.20)** で
分布の下端を見る新しい量。ただし**頭数との相関が +0.643** と高いので、
腕Mに頭数（特徴量4）が入っていることで統制される。
🔴 事前チェックでは 102.3% のセルが出たが3本抜きで78.0%・CI下限81%。
**あの数字は採用根拠にしない**（探索期/確認期を分けていない）。

⚠ Phase 4 の指摘どおり **AI集中度・エントロピーは内生的**。腕Mに市場側の同型量
（1・2・3）を入れることで自動的に統制される。

## 目的変数 — 🔴 AUCではなく ROI そのもの

    r = 軸(RL1)を複勝1点100円で買ったときの実現リターン（払戻/100）

- 主目的変数は **r**。腕J・腕M はこれを回帰で予測する
- 副として「軸が複勝圏に入ったか(0/1)」も出すが、**判定には使わない**
- ⚠ この設計自体が「当たりやすさ ≠ 儲けやすさ」を直接検定することになる
  （2026-08-18② は的中側で測って 100% に届かなかった）

## 買いレース数を揃える（結果を見る前に決める）

ROIは「何レース買うか」で動くので、**確認期では買いレース数を揃えて比較する**。

- 主判定に使う割合は **上位30%** に固定する（探索期のNから、確認期で
  1腕あたり約500レース＝北Star #7 の N≥300 を満たす水準として先に決めた）
- 10% / 20% / 50% も出すが**参考値**。主判定は30%のみ

## 評価指標（ユーザー指定・全腕で必ず併記）

## 主判定（事前登録・これ以外の理由で採用しない）

**腕J が腕R を確認期で上回る**とは、次の3つを**すべて**満たすこと:

1. ROI が腕R より高い
2. 確認期の**前半・後半とも**腕R より高い
3. 日ブロック bootstrap（2,000回）で **腕J − 腕R の 95%CI 下限 > 0**

### 結果ごとの結論（先に固定）

| 結果 | 記録する結論 |
|---|---|
| 腕J が3基準すべてで腕Rを上回る | レース条件による選別に上乗せがある。次の検証へ |
| 腕J が腕R を上回らない | 🔴 **②終了。「レース条件による選別」の方向は閉じる** |
| 腕R も腕J も腕M を上回らない | **レース選別の利得は市場側にある**（E-3・不人気馬検証と同じ結論） |
| どの腕も ROI < 100% | 選別の順序は正しくても控除率を超えない（既存の結論と整合） |

⚠ **どの腕も 100% を超えないことが最も起こりやすい結果**。
   その場合「腕Jが腕Rを上回った」だけを取り出して成果として書かない。

## 計測器の関門（結果を見る前に置く・North Star #8 / 2026-08-17の教訓）

1. **対照群**: レース単位で r をシャッフル → 腕Jの選別によるROI差が0付近に消えること
2. **較正チェック**: 探索期で「予測 r」と「実測 r」が単調
3. **母集団の検算**: 配当欠損の除外率が 3〜4%（2026-08-18③の実測と一致するか）
4. **腕の同一性**: 3腕とも同じレース集合・同じ買いレース数で比べているか
5. 🔴 **関門を1つ壊して、実際に止まるか確かめる**
   （2026-08-25 D-2④で「NaN > 1e-4 は False」により関門が素通りした）
