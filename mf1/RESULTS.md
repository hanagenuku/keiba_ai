# M-1 結果: 市場フリーモデルのハイパーパラメータ最適化

実施 2026-09-08。事前登録は `mf1/CRITERIA.md`（結果を見る前に確定・commit 83f697c）。

## 結論

**現行既定は 121配置中 113位だった。** 探索期で選んだ配置を確認期で測ると
**3着内AUC +0.0283**、5指標すべてが同じ方向に改善した。
市場との差は **−0.0277 → −0.0149** と**ほぼ半分**になった。

これは特徴量を1つも足していない。**設定が目的とズレていただけ**だった。

## 🔴 まず前ハーネスの欠陥を直した（関門1）

`pl/stage2.py` は early stopping の `eval_set` に**外側の検証窓**を渡していた。
A/B比較（θ差し替え）では両アームに同じ下駄が乗るので結論は歪まなかったが、
ハイパーパラメータ探索では検証窓へのリークになる。

M-1 では **学習期間の末尾42日を内側ホールドアウト**に切り出し、
early stopping も Isotonic 較正もそこだけで行う。外側の窓は評価にしか使わない。

```
確認期3窓 現行既定   旧ハーネス 0.7889  →  新ハーネス 0.7626   (−0.0263)
```

下がるのは想定内（下駄が外れたため）。⚠ **以後、旧ハーネスの 0.7889 とは比較しない。**

### 下がった理由がそのまま今回の発見だった

```
現行既定 (ES指標=logloss)   3着内AUC 0.7646   使った木 2,381本   ← W1・単発
     ↓ ES指標を auc に変えただけ
現行既定 (ES指標=auc)       3着内AUC 0.7768   使った木   340本
```

**木を7分の1にしてAUCが +0.0122 上がる。** 2026-09-08 に測った
「木を 500→4000 に増やすと AUC が単調に悪化する」の裏側で、
early stopping が **logloss で止めている**ので、logloss が改善し続ける限り
木を足し続ける。その区間ではもう順位付けの質は落ちている。

`n_estimators=500` は「偶然の正則化」だったと前回書いたが、**より正確には
「止め方の指標が目的とズレていた」**。訂正する。

## 🔴 副産物2: origin/main の集計キャッシュが 2026-08-05 のマージ前で止まっている

フル履歴から再構築      43,220     164,328    4,172      331

`history.db` の place有り行数は 164,328。origin/main の 69,466 は

チューニングノートがマージ後に一度も実行されていないため。

⚠ これは M-1 とは別の課題。直すなら「キャッシュを消して再構築」だけで済むが、
**同時に上記のカットオフ無しリークも濃くなる**（フル履歴＝評価窓を全部含む）ので、
カットオフを入れてから再構築するのが正しい順序。

## 🔑 手法として残すこと

**CSV を作り直す前に、`data/` に何が置かれているかを確認する。**
`init_engine()` はキャッシュが無ければ黙って再構築し、json が無ければ黙って
デフォルト値に落ちる。どちらも例外を出さないので、**141列・164,328行という
「正しい形」の CSV ができあがったまま中身が違う**。

今回それに気づけたのは、別セッションが同じ `mf1/fit.py` で測って
**`market_auc` が4桁一致・AUCだけズレた**ため。
🔑 **同じ母集団で市場ベースラインを併記していたことが、切り分けを可能にした。**
関門4（市場基準線の併記）は合否判定のためだけでなく、**計測器の同一性の検算**として働いた。
