# M-1: 市場フリーモデルのハイパーパラメータ最適化（事前登録）

作成日: 2026-09-08。**結果を見る前に確定。**

## なぜやるか

市場フリーモデルは `max_depth=6 / lr=0.05 / min_child_weight=10 / subsample=0.8 /
colsample=0.8 / reg_alpha=0.1 / reg_lambda=1.0 / n_estimators=500` で動いているが、
これは**残差学習モデル（base_margin が土台を担い、木10本で飽和する別物）から
そのまま引き継いだ値**で、市場フリーの体制では**一度も振っていない**。

2026-09-08 に「木を 500→1500→4000 と増やすと AUC が 0.7889→0.7816→0.7757 と
**単調に悪化**する」と実測した＝**容量不足ではなく過学習側に居る**。
正則化を強める方向に伸びしろがある可能性が高い。

これは「特徴量を磨く」筋（R1・P-1 で独立に2回失敗）とは別クラスなので、
North Star #12 の打ち切り条件には該当しない。

## 🔴 前回のハーネスにあった設計上の欠陥を先に直す

前セッションの `pl/stage2.py` は **early stopping の eval_set に外側の検証窓を
そのまま渡していた**。A/B比較（θ差し替え）では両アームに同じ下駄が乗るので
結論は歪まなかったが、**ハイパーパラメータ探索では致命的**（検証窓に最も
都合の良い木の本数が選ばれる＝検証窓へのリーク）。

M-1 では **early stopping を学習データ内の内側ホールドアウト**
（学習期間の末尾42日）で行い、外側の窓は評価にしか使わない。

⚠ この変更で**基準線の数字自体が動く**ので、現行既定の配置も同じ新ハーネスで
測り直し、そちらを比較の起点にする。旧ハーネスの 0.7889 とは直接比較しない。

## 窓を「探索」と「確認」に分ける

3窓しかない状態で探索も確認も同じ窓でやると、選んだ配置が窓に過適合する。

| | 窓 | 用途 |
|---|---|---|
| **探索期** | T1 2025-03-01〜04-30 / T2 2025-06-01〜07-31 / T3 2025-10-01〜11-30 | **ここだけ見て配置を選ぶ** |
| **確認期** | W1 2026-07-04〜09-06 / W2 2026-05-02〜06-28 / W3 2026-03-01〜04-26 | 選んだ後に一度だけ見る |

確認期は前セッションで基準線（市場だけ 0.8101 / 市場フリー 0.7889）を測った窓と
同一。**探索中は一度も触らない。**

## 記録する指標（ユーザー指定）

木数の実験で「**LogLoss が改善しながら AUC が悪化する**」ことが実証されたので、
単一指標で選ばない。全配置について以下を必ず残す。

| 指標 | 意味 |
|---|---|
| **3着内 AUC** | 主指標（学習目標と同じ） |
| **1着 AUC** | 同じ確率で1着を当てられるか（券種が変わると効く） |
| **LogLoss** | 確率としての当てはまり |
| **Brier** | 同上（二乗誤差） |
| **ECE（較正誤差）** | 予測確率と実測の乖離。**内側ホールドアウトで Isotonic を当てた後**の値。本番も較正層を通すため |
| best_iteration | 実際に使われた木の本数 |

**選抜は 3着内AUC で行う**（事前に宣言）。他の4指標は「選んだ配置が他の軸で
壊れていないか」を確認するために使う。後から指標を選び直さない。

## 探索空間

`n_estimators=4000` 固定・early stopping（内側・50ラウンド）で本数は自動決定。

| パラメータ | 候補 | 現行 |
|---|---|---|
| max_depth | 3 / 4 / 5 / 6 / 8 | 6 |
| learning_rate | 0.02 / 0.05 / 0.10 | 0.05 |
| min_child_weight | 10 / 30 / 100 / 300 | 10 |
| subsample | 0.6 / 0.8 / 1.0 | 0.8 |
| colsample_bytree | 0.4 / 0.6 / 0.8 | 0.8 |
| reg_lambda | 1 / 5 / 20 | 1.0 |
| reg_alpha | 0 / 0.1 / 1.0 | 0.1 |
| scale_pos_weight | 1.0 / 事前確率ベース | 事前確率ベース |
| early stopping の指標 | logloss / auc | logloss |

全組合せは 8,640通りで回らないので**ランダム探索120配置**（seed固定・再現可能）。
**現行既定は必ず含める**（比較の起点）。

⚠ `eval_metric='auc'` は MF-1b で「本番の残差モデルと条件がズレる」として
問題視したが、あれは**本番同型を再現する場面**の話。ここは開発モデルを
意図的に最適化する場面なので、探索の軸として正当。

## 関門（結果を見る前に置く）

1. **現行既定を新ハーネスで測り直し、旧ハーネスとの差を明示する**
   （数字が動くのは想定内。動かなければハーネス変更が効いていない＝疑う）
2. **探索期の順位と確認期の順位の相関**を出す。0付近なら「探索が何も選べていない」
3. **同じ配置を3シードで回し、シードstdを出す**。改善幅がシードstd以下なら意味がない
4. **市場だけの基準線を同じ窓・同じ母集団で必ず併記する**（差が縮んだかを見るため）

## 判定（打ち切り基準は置かない）

North Star #12 と、2026-09-08 のユーザー方針
（**「0.80 を絶対条件にしない。0.789 の AI がどのレースで市場以上の仕事をするかを
調べる方が利益への距離が近い」**）に従い、**M-1 に合否ゲートは設けない**。

- 探索期で最良の配置を選び、確認期で全指標を記録する
- 確認期で現行既定を上回れば開発モデルの既定として採用する
  （取り込み基準: 3窓中2窓でプラス かつ 平均が負でない）
- 上回らなければ現行既定のまま。**どちらの場合も次は「レース選別」へ進む**

⚠ **本番モデルは差し替えない。** これは開発モデルの設定であり、
本番投入には従来どおりの採用基準（対照群・3本抜き・CI下限）を別途通す。

## 事前の見立て（外れても隠さず記録する）

- 木を増やすと悪化した以上、**max_depth を下げる方向 / min_child_weight を上げる
  方向**が効くと予想する
- **early stopping を内側に移すだけで確認期の AUC は下がる**（外側に合わせて
  止めていた下駄が外れるため）。0.7889 → 0.78 前後に落ちると予想する
- 改善幅は **+0.003〜+0.008** 程度と予想する。市場との差 0.0212 は埋まらない
