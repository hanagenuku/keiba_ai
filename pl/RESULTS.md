## 🔴 途中で私が計測器を壊した（1件・修正済み）

`pl/build_theta.py` の SQL を `ORDER BY date, race_id, place` と書いた。
本番 `build_from_history` からコピーしたためだが、**そちらは更新にしか使わないのに対し、
私の実装は同じ行順で特徴量（θ順位）も作っていた**。θ が同値の馬（13.8%）で
安定ソートが入力順を保つので、**順位がそのまま着順順に並んだ**。

これは **2026-08-08 に「AUC +0.037 / 回収率115%」と誤報告した事故と完全に同型**。
当時 CLAUDE.md に「同じ特徴量を別実装で作って値を突合せよ」と書いたが、
今回は**その突合を、同じ行順を渡した参照実装との間で行ったので通過してしまった**。

発覚したのは **単勝回収率が 162.8% と出た**ため（North Star #8: 異常に良い数字を疑う）。

| | corr(θ同値行の順位, 着順) |
|---|---|
| 壊れていた版 | — （2026-08-08 の同型事故では +0.8678） |
| **修正後（今回）** | **+0.1717** |
| 本番パイプライン（2026-08-08 実測） | +0.1694 |

修正後は本番の健全値と一致する。**関門5「θ同値行で順位が着順を漏らしていないこと」を
今後の標準にする。**

### 汚染の範囲（正直に）

- **主指標（z のAUC）は無事**。AUC は連続値 z で測っており、同値はタイとして
  中間順位で処理されるため、順位の並べ方が入らない。修正前後で数字が完全に一致した
- **θ 自体も無事**。更新は `sorted([(place, name)…])` で行うので行順に依存しない
- 🔴 **汚染されたのは「順位AUC」と「回収率」の2つだけ**。両方測り直した

# P-1 第2段：θの改善はモデルに届くか

`pl/work/data/hf.csv`（164,328行 × 141列）を history.db から再生成し、
**θ5列だけを差し替えて**他の128列は完全に同一にした上で比較。
モデルは**市場フリー**（`f_popularity` / `f_pop_last` / `f_pop_avg` /
`f_beat_market_rate` を除外・base_margin なし）、本番と同じハイパーパラメータ、
3窓 × 3シード。

**検算**: 既定θで差し替えたCSVが元のCSVと**最大差 1.2e-15**（全5列）で一致することを
assert で固定してから測定した。

## 🔴 その検算が2度目の欠陥を見つけた（同着の並べ替え）

最初この検算が **最大差 4.00** で落ちた。原因は θ更新に渡す着順リストを
`sorted([(着順, 馬名)])` と書いたこと。本番は `key=lambda x: x[0]`（着順のみ）で、
安定ソートにより**馬番順**が保たれる。**同着が294組**あり、そこで並びが変わると
θがズレ、それが対戦相手の勾配を通じて**全体の34%（55,367行）に伝播**していた。

第1段のグリッドもこの状態で測っていたので、**1,044配置すべて測り直した**。
結論（最良配置・順位相関 r=+0.994）は変わらなかった。

## 結果：θの質は上がるが、モデルの上乗せは増えない

| 候補 | 3窓平均の差 | プラス窓 |
|---|---|---|
| #1 LR0.80 / DAMP0.30 / SHR0.15 / DEC550 | **−0.0003** | 2/3 |
| #2 LR1.20 / DAMP0.45 / SHR0.12 / DEC550 | **+0.0001** | 2/3 |
| #3 LR1.10 / DAMP0.50 / SHR0.15 / DEC550 | −0.0001 | 1/3 |

取り込み基準（3窓中2窓プラス かつ 平均が負でない）を満たすのは **#2 だけ**。
しかし **+0.0001 はシード揺らぎ（std ≈ 0.0015）の 1/15** で、実質ゼロ。

### 決定的：θ列を丸ごと抜いた腕を足すと、機序がはっきりした

| 腕 | 市場フリーAUC への寄与（9回平均） | プラス |
|---|---|---|
| **θ列あり（既定θ）− θ列なし** | **+0.0016** | **9/9** |
| **θ列あり（調整後θ）− θ列なし** | **+0.0016** | **9/9** |

🔑 **PLレーティングは確かに効いている（+0.0016・9/9で一貫）。
しかし θ の質を +0.0074 AUC ぶん上げても、寄与は 1ミリも変わらない。**

モデルは θ を「粗い強さの目安」としてしか使っておらず、
θ の中の細かい順序は、他の129特徴量が既に持っている。

### これは2回目の同じ結果

| | 何を良くしたか | 特徴量としての改善 | モデルAUC |
|---|---|---|---|
| R1（2026-08-28） | `f_recent` の順序反転バグ修正 | 重要度 6.94% → **15.05%** | **−0.0000** |

**「馬の強さを測る道具を磨く」という筋は、独立に2回失敗した。**
運用ルールの「独立に2回失敗したら閉じる」に該当するので、
**P-2〜P-5（反復フィッティング・θの芝ダ分割・距離分割・スピード指数の回帰化）は
すべて同じ筋なので優先度を下げる。**順番に実行しない。

# 副産物：モデルの容量は上限ではなかった（むしろ多すぎると悪化）

`best_iteration` が 492〜499 と `n_estimators=500` に張り付いていたので、
「木が足りないのでは」と考えて増やした。**逆だった。**

| 窓 | **市場だけ**（人気順） | 木500 | 木1500 | 木4000 |
|---|---|---|---|---|
| W1 2026-07〜09 | 0.7965 | **0.7758** (木498) | 0.7697 (木1496) | 0.7637 (木2953) |
| W2 2026-05〜06 | 0.8124 | **0.7908** (木499) | 0.7842 (木1498) | 0.7785 (木3162) |
| W3 2026-03〜04 | 0.8214 | **0.8002** (木498) | 0.7908 (木1493) | 0.7850 (木2747) |
| 平均 | **0.8101** | **0.7889** | 0.7816 | 0.7757 |

**木を増やすほど AUC が下がる。** early stopping は val の logloss で止めているので、
logloss は改善し続けながら**順位付けの質は落ちている**。
`n_estimators=500` は制約ではなく**偶然の正則化**として働いていた。

## 🔑 正しい基準線が確定した

これまで「市場単独 = 0.8001」を目標に置いていたが、それは**別の窓の値**だった。
**この3窓で測った市場単独は 0.8101**、市場フリーモデルは **0.7889**。

**差は −0.0212。** 私が前に言った「−0.014」より大きい。

# 次にやること（P-2〜P-5 は保留。代わりにこれ）

**M-1: 市場フリーモデルのハイパーパラメータを初めて振る。**

理由は θ と同じ形をしている。市場フリーモデルは
`n_estimators=500 / max_depth=6 / lr=0.05 / min_child_weight=10 / subsample=0.8`
で動いているが、これは**残差学習モデル（木10本で飽和する別物）から
そのまま引き継いだ値**で、**この体制で一度も振っていない**。

しかも今回「木を増やすと悪化する」＝**過学習側に居る**ことが分かった。
depth を下げる・正則化を強める・lr を下げる方向に伸びしろがある可能性が高い。

⚠ これは「特徴量を磨く」筋とは別のクラスなので、
「独立に2回失敗した」対象には該当しない。
