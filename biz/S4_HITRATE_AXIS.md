## 1. 前提として確定している事実（AI研究側の実測）

出典は `hitrate/RESULTS_A.md` / `hitrate/RESULTS_C.md`。**ここでは議論せず引くだけ。**

1. **◎は市場1番人気と同じ馬**（本番15開催日で96〜100%一致・4番人気以下は全日0本）
2. **1番人気を上回る馬は、事前に確率で名指しできる。**
   「上回る確率 >= 0.60」と宣言した群の **64.1%** が実際に上回った（完全OOS・2025年3,442レース）
3. その馬に差し替えると **複勝率は 31.56% → 56.91%（+25.35pt）**
4. 🔴 **複勝回収率は 80.40% → 79.93%（−0.47pt）＝ 1ptも上がらない**
5. 🔴 **回収率100%超は一度も確認できていない**（単勝で出た 101.46% は N=134 の
   事前登録外の数字で、`hitrate/CRITERIA_D.md` で測り直し中。**根拠にしない**）

## 2. 商品の軸として「的中率」は使えるか

### 使える形

- 「**当てやすい馬／当てやすいレースを見分ける**」は、2 と 3 で**測れている**主張である。
- すでに商品に載っている `conf`（軸の3着内確率）も同じ軸で、
  市場より良いと測れている唯一の指標（AUC 0.6041 vs 市場 0.5708）。
- つまり**軸を増やすのではなく、既にある軸（当てやすさ）を濃くする**話になる。

### 使えない形（書かない）

- 🔴 「的中率が高い → 儲かる」。**4 が反例**。的中率と回収率は別物（North Star #9）。
- 🔴 「的中率◯%」を**単体で**大きく出す。複勝の的中率は買い方次第で上下するので、
  条件（券種・点数・母集団）を書かずに数字だけ出すと誤解を招く（景表法のリスク）。
- 🔴 「AIだから当たる」。1 のとおり◎は市場1番人気なので、**◎の的中率は市場の的中率**である。

### 判断（ユーザーに渡す形）

**的中率を「商品の中心」には置かない。「読む価値の1つ」として置く。**
中心に置くと 4 を隠すことになり、`biz/README.md` の「やらないこと3」に触れる。
代わりに、§3 の ☆ マークのように **「何が分かるか」を具体物として見せる**形にする。

## 3. ☆マークの設計（◎は動かさない）

### 何を表すか

> **☆ = 「市場1番人気を着順で上回る可能性が比較的高いとAIが見ている馬」**

- 対象は **1番人気以外の馬**。1レースに最大1頭。該当なしのレースが大半（τ=0.60 で約4%）。
- 根拠は `hitrate/` の C-2 モデル（「1番人気を上回るか」を直接学習して較正した確率）。
- **◎○▲△ は1つも動かさない。** ☆は独立した追加マーク。

### なぜ ◎ を動かさないのか（商品側の理由）

1. `conf`（商品に載せている信頼度）は **`rl_rank` 1位を軸としたときの値**。
   ◎を移すと `conf` が何の数字でもなくなる。
2. 回収率が改善しないので（§1-4）、「◎を替えたら成績が良くなる」とは書けない。
3. ☆なら主張が実測と一致する。「上回る可能性が比較的高い」は**着順比較の話**で、
   較正が効いていることは測れている。

### 必ず併記する文（省略不可）

> ☆は**着順で1番人気を上回る可能性**についての表示です。
> 過去データでは、この表示が出た馬は1番人気より3着内に入りやすい傾向がありました。
> 一方で**回収率は改善していません**（配当が小さくなるため）。買い目の根拠ではありません。

### 書いてはいけない文

- 「☆は妙味」「☆は狙い目」「☆で勝てる」「☆の回収率は◯%」
- ☆を**買い目の軸・ヒモに自動で入れる**（買い目は `axis_bets.py` のまま。触らない）
- ☆の的中率を ◎ の `conf` と**並べて1つの表にする**（別の意味の数字なので混ざる）

### 出す条件 → ✅ **2026-11-10 に合格した**

`hitrate/CRITERIA_C_RERUN.md` §4 の5基準すべてに合格（全文 `hitrate/RESULTS_C_RERUN.md`）。
中止条件は発火なし。対照群 B-1/B-2/B-3 は**3つとも厳密に復元**
（ROI +5.0000pt / AUC 1.000000 / オラクル 0.71197 = 0.71197）。
対照群A も合格（帰無が0中心・実測は帰無の10倍以上外）。
**τ=0.55 と τ=0.60 の2つが合格**した。

🔴 **ただし実装は保留。** 同日の `hitrate/RESULTS_D.md` §2 で、**同じ τ での ☆ の出現頻度が
2025年 3.6% → 2026年 18.7%（約5倍）**になることが分かった。差し替え馬の複勝率は
2026年でも 56.64%（2025年 56.91%）で**主張側は壊れていない**が、
「1開催日に1本前後」の想定が「5レースに1本」になるので商品としての意味が変わる。
さらに **2026年での較正と P1 との複勝率差はまだ測っていない**。
→ `RESULTS_D.md` §4 の3項目を別カードで測ってから実装する。

## 4. 無料／有料の振り分けへの影響

**変えない。** `src/product/scope.py::article_kind()`（有料＝`conf >= 66`）は触らない。
☆は記事の中身が増えるだけで、振り分けの判定には入れない。
（範囲や定義を変えたら読む側を全部 grep して揃える、というルールを守るコストを払わない）

## 5. 次にユーザーが決めること

### (1) 🔴 τ をどちらにするか（最重要。文言が変わる）

2つとも事前登録の5基準に合格しているので、どちらを選んでも「後出しの閾値変更」ではない。
**どれだけ ☆ を出すか／どれだけ強く言えるか**のトレードオフである。

| | τ=0.55 | **τ=0.60（推奨）** |
|---|---|---|
| ☆が出るレース | 303 / 3,442 = **8.79%**（1開催日あたり 2〜3本） | 134 / 3,442 = **3.91%**（1開催日あたり 1本前後） |
| 言える確率（完全OOS実測） | 58.8% | **64.1%** |
| 1番人気との複勝率差 | +13.74pt | **+25.35pt** |
| 窓ごとの最小 | +6.75pt | **+20.44pt** |
| 使える文言 | 「やや上回りやすい」 | 「**上回る可能性が比較的高い**」 |

**推奨は τ=0.60。** 58.8% は「ほぼ五分」なので「比較的高い」と書くと誇張になる。
頻度を増やしたい（毎レース近くに ☆ を出したい）なら τ=0.55 にして、
**文言を「やや上回りやすい」に弱める**こと。

### (2) その他

1. ☆のマーク文字（☆ / ★ / 別の記号）と表示名
2. ☆を**無料記事にも出すか**、有料だけにするか
3. 台帳が何開催日分溜まったら「☆の成績」を公開するか（提案: 最低15開催日）

## 6. 実装の前に必ずやること（North Star #3）

本番でこのモデルを動かすなら、**学習時と推論時で経路が同一**であることを
テストで固定してから入れる:

- `P1`（人気1位）の決め方が学習時（ドリフト後の確定人気）と推論時（朝オッズの人気）で同じ形か
- 差分 `Δx = x_X − x_P1` の特徴量の**順序**が学習時の列順と一致するか
- 較正器（Isotonic）を本番モデル差し替え時に作り直す手順が残っているか

崩れると片方だけ静かにデフォルト値になる（North Star #3）。
