## 1. 🔴 着手前に確定させる矛盾2件（ユーザーの §5〜§8 に関わる）

戦略文書の §5（パターンA〜E）と §6〜§8（能力×適性 → 馬券選択モデル）は、
**このプロジェクトが一度測って閉じた研究と同じ形**をしている。
§8 で「回収率100%超を前提条件にしない」と明示されている点は正しいので、
**記述的な問い（着順分布・人気・オッズにどんな違いが出るか）の答えは既に出ている**。
これを知らずに再登録すると、同じ測定を2回することになる。

### 矛盾① 能力×適性 → 馬券 は Betting Policy Step 1 で、ユーザー自身が閉じている

`CLAUDE.md` の記録（2026-09-22）:

```
主効果          A1(2023) +8.88pt / A2(2024) +9.68pt   ← 大きく見えた
能力のみ統制     +8.88 / +9.68
市場のみ統制     +3.03 / +4.31
能力 × 市場統制  +1.68 / +3.20pt                      ← 効果の67〜81%が市場評価の言い換え

回収率  9セル × 2期間 × 2券種 ＝ 36マスすべて 100% 未満
       最良は複勝 A1 80.3% / A2 81.9%（複勝プール平均80%と同水準）
```

> 🔴 **ユーザーが (A) を選択し Step 1 で閉じた**（2026-09-22）。
> **同じ T を定義・期間・推定仕様を変えて測り直さない**（P3-01 と同じ扱い）。
> **Step 2・Step 3 には進まない。**

- §5 の **パターンC（能力5位×適性1位→妙味候補）** と
  **パターンD（乖離が大きければ注目）** は、この「能力×適性で馬券を選ぶ」そのもの。
- 特に **パターンD は「AIが市場より高く見ている馬を買う」方向**で、
  これは **3回測って3回否定**されている（2026-07-30 / 08-03 / 08-31）。
  直近の実測は `corr(gap, 符号つき誤差) = -0.1213`
  ＝**市場と食い違うほど、その食い違いの方向にAIが間違っている**。
- ✅ ただし **B期間（2025-01〜・5,932レース）は一度も読んでいない**ので、
  「別の問い」のためには丸ごと残っている。

🔑 **だから §8 の順序①（記述的に違いを見る）は、答えがもう手元にある。**
新しく測るのではなく **Step 1 の結果を読む**のが正しい（全文 `betting/RESULTS_STEP1.md`）。
そして §8 の順序②③（馬券に利用できるか／どの券種が合理的か）は、
**①の答えが「回収率は36マス全部100%未満」なので、そこから先に進む根拠が無い**。

### 矛盾② 券種選択モデル（§6〜§7）は、データ側で構造的に塞がれている

`bet_strategy_lab/README.md` の記録:

```
組み合わせ券種の実配当 race_dividends
  → 2026-06-06 以降・約1,000レース / 30開催日しか無い
  → JRAの結果一覧が遡れないため増えない（毎週2日ぶんずつ増えるのみ）
単勝・複勝の配当
  → history.db の tansho_payout / fukusho_payout が 2023-01 から揃っている
```

つまり **ワイド・馬連・三連複で「どの券種が合理的か」を過去データで検証することは、
いま構造的にできない**（A期間に1行も無いので out-of-sample の形が組めない）。
§7 の「過去データで検証」が成立するのは**単勝・複勝の2券種だけ**。

⚠ これは「券種選択に意味が無い」ではない。**測る材料が無い**である。
毎週2日ぶん増えるので、待てば可能になる（N=2,000 まで約7ヶ月）。

🔑 皮肉なことに、**§10 で決めた「券種は2種類以内」「複勝＋ワイド」という結論は、
データの制約と偶然ほぼ一致している**（`src/product/tickets.py` は既に複勝＋ワイドのみ）。

## 2. STEP 1: 競合調査（8軸）

ユーザーが挙げた8軸で、note 側5名（`S2_ACQUISITION.md` §1 の続き）と X 側の実態をまとめる。

| 軸 | 実態 |
|---|---|
| **フォロワー規模** | note 上位5名の X フォロワーは **5.5万〜12万**。X 単独の予想家ランキング上位も同オーダー。**フォロワーを作り終えてから有料に移している**（上位5人中4人が無料予想なし） |
| **投稿内容** | X では「当日の無料予想」「レース情報」「**有料予想の的中実績のスクショ**」の3種が繰り返される。1アカウントが X／note／月額サロン／Instagram／LINEオープンチャットに同時展開する例もある（軸馬くん: X=考察付き予想を毎日無料 / note=勝負レース / 月額サロン=中央の予想が見放題 / Instagram=重賞動画 / LINE=限定予想を毎日無料） |
| **無料→有料への導線** | 「X で無料予想を出して拡散 → フォロワーを積む → note の有料予想に送る」が定型。⚠ まとめ記事側は**「全レース有料に誘導するアカウントが多い」ことを警告として書いている**＝この導線は飽和して嫌われ始めている |
| **有料価格** | note は **100円〜10,000円**まで自由設定。実勢は **400〜980円/1R**（上位5名）。解説記事の推奨は**最初は300〜500円** |
| **的中実績の見せ方** | **スクリーンショット**が事実上の標準。信頼度が高いとされる予想家は「スクショ付きで買い目を残す」「X で**事前に**公開する」。🔴 逆に、**外れた予想の削除・的中画像の捏造・フォロワーに代わりに投稿させる**といった手口が名指しで指摘されている |
| **買い目の出し方** | ◎○▲△ の印＋券種＋買い目点数。組み合わせ券種（三連複のフォーメーション等）が中心。**「危険な人気馬」は記事内の1セクションとして普通に書かれている**（§4） |
| **差別化方法** | 実質**回収率の数字のみ**。第三者ランキングが 132%〜179% という掲載回収率で並べており、棚の並び順がそれで決まっている |
| **更新頻度** | **基本毎日**（上位5名すべて）。週末のみの例は上位に見つからなかった |

🔑 **8軸のうち7軸は「もっと多く・もっと頻繁に・もっと高い数字」で競う軸**で、
こちらが勝てるものが1つも無い（フォロワー0・週2日・回収率100%未満）。
唯一こちらに材料がある軸は**「的中実績の見せ方」**＝**削除も捏造もしない**ほう。

## 3. STEP 1 の副産物: 棚の並び順を決めているのは第三者ランキングサイト

検索で出てくる note 予想家の一覧は、**本人の note ではなく

   この構造を回避する形になっている（棚に並ばずに購入率を測れる）。

## 5. STEP 2: 真正面から競争しない差別化案（5案）

前提として**使える材料**を確定させる。すべて実測済み・実装済み。

| 材料 | 実測 | 状態 |
|---|---|---|
| **レース信頼度 `conf`**（軸の3着内確率） | 当てやすさ予測 **AUC 0.6041** vs 市場のみ 0.5708（**N=3,560レース**）。市場の自信度で4分割したどの層でも効く | 本番で稼働・画面表示済み |
| **危険な人気馬**（市場1番人気 × 素のAI6位以下） | 複勝率 **68.5% → 51.4%**（N=242・walk-forward） | `solo_rank` として実装済み |
| **AI評価の内訳**（15カテゴリSHAP） | 「なぜ市場と違うか」を分解できる。主因は実力レーティング＋スピード能力で差の55% | `ability_breakdown` として出力済み |
| **3列**（AI単・適性・AI+市） | 2026-09-28 に画面へ分離済み | 実装済み |
| **全記録**（`stats.json` / `prediction_archive/`） | 予想数・的中・投資・払戻・回収率が毎週自動で溜まる | 実装済み（追記保存1点のみ未実装） |

🔴 **この5案は排他ではない。** 組み合わせられる。ここでは軸ごとに分けて評価するために並べる。

### D-1 「買うレースを選ぶ」を商品にする（印ではなくレース表を売る）

商品は◎○▲ではなく「今週、対象にするレースと、見送るレース」。
根拠は `conf`（AUC 0.6041 > 市場 0.5708）で、**これが市場を上回っている唯一の量**。

- 🔑 競合の8軸のどこにも無い商品形（全員が「どの馬を買うか」を売っている）
- 🔴 ただし `conf` 最上位帯でも**複勝回収91.2%**で100%に届かない。
  「見送れば勝てる」ではなく「見送れば損が減る」までしか言えない
- 🔴 §5 の (a)/(b) が未解決＝**「買うな」に金を払う人がいるか分からない**

### D-2 「なぜ市場と違うのか」を内訳で見せる（SHAP 15カテゴリ）

「AIは◎、市場は8番人気。理由は実力レーティング −0.19、スピード能力 −0.14」という
**分解を記事に出す**。他の予想家は内訳を持っていないので構造的に真似できない。

- 🔑 追加開発ほぼゼロ（`ability_breakdown` は既に出ている）
- 🔑 読み物としての情報量が単純に多い（§9「読み物として売る」に最も合う）
- 🔴 **2026-08-27 に「内訳から信頼度は読めない」と測ってある（−0.0038・3窓26,340頭）。**
  つまり**説明の解像度が上がっても当たるようにはならない**
- 🔴 リスクは誤読。読者が「説明が細かい＝当たる」と受け取れば、
  それは**書いていない誇張**になる。§20 の「誇張しない」に触れる可能性がある

### D-3 「能力・適性・市場を分けて見せる」（ユーザーの §4・§18案2そのもの）

`AI単`（市場ゼロ）／`適性`／`AI+市` の3列をそのまま商品の語彙にする。

- 🔑 実装済み（2026-09-28）。説明が明確で、初見の読者にも1行で伝わる
- 🔑 Phase 2 の8ブロックが**説明用の語彙として残すと決めた**ものと整合
- 🔴 **「適性」で馬券の優位は測って否定されている**（§1 矛盾①）。
  Gate 0（能力と独立か）は通ったが、Step 1（結果に効くか）で閉じた。
  **「分けて見せる」は説明として成立するが「だから当たる」は書けない**
- 🔴 §4 の「強い馬と今回条件に向く馬は違う」は正しいが、
  `f_course_fukusho` 等は 2026-09-18 に「適性ではなく**条件付き能力**」と判明している。
  記事で「適性」と呼ぶ列の定義を間違えないこと

### D-4 「答え合わせを全部出す」を差別化の中心に置く（§14 の全記録公開）

予想数・的中数・投資額・払戻・回収率を全件・毎週・削除なしで出す。
外れたレースも残す。良い数字を切り取らない。

- 🔑 **競合の弱点を正面から突く**。削除・捏造は第三者のまとめ記事が
  実際に警告として書いている項目で、そこが空いている
- 🔑 **過去は後から作れないので真似されにくい**（積み上げ型の参入障壁）
- 🔑 実装コストが最も低い（`stats.json` が既に自動で溜まる。
  未実装は「公開スナップショットの追記保存」1点だけ）
- 🔴 **効くまでに数ヶ月かかる**。短期の集客力はほぼゼロ
- 🔴 そして**毎週「回収率100%未満」を自分で示し続けることになる**。
  棚が回収率で並んでいる市場では**逆風**として働く

### D-5 「買い目を出さない」判断材料型にする（§9 から【最終買い目】を外す）

印・内訳・見送り判断・危険な人気馬までを売り、最終的な買い目は読者が決める。

- 🔑 景品表示法・特定商取引法のリスクが最も小さい（「当たる商品」を売らない）
- 🔑 「当たった／外れた」で評価されないので、回収率の棚と**そもそも比較されない**
- 🔴 **ユーザーの §9 は【最終買い目】を入れると決めており、正面から矛盾する**
- 🔴 買い目の無い競馬予想記事に需要があるかは**まったく未確認**。
  §19 STEP 5 が測ろうとしている「商品として需要があるか」の答えを最も外しやすい

### 軸ごとの見方（数字の裏付けがある部分だけ）

- **開発コスト**: 5案すべて**新規の大規模開発を必要としない**。
  `biz/README.md` の「販売システムを先に大規模開発しない」に全案が適合する。
  未実装は D-4 の追記保存1点のみ（§8 の小さな差分2件は 2026-09-29 に実施）。
- **集客力**: 🔴 **5案すべて弱い。** 理由は案の中身ではなく構造で、
  棚が回収率で並んでいて（§3）こちらは100%超を出せない。
  集客は差別化案の選択では解決しない（`S2_ACQUISITION.md` §8 の P1
  「既存の接点10人に直接渡す」が、集客ゼロで購入率を測る唯一の形）。
- **継続性**: ユーザーは**時間を割けないと明言している**（2026-09-15）。
  競合が**基本毎日**更新する中で、週2日・対象10レース（`src/product/scope.py`）は
  最初から別の軸で戦うことになる。D-2 が最も手間が大きい。
- **信頼性**: D-4 だけが**時間に比例して増える**。他は初日から一定。
  逆に D-3 は「適性」の扱いを誤ると**測って否定された主張を書く**ことになる。
- **収益化可能性**: 🔴 **5案すべて未確認。** 購入率を一度も測っていないので、
  この列は実測ではなく構造からの推測でしかない。
  note の手数料は 1,000円 → **手取り585円**（`S2_ACQUISITION.md` §4）。
