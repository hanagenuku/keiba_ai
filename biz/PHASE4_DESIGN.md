# Phase 4 設計：AI分析を「予想＋印＋買い目」に変換して販売する

> 🔴 **この文書は商品研究（`biz/`）に属する。** AI研究（AUC・回収率）と同じ文書で論じない。
> 🔴 **予想ロジックは変更しない。** Phase 3 までのAIをそのまま使い、出力を読んで整形するだけ。

---

## 0. 実装する前に確定させた3つの矛盾（重要）

ユーザーが示した商品フォーマット（§2・§25 の実例）には、**このシステムが持っていない情報**が
含まれていた。そのまま実装すると §12「存在しない陣営コメントを作らない」に自分で違反する
コードを作ることになるので、先に切り分けた。

### ① 陣営コメント・調教は書けない（データが存在しない）

示された実例の以下の文は、**こちらの情報源には存在しない**。

| 実例の文 | 状態 |
|---|---|
| 「陣営によればこの距離は少し忙しいとのこと」 | 🔴 **陣営コメントは取得経路が無い**。JRA公式に無く（2026-08-16 に4回検証して打ち切り）、netkeiba の該当欄は有料 |
| 「この中間も引き続き好調をキープしているとのこと」 | 🔴 同上 |
| 調教タイム | 🔴 JRA公式に機械可読な値が存在しない。jugem は 1頭/開催日で 2026-09-25 に閉じた |
| パドックの気配 | 🟡 ユーザーの手入力が 987行あるが**予想に繋いでいない**（効果は一度も測っていない） |

→ **見解は「こちらが実際に持っている事実」だけで書く。** 持っていない項目は
**書かない**（推測で埋めない）。文章が短くなることを受け入れる。
Web で取得した情報を使う場合のみ「○○によると」と出典を付ける（§12 のルールどおり）。

### ② 地方競馬（船橋・川崎など）は対象外

実例は **船橋9R**（地方競馬・NAR）だが、このシステムは **JRA専用**。
`history.db` も JRA のみ、スクレイパーも JRA の JRADB のみ。
→ **商品の対象は JRA のみ**。実例は他の予想家のフォーマットを借りたものとして扱い、
形式だけを採用する。

### ③ §6 パターンC（穴候補）は測定で逆が出ている

§6 のパターンのうち1つは、**このプロジェクトが3回測って否定した方向**そのもの。

| §6 のパターン | 測定結果 |
|---|---|
| **パターンC** 能力5位 × 適性1位 × **市場低評価 → 穴候補** | 🔴 **逆**。`EV = AI確率×オッズ` で選ぶと回収 **57.9%**（買わない側75.0%）／AIが市場より強気+3以上は複勝率 **12.7%**・回収 **53.0%**／`corr(gap, 符号つき誤差) = −0.1213`＝**市場と食い違うほどその方向にAIが間違っている**（2026-07-30 / 08-03 / 08-31 の3回） |
| パターンD 能力1位×適性1位×市場1番人気 → オッズ次第で見送り | ✅ 方向は測定と整合（1番人気の複勝回収85.6%は最良だが100%未満） |

→ **「AIが市場より高く見ている馬を穴として推す」形は商品に入れない。**
代わりに**逆向き**（市場が高く見ている馬をAIが低く見ている＝疑う側）を使う。
こちらは測定で機能している（市場1番人気のうち素のAIが6位以下 → 複勝率 **68.5%→51.4%**）。

🔑 **つまり印は「買う方向」に使い、乖離は「疑う方向」にだけ使う。**
これは §10「買わない」も予想として販売する、と同じ方向を向いている。

## 1. 印の決め方（固定ルール・後から変えない）

```
◎ = rl_rank 1     （＝アプリの軸。conf が測られている対象そのもの）
○ = rl_rank 2
▲ = rl_rank 3
△ = rl_rank 4, 5
```

**◎を rl_rank1 から動かさない理由**：唯一「市場を上回っている」と測れているのは
`conf`（軸の3着内確率。当てやすさ AUC **0.6041** vs 市場 0.5708・3,560レース）で、
これは **rl_rank1 を軸としたときの値**。◎を別の馬に動かすと、
商品に載せる信頼度の根拠が消える。

⚠ §4「AI順位1位→◎と文章化するだけでは普通のAI予想と差がない」という指摘は正しい。
差が出るのは**印の付け方ではなく、なぜその順位なのかの説明と、疑う側の指摘**のほう。
印そのものは素直に固定し、説明で差を付ける。

## 2. 「危険な人気馬」セクション（測定済み資産をそのまま商品化）

```
条件: 市場人気 1〜2番 かつ solo_rank（市場ゼロのAI順位）が 6位以下
```
根拠：walk-forward 5窓・N=242・73開催日で、該当する市場1番人気の
複勝率が **68.5% → 51.4%**（−17pt）。
⚠ ただし**「代わりに誰を買えばいいか」は言えない**（素のAIの推しは複勝回収77.5%で、
避けた1番人気75.9%と区別できない）。だから商品でも
**「この人気馬は危ない」までしか書かない。**

## 3. 券種（固定ルール・2券種以内）

| conf | 勝負度 | 券種 | 理由 |
|---|---|---|---|
| 66以上 | ★★★★☆ 以上 | 複勝◎ ＋ ワイド◎-○▲ | rec=True 相当。実データで conf>=66 と rec=True が1件も食い違わない |
| 56〜65 | ★★★☆☆ | 複勝◎ のみ | 相手を広げる根拠が無い帯 |
| 55以下 | ★★☆☆☆ 以下 | **見送り** | 最下位帯は軸の複勝回収が一貫して悪い |

**複勝を基本にする理由**（好みではなく測定）：
2026-08-18③ で高自信レースの券種を総当たりしたとき、**上位3本の配当を抜いても崩れないのは
複勝だけ**（複勝 −1.4pt / ワイド −8.5pt）。ワイドは控除率 22.5% で複勝 20% より不利、
かつ高配当1本依存になりやすい。単勝は RL1 が 86.0% で 1番人気 86.1% と区別がつかない。

🔴 **三連単・三連複・馬連は商品の標準構成に入れない。** 2026-08-03 に総当たりして
馬連70.2% / ワイド71.4% / 三連複は万馬券1本を除くと58.9%。控除率が22.5〜25%で単勝より不利。

🟢 **2026-09-29 にこの理由を記事へ書くようにした**（戦略文書 §11「この予想なら、なぜ
この券種なのか」まで説明する）。`tickets.bet_type_reason()` が、①複勝が本線の理由
②ワイドが押さえの理由 ③勝負度が足りない帯で1点に絞る理由 ④**除外した券種の理由**
⑤🔴「ここに挙げた回収率はいずれも100%を下回っています。券種の選び方で控除率を
超えられるとは考えていません」を返す。⑤は省略できない形にしてテストで固定した（§20）。

## 4. 資金配分（比率で示す・金額は換算例）

```
複勝 70% / ワイド 30%
```
⚠ **傾斜配分で期待値は動かない**（2026-08-18③：総期待値＝各EVの加重平均。
全EV<1ならどう配分しても<1）。配分を示すのは**分散を抑えるため**であって、
「配分で勝てる」とは書かない。

🟢 **2026-09-29 に文面を §10 に合わせた**（戦略文書 §10「資金配分は、オッズと資金に
応じて各自調整 とする」）。比率は「目安」・金額は「換算例（推奨額ではありません）」と明記し、
`tickets.ALLOCATION_NOTE` を記事とアーカイブの両方に載せる。
**券種が1つのレースでは比率表も換算例も出さない**（複勝100%の自明な表は載せない）。
`ALLOC_STRONG` / `AMOUNT_EXAMPLES` の値は変えていない——壊れていたのは値ではなく**文面**だった。

## 5. 見解に書いてよい事実（history.db から機械抽出）

| 書ける | 出どころ |
|---|---|
| 距離延長・短縮（何mから何mへ） | 前走の `distance` |
| コース替わり・遠征 | 前走の `racecourse` |
| 芝⇔ダート替わり | 前走の `surface` |
| 近走成績（n戦連続で3着内 等） | `place` の並び |
| 末脚（上がり順位） | `agari_rank` / `agari3f` |
| 脚質 | `running_style` |
| 道悪実績 | `track_condition` × `place` |
| クラス替わり（昇級・同級） | `class_grade` |
| 人気に対する着順（市場の見立てを超えた） | `popularity` vs `place` |
| 騎手替わり | `jockey` |
| 休養間隔 | `date` の差 |
| 斤量 | `weight_load` |
| 市場順位 / AI順位 / AI単独順位 / 適性順位 | `latest.json` |
| SHAP のカテゴリ内訳 | `ability_breakdown` |

| 書けない | 理由 |
|---|---|
| 陣営コメント | 取得経路なし |
| 調教タイム | 同上 |
| パドック | 予想に繋いでいない |
| 馬体重の増減 | 充足率 **6.5%** しかない。欠損時は書かない |
| 馬場状態の断定（前日夜の生成時） | `going.py` は当日R1終了後しか取れない |

🔴 **リーク防止**：見解に使う履歴は **対象レースの日付より前** のものだけに厳格に絞る。
`history.db` には対象レース自身の結果が入ることがある（結果取得後に生成し直した場合）。

⚠ **新馬戦は書ける事実がほぼ無い**（全馬に過去走が無い）。
2歳未勝利でも1〜2走。conf が高く出るのは未勝利・新馬に偏るので
（2026-08-24 E-1：未勝利・新馬 82.7% vs それ以外 79.2%）、
**「conf が高い＝書ける事実が多い」ではない**。商品化するときに効いてくる制約。

## 6. 予想を後から変更しない仕組み（§18）

```
prediction_archive/YYYY-MM-DD/{race_id}.json
```
- `latest.json` は当日 refresh で**上書きされる**（2026-09-19/22 に実害が出ている）ため、
  公開時点のファイルが別に永続しないと「後から変更していない」ことを示せない
- **同じ race_id が既に保存されていれば上書きしない**（`overwrite=False` が既定）。
  コードで固定し、テストで守る
- 保存するもの：公開時刻・AI順位・AI単独順位・適性順位・市場順位・オッズ・印・
  見解・買い目・推奨配分・レース信頼度・**生成に使った入力のハッシュ**

## 7. 最適買い目研究は本番と混ぜない（§24）

`bet_strategy_lab/` に分離する。
🔴 **結果を見て最もROIが高かった組み合わせをそのまま本番に採用しない。**
事前登録カード → 測定1回 → 結果ファイル の手順を守る（`biz/README.md` と同じ）。
⚠ このプロジェクトは**買い目の絞り込みを大規模OOSで6回否定している**
（人気×RL乖離マトリクス2回 / EVフィルタ3回 / 先行×実力×オッズ / 馬連構成 / 能力×適性）。
ラボを開けるのは新しい問いだけで、上のどれかの言い換えは登録しない。

## 8. この設計で「売り物」になっているもの

| 要素 | 測定状態 |
|---|---|
| 見送り判断（勝負度・conf） | 🟢 **市場を上回っている**（AUC 0.6041 vs 0.5708） |
| 危険な人気馬 | 🟢 **市場を上回っている**（68.5%→51.4%） |
| 印（◎○▲△） | 🟡 市場とほぼ同等（+0.0004）。**差別化要素ではない** |
| 見解（なぜその評価か） | ⚪ 予測力とは無関係。**情報価値**として売る |
| 買い目 | 🟡 複勝 79〜86%。**100%未満であることを明記して売る** |
| 資金配分 | ⚪ 期待値は動かない。分散を抑えるためだけ |

🔴 **商品価値の中心は「印」ではない。**「どのレースを見送るか」「どの人気馬を疑うか」
「なぜAIがそう評価したか」の3つ。ここだけが市場に対して何かを足している。
