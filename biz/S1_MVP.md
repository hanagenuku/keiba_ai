# STEP 4・5 — MVP設計と、無料→有料の導線

前提（→ `S0_MARKET.md`）:
**AI予想と買い目は無料で飽和している。単発1,000円は月額800円に負ける。
差別化できるのは「なぜ」と「買わない判断」だけ。**

---

## 1. 商品の定義（S0の確定事項）

| | |
|---|---|
| **商品名（仮）** | 今日の「買わないレース」とその理由 |
| **コンセプト** | 競馬をデータで考えるためのAI（当たる予想屋ではない） |
| **ターゲット** | 毎週買っていて、**外れた理由が分からないことに不満がある人**。無料AI予想は既に見ている層 |
| **売るもの** | ①AI順位（大量データからの順位付け）②AI解説（なぜその順位か）③市場との比較（市場評価との違い） |
| **売らないもの** | 「勝てる」「回収率」「必ず」。買い目は**付属**（星ではない） |
| **中心の主張** | 「AIが大量の過去データと当日の条件を分析し、人間が見るには面倒な情報を整理して、買い判断をしやすくする」 |

## 2. 表示フォーマット（実データで組んだ実例）

`data/latest.json`（2026-09-27 生成）の**中山6R をそのまま**流し込んだもの。
加工は並べ替えと文章化のみ。数字は全部すでに出力されている。

```
━━━━━━━━━━━━━━━━━━━━━

  ◎の脚質はこの展開に噛み合う。やや拮抗したメンバー構成。

  買うなら #11 より #7 の側に理がある。ただし見送りを推奨する。
```

### 2-1. 最後の一文のルール（ここが商品の核）

🔑 **「この条件ならこう判断する」と言う。「絶対買い！」とは言わない。**
`conf`（軸の3着内確率）で機械的に決め、**手で書き換えない**。

| `conf` | 最後の一文 |
|---|---|
| 70以上 | 「この条件なら◎から入って良い。AIの見立てでは読みやすいレース。」 |
| 60〜69 | 「買うなら◎。ただし強く勝負するほどの確信度ではない。」 |
| 60未満 | 「AIの見立てではこのレースは読みにくい。見送りを推奨する。」 |

根拠: `conf` は「当てやすさ」を市場より正しく当てる唯一の量（AUC 0.6041 vs 市場 0.5708・
3,560レース）。ただし**当てやすさと儲けやすさは別**で、最上位帯でも複勝回収は 91.2% どまり
（2026-08-18②）。だから「高いから買え」ではなく「**低いから見送る**」向きに使う。

### 2-2. 実データでの分布（2026-09-27・23レース）

```
conf 34 … 中山R1        ← 最も読みにくい
conf 51 … 中山R6（上の例）
conf 58〜65 … 8レース
conf 66〜74 … 6レース    ← rec=True（推奨）と完全一致
```
🔑 `rec=True` は `conf>=66` のレースと1件も食い違わない。
**「今日買うのはこの6レースだけ」という判断を、その日のうちに機械的に出せる。**

## 3. 無料／有料の境界

| | 中身 | なぜここで切るか |
|---|---|---|
| **無料** | ①その日の**全レースのAI信頼度一覧**（上の分布そのもの）②**見送り推奨レースの明示** ③**1レースだけフル解説**（上のフォーマット全文）④前週の実績（固定ルール） | 「買わないレースが分かる」だけで単体で価値がある＝損を減らす。かつ**商品の中身を隠さない**（隠すと「情報商材」に見える） |
| **有料（1日パック 500円）** | 推奨レース**全部**の同じフル解説（通常6レース前後） | 「もっと当たる情報」ではなく「**同じものが全部**」。ここを取り違えると虚偽訴求になる |

🔴 **無料と有料の差は「質」ではなく「量」にする。**
「無料は薄い予想、有料は本物の予想」という構成にしない。
同じAIの同じ出力を、1レース分か全レース分かで分ける。これなら
「無料の方が当たらないように作っている」という疑いが原理的に立たない。

### 3-1. 価格

**500円／日から始める。** 理由:
- 1レース500〜1,000円は **月額800円（14日無料）の SPAIA より高く**、成立しない
- 月額は**やらない**（単発の需要が確認できるまで）
- 価格テストは S4 で 500 / 980 / 1,500円。**商品内容と期間は固定**して価格だけ動かす

## 4. 技術開発は1点だけ（🔴 これ以外は作らない）

> 「システムを作ってから売る」ではなく「売れることを確認してからシステムを作る」

**作るもの: 公開スナップショットの追記専用保存。**

```
prediction_archive/2026-09-27/20260927_06_09.json   ← 公開時点の予想をレース単位で
（⚠ 当初 data/published/ と書いたが、実装はレース単位の prediction_archive/。2026-09-30 に訂正）
```

理由: `data/latest.json` は当日 refresh で**上書きされる**（2026-09-19/22 の記録）。
git 履歴には全世代が残るが、**商品として「後から変更していない」ことを読者に見せるには、
公開時点のファイルがそのURLに永続していることが要る**。

これで「予想公開後に内容を変更しない」という**最大の信用材料**が
コミット時刻つきの公開URLとして成立する。⚠ 追記専用。上書き・削除をしない。

**これ以外は作らない。** 記事は手作業でコピペして出す。
Webアプリ・会員ページ・自動配信・通知・決済連携は S7 まで一切着手しない。

## 5. 無料→有料の導線（STEP 5）

```
X（手動投稿・開催日の朝）
  ↓  「今日の23レース、AIが読みにくいと判定したのは7レース。中山1Rは信頼度34。」
無料記事（note 等）
  ・全レースのAI信頼度一覧
  ・見送り推奨レースの明示
  ・1レースだけフル解説
  ・前週の実績（固定ルール）
  ↓  「今日のAI分析では、推奨6レースについて同じ解説を出しています」
有料記事 500円／日
  ↓  （2回目・3回目の購入を記録）
リピーター
  ↓  （リピートが確認できた場合のみ）
月額
```

⚠ **X のスクレイピングはしない。** 手で投稿する（規約上スクレイピングは明確に禁止）。

### 5-1. 有料への一文の書き方

| ❌ 書かない | ✅ 書く |
|---|---|
| 「有料版はもっと当たります」 | 「推奨6レース分の、**同じ解説**があります」 |
| 「回収率○○%の買い目」 | 「AIが評価した理由と、市場との違い」 |
| 「無料版では言えない情報」 | 「無料は1レース、有料は推奨レース全部」 |

### 5-2. 最初の10人をどう取るか（問い⑥）

購入率2%を仮定すると **10件 ≒ 500閲覧**。
1開催日あたりの無料記事閲覧が 30〜60 だとすると **4〜8週**。
🔴 **1週目に売れないことは失敗ではない。** `CRITERIA_SALES_01.md` の失敗条件を先に読む。

## 6. 実績の見せ方（固定ルール・後から選び直さない）

公開する数字を**先に決めて固定する**。良かった期間を選び直したら研究として終わり。

| 出す数字 | 出典 | 2026-09-27 時点の実測 |
|---|---|---|
| AI1位の3着内率 | `stats.json` `rl_accuracy.rl1_top3_rate` | **55.2%**（911レース） |
| AI1位の勝率 | `rl_accuracy.rl1_win_rate` | **31.0%** |
| AI2位・3位の3着内率 | `rl_accuracy.rl2/rl3_top3_rate` | 43.5% / 38.9% |
| AIと市場の比較 | `model_kpi` | AI logloss 0.2374 vs 市場 0.2244 → **市場優位（delta +0.013）** |
| 買い目成績 | 固定ルールで算出 | 複勝回収 **79〜86%**帯 |
| 予想変更なし率 | `prediction_archive/` の存在 | ⚠ **まだ測れない**（実データ0件）。1件目を公開してから |

🔴 **`model_kpi` が「市場優位」と出ていることも一緒に出す。**
隠すと後で見つかったときに商品全体の信用が消える。
出し方: 「**AIは市場全体の予測精度では市場に勝っていない。AIが市場より正しいのは
『どのレースが読みにくいか』の判定と、『人気馬のうちどれが危ないか』の指摘**」。

🔴 **回収率は必ず 100% 未満の実数のまま出す。** 「控除率20%のプールで79〜86%」と併記する。
