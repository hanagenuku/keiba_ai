# F-3 結果: 新馬戦で現行 Layer 1 が市場に −0.085 負ける原因の分解

実施 2026-09-08。ユーザー指示（2026-09-08「次フェーズ指示書」§3）に対応。
⚠ 新馬専用モデルを作るのが目的ではない。原因の特定のみ。
⚠ 本番のモデル・買い目・予想パス・DB には触れていない。

## 事前登録された基準（ユーザー指示・実行前に確定）

> 最小モデルと131列モデルの差が **+0.005未満**なら、
> 「新馬では現在の特徴量構成では情報がほとんど存在しない」という仮説を支持する。

## 設計

- 学習は**全レース**（本番と同じ）、評価は**新馬行のみ**。
- 窓・手続きは M-1 / Phase 4 と同一（cid82・内側ホールドアウト42日・3シード平均）。
- 新馬行がある窓のみ使用: 探索期 T2(663行/61R)・T3(1,183行/85R) / 確認期 W1(886行/79R)・W2(297行/30R)。
  T1・W3 は新馬0行。
- 市場と比べるので母集団は「人気が取れている行」に統一。
- 131列には**レース距離そのものも頭数も無い**（すべて過去走との関係として符号化）ため、
  E 腕では距離・頭数・芝ダ・競馬場を生値で補った（予測時点で既知の情報のみ）。

## 判定: **基準を満たし、「情報がほとんど存在しない」を支持**

**E − D = −0.0022（確認期） / +0.0000（探索期）。両期間とも +0.005 未満。**

- **24列と131列で性能が同じ。**
- **C（騎手+調教師の7列だけ）で D の 97〜99% に到達**（探索期 0.7532 vs 0.7559）。
- 実測: **131列中 66列が新馬行で完全に定数**。実質的に動くのは53列だが、
  うち19列は下記の馬番ノイズなので、本当に情報を持つのは約30列。

🔑 **「AIが下手」ではなく「AIに渡すものが無い」が正体。**
E（いまアクセスできる情報を全部使い切った腕）でも市場に −0.0832 負けるので、
使い方の問題ではない。

## オラクル診断: AIは市場に何を足せるか

⚠ 市場人気を特徴量に入れた腕。**Layer 1 に採用するものではなく、上限を測るためだけ。**

```
                    確認期    探索期
M 市場のみ           0.7826   0.8241
D 現行131列          0.6972   0.7559
G 131列+市場人気      0.7861   0.8268
G − M               +0.0035  +0.0027
```
### 🔑 解釈は3点に分けて記録する（読み違えを防ぐため）

1. **AI単体は市場より大幅に弱い。** 131列単体 0.6972 vs 市場単体 0.7826（**−0.0854**）。
2. **市場を特徴量に入れると、AIの数字自体は劇的に上がる。** 0.6972 → **0.7861**（+0.0889）。
   ⚠ 「市場を入れてもAIの性能はほとんど上がらない」という読み方は**誤り**。大きく上がる。
3. **ただしその 0.7861 の大部分は市場の情報。** 市場単体 0.7826 に対して
   **AIが追加できたのは +0.0035 だけ**（探索期 +0.0027）。

つまり AIが新馬で持っている情報（騎手・調教師・レース条件）を、市場はほぼ完全に織り込んでいる。
全体レースでの上乗せ +0.0009（2026-08-18）と同じ桁で、新馬が特別に有望なわけでもない。

## 🔴 副産物: 新馬では相対順位列19本が「馬番順」になっている（ただし実害なし）

新馬行では過去走ベースの相対順位列が**馬番順そのもの**になっている（馬番との相関 **0.999**）。
元の値が全馬同値のため、レース内順位を付ける操作が安定ソートで馬番順を返す。

```
rl_f_speed_avg_rank / rl_f_speed_last_rank / rl_f_recent_rank / rl_f_recent_fukusho_rank /
rl_f_late_speed_rank / cl_f_dist_fukusho_rank / cl_f_course_fukusho_rank / cl_f_blood_rank /
cl_f_heavy_track_rank / rl_f_finish_time_rank / rl_f_time_diff_rank / rl_f_speed_fig_last_rank /
rl_f_speed_fig_avg_rank / rl_f_speed_fig_max_rank / cl_f_style_course_fit_rank /
cl_f_pace_fit_rank / cl_f_style_total_fit_rank / rl_f_pl_rating_rank / f_rl_rank
```
2026-08-29 の「オッズ全滅時に `sorted(..., key=lambda x: x.get('win_odds') or 999)` が
安定ソートで馬番順の人気を作っていた」事故と**同型の構造**。

🔴 **ただし実害は測定できるレベルにない。** 抜いた腕 D' は D とほぼ同じ
（0.6955 vs 0.6972 / 0.7544 vs 0.7559）で、木はこの偽情報を使っていない
（予測と馬番の相関 0.08〜0.16）。**「重大な発見」と最初に報告したのは行き過ぎで、訂正する。**
設計上の欠陥ではあるので記録は残すが、修正の優先度は低い。

## 含意

- 埋めるとしたら **血統（新馬は出馬表から必ずCNAMEが引けるので取得可能）** が唯一の候補。
  ただし現在 5.8%。⚠ 効果は未測定であり、取得コストに見合うかは別途判定が必要
- 🔴 **回収率は測っていない**（North Star #9）
