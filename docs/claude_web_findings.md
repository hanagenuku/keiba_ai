# `data/claude_web_findings.json` — Claude の web 見解の受け渡し仕様

Claude が開催日の朝に web から集めた情報を、アプリ・記事・台帳に渡すための1ファイル。
読み手は `src/features/claude_web.py`（画面・記事）と `src/product/web_log.py`（台帳）。

> 🟢 **2026-11-10 にユーザー指示で入口を広げた。** 方針は
> 「**いまはより多くの情報を web から取り込む段階**。実績が溜まったら信頼できる情報源を見極める」。
> ① 対象レース: 10R/11R だけ → **全レース**（記事になるレースを先に）
> ② 次元: 馬場・調教 → **＋予想家・予想サイトの印**（`picks`。台帳にだけ流す）
> ③ 不採用にした情報源も**集め続ける**（不採用＝本番モデルに入れない、であって集めない、ではない）
> 🔴 変えていないこと: **AI側の数字は1つも変わらない**（下の節）。

## この層が何をしないか（最初に読む）

このプロジェクトでは「予想の出力を後から書き換える層」が **5件すべて撤回**されている
（市場補正レイヤー / `error_tags` 週次補正 / `rank_matrix_filter` / AI xx%バッジ /
ROI予測150%）。そのためこの層は **AI側の数字を1つも変えない**:

- `score` / `total` / `win_prob` / `cal_prob` / `rl_rank` / `fit_rank` /
  `bets` / `gumbel_bets` / `rec` / `conf` を**読まないし書かない**
- 画面では AI の列とは**別枠**（🌐 Claude の web 見解）に出る
- だから後から A/B が組める（AI単体 vs AI＋web を同じレースで実配当で比べられる）

`tests/test_claude_web_findings.py::test_notes_do_not_change_probabilities_or_bets`
がこれをコードで固定している。**このテストを緩めて通さないこと。**

## 期待値（先に書いておく）

- 2026-09-26（N=1）: 別AIが web 情報でアプリの印を組み替えた案は序列の精度が
  ρ +0.381 で、**市場人気順 +0.548 より下**だった
- 2026-09-27（23レース）: web の能力指数とレース内順位の相関は
  **指数~市場 +0.825 / AI~市場 +0.627 / AI~指数 +0.630**
  ＝ **web指数のほうが市場に近い**。独立な情報ではない
- websig（134,874頭・2026-09-25）: AUC は +0.002〜0.004 動き LogLoss は3窓とも改善したが、
  **複勝回収率は 79.7% → 79.1% で悪化**

→ この層（別枠表示）自体は予想を変えない。**予想に反映するかどうかは
`websig/ADOPTION_STANDARD.md`（2026-11-11〜: 順位付けの精度と的中率）で決める。**
2026-11-10 までは「採否は実配当で決める」だった。

## 入れてよい情報 / 入れない情報

| | | 行き先 |
|---|---|---|
| ✅ 入れる | **馬場状態・トラックバイアス** | 画面・記事・台帳 |
| ✅ 入れる | **調教（追い切り）の評価・タイム**。情報源が序列を付けていれば `grade` に**必ず**入れる | 画面・記事（`grade` は台帳のみ） |
| ✅ 入れる | **予想家・予想サイトの印**（`picks`・出典ごと）。2026-11-10 追加 | **台帳のみ**（画面・記事に出さない） |
| ❌ 入れない | 朝イチオッズ・人気の分析（市場そのもの。`base_margin` から既に入っている） | — |
| ❌ 入れない | 出典 URL を示せない情報、`netkeiba` 由来のオッズ・タイム（規約） | — |

🔑 予想家の印は 2026-11-09 まで「市場の言い換えだから入れない」としていた
（2026-09-27 実測: web 指数〜市場 ρ+0.825）。**これは「予想に足しても上乗せが無い見込み」で
あって「集めなくてよい」の根拠ではない。** どの出典が当たるかは、集めて結果と並べないと
分からない。だから集める。ただし AI の印と並べて見せない（2026-10-07 の決定）。

対象は**全レース**。時間が足りないときの優先順は
① 有料記事になるレース（`conf >= 66`）→ ② 無料記事になるレース（9〜11R の推奨漏れ）→ ③ それ以外。

### 検証ルール（`build_claude_view` が実際に弾くもの）

| 条件 | 挙動 |
|---|---|
| `race_num` が 1〜12 以外 | `None`（2026-11-09 までは 10/11 以外をすべて落としていた） |
| `date` が対象日と不一致 | `None` ＋ 警告。**前の開催の印を今日の画面に出さない** |
| レース entry に `sources` が無い | `None` ＋ 警告。裏づけの無い見解は通さない |
| `schema_version` が 1 以外 | ファイルごと無視 ＋ 警告 |
| そのレースに居ない馬番 | その項目だけ落とし、理由を `dropped` に残して画面に出す |
| `order` に重複 | 同じく落として `dropped` に記録 |
| 未定義の印（`◎○▲△☆✕消` 以外） | 落として `dropped` に記録 |
| `order` / `marks` / `horses` / `going` / `summary` が全部空 | `None` |
| `picks` | **view に入れない**（画面・記事に出ない）。台帳だけが読む |

`coverage`（序列が付いた馬の割合）が 100% 未満なら画面に明記される。
**欠けたまま「序列」と名乗らせない。**

### 🟢 `picks` ＝ 予想家・予想サイトの印（2026-11-10 追加・任意）

| | |
|---|---|
| 形 | `[{"source": URL, "tipster": "名前(任意・40文字まで)", "marks": {"馬番": "◎"}}]`。**出典ごとに1要素** |
| 印 | `◎○▲△☆✕消` のどれか。それ以外の記号は情報源の表記をこの7つに寄せず、**入れない** |
| 出典 | `source` の URL が無い要素は捨てられる（出典が「どこの情報か」の単位） |
| 台帳 | `kind: "pick"`・1頭1出典1行。夜の結果取得で着順・3着内・複勝払戻が自動で付く |
| 表示 | **どこにも出さない** |
| 🔴 やらないこと | 複数の出典の印を自分で平均・集約して1つにしない（出典ごとの当たり外れが数えられなくなる）。有料記事の中身を書かない |

### 🔴 `horses[num].grade` ＝ 情報源が付けた序列（2026-10-23 追加・任意）

| | |
|---|---|
| 何を入れるか | **情報源自身が付けた評価**をそのまま。`"S"` / `"A"` / `"B"` / `"C"` / `"★2"` 等（8文字以内。超えれば捨てられる） |
| なぜ必要か | これが無いと「どの情報源が信頼できるか」を**何年蓄積しても測れない**。実測で `umasiru` は note の文中に 評価 S/A/B/C を 26/27 持っていたが、自由文なので台帳からは序列として読めなかった |
| 🔴 やらないこと | **`note` から正規表現で後から取り出さない。** 情報源が付けた値とこちらが解釈した値が同じ列に混ざると後から区別できない（2026-09-02 のパドック `condition` キーと同型） |
| 表示 | **記事にもアプリにも出さない。** web の序列・印を AI の印と並べない（2026-10-07 の決定）。`grade` は `data/web_findings_log.json` の台帳に残るだけ |
| 判定基準 | `websig/CRITERIA_RELIABILITY.md`（事前登録カード） |

⚠ **序列が無い情報源に無理に付けない。** 情報源が評価を出していないなら `grade` は
省略する（`None`）。その情報源は「測れる形になっていない」のが事実で、
こちらが自由文から推測した値を入れると、その事実が見えなくなる。

## 運用手順（開催日の朝）

正は朝の Routine のプロンプト。要点だけ:

1. 予想の生成（`weekend.yml`・13〜14分）を起動したら、**待っている間に web 収集を始める**
   （会場は前日の時点で分かっている。馬番の検証は `latest.json` が出てから）
2. 全レースについて、上の3次元を「使える」情報源＋WebSearch で集める。優先順は上のとおり
3. `data/claude_web_findings.json` を書く（`date` は開催日・`collected_at` は実時刻）
4. `data/` 配下のデータコミットとして `main` に置く（North Star #2 の例外。**コードは触らない**）
5. 夜の結果取得（`sunday-results.yml`）が台帳 `data/web_findings_log.json` に結果を付ける

🔑 新しいホストを使うときは、**先に robots.txt を読む**。使ったら
`data/source_registry.json` とこのファイルの表の両方に足す（報告に書けば次のセッションが足す）。

## 後から測るとき

`claude_view.order` と実着順、`rl_rank`（AI+市）と実着順を同じレースで並べれば
**AI単体 / AI＋web / 市場**の3者をレース内 Spearman と実配当で比較できる。
⚠ North Star #7: 数レースの結果で採否を決めない。事前登録カードを書いてから測る。
