##### 🔴 自分の仮説が外れた：食い違いの代償はゼロだった
「旧モデルは**バグのある最古走**で学習されており、PR #209 で推論側だけ前走を返すように

**旧モデルは、学習したバグ入りの値より、修正後の正しい値を渡した方がわずかに当てる。**
食い違いは損失ではなかったので、「食い違いを直すための再学習」という動機は消えた。

#### 📘 GAP：素のAIが市場と大きく食い違う原因は追える。ただし「代わりに誰を買うか」は言えない

直前オッズを押した時点では ② は既に手元にある。知りたいのは ① だけ。

同じ時点のアンカー **A2（確定オッズから作った人気順位 + Zipf）** を足して分離した。

```
A  人気順位 + ドリフト（朝の予想生成時点）   AUC 0.8038
A2 人気順位（直前オッズを押した時点）        AUC 0.8226
B  実オッズ（同じ時点）                    AUC 0.8292
C  実オッズ + ドリフト（朝の時点）           AUC 0.8080

  Q1 朝に生成する予想      C − A  = +0.0042   ① 2/3窓 ❌   ② ❌
  Q2 直前オッズを押した後  B − A2 = +0.0066   ① 3/3窓 ✅   ② ❌

窓ごと(Q2)  +0.0018 / +0.0040 / +0.0138  ← 3窓とも同符号
```

##### 🔑 内訳が一番の収穫: 効いているのは実装よりユーザーの運用
```
A  0.8038  朝の予想のまま
A2 0.8226  直前オッズを押す          ← +0.0188  ユーザーの運用
B  0.8292  さらにオッズの大きさも使う  ← +0.0066  アンカーの作り方
```
+0.0254 の**7割はユーザーが直前まで待って押していること**が稼いでいた。
アプリを変えるより、押し続けることのほうが効いている。

##### 実装した（⚠ 基準②未達をユーザーが承知のうえで判断）

`ranked.sort(...)` → `pop = i+1` → `_baseMarginFromPopularity` と、

⚠ **基準②（平均+0.01以上）は未達**。基準①は満たす。2026-07-27 に「基準未達でも

#### ❌ F-4：「直近の成績を買いすぎ」の偏りを細分化 → **どの条件で強まるかは予測できない**

F-3 で見つかった偏り（前走大敗が有利・前走好走が不利）を、条件別に細分化した。
セルの回収率そのものではなく**偏りの大きさ Δ**で測った:

    Δ = 回収率(前走6着以下) − 回収率(前走1-3着)

🔑 セルの回収率を見ると多重比較で必ず100%超が出る（F-3で実証済み）。
**Δ なら、その条件固有の水準（コースの荒れやすさ等）が相殺される。**

##### まず：偏りは 2〜4番人気にほぼ固有だった
```
人気         前走1-3着   前走6着以下      Δ
1番人気       77.5%    80.8%   +3.3pt
2-4番人気     73.5%    83.7%  +10.2pt   ← 4〜9.9倍の帯
5-9番人気     76.7%    73.8%   -2.9pt   ← 符号が反転
10番人気〜     55.7%    64.3%   +8.6pt
```
⚠ **5-9番人気で逆転する**（N=9,168/29,378と十分大きい）。一般的な市場バイアスなら
人気に沿って滑らかに変わるはずで、この飛び方は「偏りが思ったより脆い」ことを示唆する。

##### 条件別（人気2-4・両側N>=500の41セル）
```
福島        66.6% → 98.0%  Δ+31.4pt      中山        77.0% → 71.7%  Δ -5.4pt
函館        64.6% → 93.3%  Δ+28.7pt      重          77.9% → 73.3%  Δ -4.6pt
休み明け(半年〜) 67.7% → 93.6%  Δ+25.8pt      少頭数(〜9)   80.6% → 80.5%  Δ -0.2pt
2100m〜     67.0% → 91.6%  Δ+24.7pt      小倉        78.4% → 79.1%  Δ +0.7pt
（全体）      73.5% → 83.7%  Δ+10.2pt
```
41セル中4セルが Δ>=+20pt。⚠ Δの5〜95%点が -0.2〜+25.8pt なので、
**+20pt超は約1割が期待され、41×0.1≒4セル。観測4セルは期待値ちょうど。**

##### 🔴 決定的：Δ の順位は前半と後半で**まったく相関しない**
40セルについて 2023-24 の Δ と 2025-26 の Δ を突き合わせた:
```
r(Δ2023-24, Δ2025-26) = -0.001    並べ替え検定 P=51.1%

2023-24でΔ上位5セル → 2025-26     2023-24でΔ下位5セル → 2025-26
  半年〜      +30.9 → +22.4 ✅      小倉      -28.0 → +26.9 （反転）
  5歳        +29.4 →  +2.5 ❌      中山       -8.0 →  -3.2
  2100〜     +26.9 → +24.0 ✅      重         -4.4 →  -5.4
  1400-1600 +26.1 →  -3.4 ❌      連闘       +0.3 →  +8.0
  福島        +26.1 → +36.5 ✅      中京       +0.4 →  +8.7
```
**「どの条件で偏りが強まるか」は、翌年にまったく持ち越さない。**

##### 🔴 自分がやりかけた誤り（記録）
最初、福島・函館・休み明け・2100m〜 の4セルを **全期間の表から選んで**
「2023-24 → 2025-26 で Δ が維持されている（+26.1→+36.5 等）」と書きかけた。
**選抜に2025-26のデータを使っておきながら、2025-26で検証したことにしていた**（選択汚染）。
正しい検査は「前半だけで順位をつけて後半で評価する」で、それをやると r=-0.001。
2026-08-15② の「25マス見れば偶然100%を超える」と同じ型を、Δ という別の量で踏みかけた。

##### 積み上げも通らない
```
前走6着以下（全体）                 N=9,227 回収 83.7% 3本抜83.1% CI[79, 88]
  × 福島or函館                   N=1,299 回収 96.1% 3本抜93.1% CI[84,110]
  × 休み明けor2100m〜             N=1,699 回収 92.1% 3本抜89.6% CI[81,104]
  × 福島or函館 × 休み明けor長距離      N=  212 回収 85.6% 3本抜72.7% CI[60,116]
```
最良の「福島or函館 × 前走6着以下」でも **CI下限84%** で基準4（CI下限>100%）に届かない。
重ねると N が落ちて 3本抜きが崩れる（93.1% → 72.7%）。

##### 判定
**細分化はここで打ち切る。** 偏りの存在（Δ≈+10pt）は 246セル・50,000頭規模で
一貫しているが、**どの条件でそれが強まるかを事前に選ぶ手段が無い**。
福島の98.0%は4年とも80%超（83/101/108/97）で目を引くが、41セルの最大値であり、
順位の持ち越しがゼロである以上、来年も高い保証は無い。

##### 🔴 まず見つかった設計上の問題：公開リポジトリへの自動push

#### 🔴 アプリ成績ページ「AIの盲点パターン」が実力を9倍悪く見せていた（修正）

ユーザーがアプリの当該カードを見て「これは何を意味しているのか」と質問。
確認したところ**3つの問題**があった。

##### ① 「AI外れ率 94.4%」は失敗率ではなく、良い数字を裏返したもの
`upset = bool(act3 - ai3)` の定義上、「外れ」でないためには
**AI上位3頭が実際の1〜3着と完全一致**する必要がある。つまりこの数字は
**三連複をAI上位3頭ボックス1点で買った時の外れ率**と同義だった。

```
AI上位3頭が実着順3着内と完全一致   32/570 = 5.6%
無作為に3頭選んだ場合（頭数平均）          0.62%
→ AIは無作為の約9倍。「94.4%」は失敗率ではない
```

##### ② 「要注意パターン 100%」は全部ノイズだった
`blind_spots` は **N>=5 のセルを upset_rate 降順**で並べていた。全体が94.4%なら:

| N | 偶然100%になる確率 |
|---|---|
| 5R | **75.0%** |
| 9R | 59.5% |
| 14R | 44.6% |
| 21R | 29.8% |

しかも combo軸4種を全会場・全グレード・全頭数帯で作った中から**最大値10件**を
拾う表。100%が並ぶのは構造的に当然（2026-08-15②「25マス見れば〜」と同型）。

##### ③ 「穴馬率」は測っていない数字を 0% として出していた
判定は `(s['winner_odds'] or 0) >= 10.0` だが、**`shadow_bets.winner_odds` は
570件すべて NULL**。永久に 0% を返す。2026-08-07⑥（ROI 150%べた書き）・
2026-08-18②（AI xx%バッジ）と同じ「作り話をしない」違反。

##### 対応
| | |
|---|---|
| ① | `hit3_rate`・`random_hit3_rate`・`overall_full_miss_rate` を追加し、**的中側を主役に**した。カード名も「🔍 AI上位3頭の当たり方」に変更 |
| ② | `_BLIND_SPOT_MIN_N = 30` に引き上げ、並び順を **`p_chance`（二項分布で偶然そうなる確率）の昇順**に変更。率の降順だと小さいNの偶然が上位を独占する |
| ③ | `longshot_rate` を**削除**（復活させるなら winner_odds を実際に埋めてから） |

##### 副産物：並べ替えたら本物の盲点が出てきた
```
条件                              N    全滅率  3頭的中  偶然の確率
Cグレード・多頭数(14頭〜)          255  18.0%   3.5%     0.4%   ← 本物
ダート・Cグレード・多頭数(14頭〜)   115  20.9%   1.7%     0.5%   ← 本物
ダート・短距離(〜1400)              86  17.4%   2.3%     9.2%
芝・Cグレード・多頭数(14頭〜)      140  15.7%   5.0%    12.1%
（以下 14.6% 〜 61.3% ＝ 読む価値なし）
```
全体の全滅率 12.1% に対し、**14頭以上の多頭数だけ 18.0%（N=255・偶然の確率0.4%）**。
combo軸のセル数（N>=30 で約40）でBonferroni補正しても 0.004×40=0.16 で生き残る。
⚠ ただし上位2件は包含関係にある（ダート多頭数 ⊂ 多頭数）ので**実質1つの発見**。
⚠ これは「多頭数で全滅しやすい」という**測定**であって、買い方の指示ではない。

##### テスト
`tests/test_upset_patterns.py` 新規9テスト。North Star #6 に従い手打ちdictではなく
**実際に sqlite3 に INSERT して sqlite3.Row として読み出した行**で検証。
特に固定したもの: 的中率と外れ率が相補であること・無作為ベースラインが併記されること・
**N<30 のセルが blind_spots に出ないこと**・並び順が `p_chance` 昇順であること・
**`longshot_rate` がどこにも出ないこと**。675テスト通過。
