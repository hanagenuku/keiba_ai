### 最終更新: 2026-08-17（展開の同時分布を9回の計測器修正を経て検証 → 定量化して打ち切り）

#### きっかけ
ユーザーの長年の主張「レースは全体として決まる。逃げ馬が何頭いるか、
人気の先行馬がやり合えば差しが決まる」を、初めて統計として検証した。
きっかけは他社アプリの「AI展開予測」（11頭を平面に並べて位置を表示）と、
「隊列を並べて何百回もシミュレートする動画」。

#### 🔑 まず整理した「2つの効き方」
| | 何を良くするか | 状態 |
|---|---|---|
| A. 展開予想の精度を上げる | 「どの馬が来るか」（周辺確率） | 実装済み。2026-08-06にリークを直し特徴量の99.5%の値が変わったが**AUCは -0.0002** |
| B. 展開を"共通の乱数"として使う | 「どの**組み合わせ**が来るか」（同時確率） | **一度もやっていない**。`simulate_race`は独立Gumbelなので構造的に不可能 |

ユーザーの例（先行が潰し合う→差しが**まとめて**来る）はBの話。
Aをどれだけ磨いても、独立に乱数を振る限り相関はゼロ。

#### 🔴 本番の実装がどうなっているか（実測）
```
① 各馬に脚質ラベル1つ（過去走の多数決。履歴なしは枠番で代用）
② レース全体で頭数を数える → escape_count / front_count
   ここで「誰と誰か」が消える
③ ペースモデル(19特徴量) → P(ハイ)/P(ミドル)/P(スロー) の3数字
④ 各馬に還元: f_pace_x_style = P(スロー) − P(ハイ)  ← 引き算1個
⑤ simulate_race: rating + 独立乱数 → 展開の痕跡は完全に消える
```
🔴 ルールベース`f_pace()`には**競り合いペナルティが実装されている**
（逃げ2頭以上で `ev -= (esc-1)*0.5` 等）が、これは`_W`専用で
**本番のXGB経路では一度も使われない**。
🔴 本番129特徴量に **`escape`を含む列は1つも無い**。
つまり本番のAIは「このレースに逃げ馬が何頭いるか」を知らない。

#### 検証の設計（軸を人が選ばない）
最初は「先行タイプの頭数」という**私が選んだ1軸**だけを測っていた。
ユーザーから「例えに固執するな」「数百パターンで探れ」と指摘を受けて全面変更:
- 周辺確率は**129特徴量の本番同型モデル＋Isotonic較正**から作る
  （騎手・調教師・コース適性・血統は全部ここに吸収される）
- 帰無モデル＝その周辺確率を保ち「ちょうど3頭が3着内」で条件付けた独立モデル
  （＝独立Gumbelシミュレータが持つ joint と同じ性質）
- **[B]大域**: 3着内の3頭は独立より129次元空間で似ているか
- **[A]局所**: 129軸それぞれで「その軸で似た2頭が同居しやすいか」→ FDR補正
- 学習≤2024 / 較正2025 / 検定2026（および1年ずらした再現）

#### 結果
| | 2026年 | 2025年 | 判定 |
|---|---|---|---|
| **[B] 大域** | z=-0.38 | z=-0.55 | **2年ともヌル** |
| **f_post（枠順）** | +0.0098 固まる | +0.0074 固まる | ✅ **2年連続・同符号でFDR通過** |
| f_course_fukusho 他 | 通過 | 圏外 | ❌ 入れ替わり |
| f_pop_last 他8軸 | 圏外 | 通過 | ❌ 入れ替わり |

124軸中、**2年で同符号を保って通過したのは`f_post`ただ1つ**。
機序は当日の馬場バイアス（内が伸びる日／外が伸びる日）で説明がつく。

#### 🔑 決定打: それは馬券の値付けをどれだけ動かすか
`f_post`を共通の潜在変数にしたモデルと独立モデルを**厳密に**比較した
（基本対称式e₃を動的計画法で計算。サンプリング誤差を挟まない。
総当たりとの突合で検算済み）。σは2025年で決め2026年で検証。
```
独立モデル      logP = -4.3698
潜在変数モデル   logP = -4.3663
差              +0.00353  → 三連複の確率が平均 1.0035倍（+0.35%）
⚠ 控除率25%の壁 = 1.333倍。**約100倍足りない**
```
⚠ `f_post`と`horse_num`の結果が小数点以下5桁まで一致した。
レース内で標準化すると同じz-scoreになるためで、
**2通り試して両方効いた、ではない**（実質1つの検定）。

#### 結論
**「展開を精緻にすれば勝てる」という筋は閉じる。**
連動は**幻ではなく実在した**が、桁が2つ足りなかった。
隊列シミュレーションを作っても絵が綺麗になるだけ。今後この方向に戻らない。

### 2026-08-17③：②「プール間の矛盾」は開催日にしか調査できない（土日に自動実行）

#### 狙い（①とは性質がまったく違う）
1レースで3着内に入るのは必ず3頭。したがって**厳密に**成立する:

    Σ_{B≠A} P(A,B がともに3着内) = 2 × P(A が3着内)

つまり**ワイドのオッズ盤**から各馬の3着内確率が導出でき、それは
**複勝のオッズ盤**に直接書いてある値と一致しなければならない。
一致しなければ、ワイドを買う群衆と複勝を買う群衆が同じ出来事に
違う値段を付けている（＝同じ意見を安い方のプールで買える）。

🔑 **正規化定数（どちらも合計3）が厳密に既知なので、控除率の推定が要らない。
予測モデルも一切使わない。**①で9回壊した「確率の推定」という弱点が
構造的に存在しないのが強み。

#### 🔴 制約: 開催日（土日）にしか実行できない
2026-08-17（月）に実行したところ直近9日すべてで
「開催情報が見つかりません」となった。前日の日曜に調教プローブを
走らせた際は同じ日付で取得できていたため、コードのバグではない。

原因: `get_kaisai_on_date`が見る出走表一覧(`pw01dli00`)は
**これから開催されるレースしか載せない**。オッズ盤も発走前にしか存在しない。

→ `probe-wide-odds.yml` に `cron: '10 23 * * 5,6'`（08:10 JST 土・日）を
設定。土曜が空振りしても日曜で拾えるよう両日に撃つ。

#### 調べること
`accessO.html` の CNAME `{odds_base}{race_num}{date}Z/{suffix}` の
**`Z`が券種の指定子か**を A〜Z の総当たりで確認する。
判定は「組番（1-2, 1-3…）が多数あるか」の一点
（単複の盤は馬番ごとに1行なので組番が出ない）。

### 2026-08-18：「回顧」をAIにやらせられるか。走行ルートのパースを修正し、
### 「溜まれば上がる」「重賞は僅差」を実測した

#### 🔴 発見：コーナー通過順（隊列表記）が2026-07-22の導入以来ずっと壊れていた
実データを見たところ `corner_pass_3` が `'7,'`、`corner_pass_4` が `'(*7,'` と
**途中で切れており充足率20.8%**。本来は `(1,*5)6,10(2,9)-(3,4)8=7` という
隊列全体の表記が入るはずだった。原因は2つ:

| # | 原因 |
|---|---|
| ① | `soup.get_text(' ')` は要素間に空白を入れるのに、正規表現の文字クラスに空白が無かった → 最初の区切りで切れる |
| ② | ラベルの後ろを貪欲に拾っていた → 次の見出し `4コーナー` の `4` が3コーナーの通過順に混ざる |

先にラベル位置で区切ってから中身を拾う形に書き直し、表記を隊列内の位置に
展開する `parse_corner_passage()`（先頭からの順位・併走頭数）を追加した。
⚠ **直るのは今後取得する分のみ。** JRAの結果一覧は直近しか遡れないため
既存の壊れた分は大半が復旧できない。

⚠ テストの落とし穴: **綺麗な1文字列のフィクスチャでは①を再現できない**
（修正前でも通ってしまう）。North Star #6 に従い、要素が分割され空白が入る
本番と同じ形のHTMLで検証した。

#### 「回顧」の信号は実在するか — コメントを取りに行く前に代理変数で測った
人間の回顧（出遅れたので度外視／末脚は評価）が儲けになるのは
**市場がその馬を割引しすぎている場合だけ**。市場も同じ映像を見ている。
そこで既存データ（`corner_all` 93.5% / `agari3f` 100%）で代理変数を作り、
**次走で市場が過小評価しているか**を測った（学習2023-24で人気×頭数の
実測表を作り、2025年以降で評価）。

| 条件 | 市場残差 | 複勝回収 |
|---|---|---|
| 前走6着以下 × 上がり上位20% | **+0.87pt** | 73.8% |
| 前走6着以下 × 上がり上位10% | +0.95pt | 74.7% |
| 前走10着以下 × 上がり上位20% | **+1.18pt** | 74.0% |
| **前走6着以下 × 大幅に出遅れ** | **−0.30pt** | **67.0%** |
| （対照）前走6着以下 × 上がりも平凡 | −0.61pt | — |

🔑 **「着外だが末脚は評価」は本物**（対照群と符号が逆・最大+1.18pt）。
🔑 **「出遅れたので度外視」は逆効果**（マイナス）。人間の回顧の定番だが、
市場は既にそれを織り込みすぎている（＝出遅れた馬は次走で買われすぎ）。
⚠ **ただし最大でも+1.18ptで、複勝回収は74%止まり**。控除率20%に届かない。
コメントをスクレイピングしても同じ出来事の描写なので、桁は変わらない見込み。

#### 「予想と結果の差」は学習できるか → できない
残差 r = 実際に3着内か − モデルの3着内確率。その馬・騎手・調教師の
**過去の**平均残差が今回の残差を予測するかを測った（すべて時点より前のみ）。

| 調教師ごと（100走以上） | ≈0 | — | ≈0 |

**相関は統計的に有意だが、当てる力は増えない**（むしろ微減）。
「期待を裏切り続ける馬」は実在するが、その情報は既に他の特徴量が
吸収している。よく当てはまったモデルの残差はノイズ、という原則通り。

#### 「溜まれば上がる」は2つの別の問い。**どちらも否**
| 軸 | 実測 |

| ① レース数（学習データ量） | 1年0.7651 → 2年0.7711 → 3年0.7710 → 3.5年0.7706 ＝ **2年で飽和**（2026-08-08③） |
| ② その馬を見た回数 | **下表。増えても市場との差は開かない** |


### 2026-08-18③：「高自信レースを更に絞って資金配分すれば勝てるのでは」→ 否定

#### 問いを2つに分けた
ユーザー提案「当てやすいレースの中身をさらに分析し順位をつける。馬券選びを精査、
資金配分や掛け金を上げる。最適なかけ方をすれば利益が出るのでは」。

| | 内容 | 扱い |
|---|---|---|
| **A. 選び方** | 高自信レースを更に切る／券種を変える | **測る**（43セル） |
| **B. 配分・掛け金** | 資金配分の最適化 | **測らない。算数で決着** |

#### 🔑 B は測る必要がない（算数）
賭け金 a_i、期待値 E_i の組み合わせの総期待値は `Σa_i·E_i / Σa_i` ＝ **E_i の加重平均**。
**すべての E_i < 1 なら、どんな配分でも総期待値は必ず < 1。**
配分が動かせるのは**分散だけ**で、期待値は1度も動かない。

Kelly基準 `f* = (p·o − 1)/(o − 1)` は EV<1 のとき **f* が負**＝「賭けるな」。

🔑 **配分の議論は、EV>1 の的が1つでも見つかってからの話。**
逆に言えば、見つかった時には配分が決定的に重要になる（大きく賭けすぎると
正のEVでも破産する）。順序が逆にならないようにすること。

#### A-1: 高自信レースを25セルに切った（複勝・3,560レース）
事前登録した5基準（①100%超 ②N≥300 ③前後半とも100%超 ④3本抜きでも100%超
⑤+の日が過半）。**満たしたセルは0個。100%を超えたセルも0個。**

```
ベースライン  全レース 軸複勝回収 83.4%  ／ 高自信(上位25%) 88.3%
最良セル      高自信×2勝以上 93.4% (N=149・後半86.4%)
次点          高自信×ダート少頭数 90.4% / 高自信×中長距離 90.3%
最低          自信度の最上位1% 79.4% (N=68)  ← 絞りすぎると逆に落ちる
```

#### A-2: 券種を9構成×2帯で総当たり（668レース・実配当）
```
構成                        高自信      低自信      差
単勝 軸1点                   95.9%     79.2%    +16.7
馬連 軸×AI2,3 (2点)          95.9%     79.9%    +16.0
複勝 軸1点                   91.3%     82.8%     +8.5
ワイド 軸×AI2,3 (2点)         87.9%     76.6%    +11.3
複勝 AI上位3頭                87.5%     81.2%     +6.3
三連複 AI1-4ボックス           86.5%     76.1%    +10.4
三連複 軸流し AI2-6 (10点)     79.7%     77.0%     +2.7
三連複 軸流し AI2-5 (6点)      73.4%     71.3%     +2.1
```
✅ **9構成すべてで高自信＞低自信**（9/9）。自信度が効くことは疑いない。
🔴 **しかし18セルすべてが100%未満。** 最良でも95.9%。
✅ 控除率の順に並ぶ（複勝/単勝20% > ワイド/馬連22.5% > 三連複25%）＝
   **控除率の高い券種に逃げるほど不利**、という2026-08-03の結論と整合。

#### 🔑 どこまで来ていて、あと何が足りないか
単勝プールの平均回収は控除率20%ぶん引かれて**80%**。
```
全レースの軸      79.2%  = プール平均の 0.99倍
高自信の軸        95.9%  = プール平均の 1.20倍   ← 自信度で+20%取れている
損益分岐          100%   = プール平均の 1.25倍
```
⚠ **2026-09-17 訂正**: ここから「必要な優位の80%を取れている」「残り4ptは市場が正しく
値付けしている部分だ」とは**言えない**（回収率の比は獲得エッジの比ではないし、残り4ptの正体は
これまでの実験だけでは断定できない）。正確には——
**現時点で検証した情報・特徴量・モデル改善・馬券ロジックの範囲では、
市場アンカーに対する安定した追加優位を確認できていない。**
「市場を絶対に超えられない」という結論にはしない。
⚠ 95.9% 自体も N=190レース・21開催日（3本抜き90.7%・＋の日47.6%）で North Star #7 の危険域。
だが残りの4ptこそ市場が正しく値付けしている部分で、
これまで測った全ての手段（129特徴量・展開・回顧・残差・蓄積・重賞）が
そこに届かなかった。

⚠ 95.9%は **N=190レース・21開催日**で、3本抜き90.7%・+の日47.6%。
  2026-07-27の事故（76点4日で182.8% → 2,000レースで71.3%）と同じ危険域にある。
  信頼できるのは **N=3,560の複勝側（最良93.4%）** のほう。

🔑 見出しはワイド軸×AI3（93.6%）が複勝（93.0%）をわずかに上回るが、
**+0.6ptはN=183のノイズ**。決定的なのは3本抜き列で、
**複勝は−1.4pt、ワイドは−8.5pt**。同じ93%でも中身が違う。

🔑 **市場は全部の隅を同じ値段にしている**（この検証で最もはっきり見えたこと）:
的中率を 77.1%→9.1%、配当を 1.21倍→9.92倍 と桁を変えても、
**回収率は73〜94%の狭い帯に収まる**。「当てにいく」も「配当を取りにいく」も
行き着く先が同じ。控除率の壁がここに見える。

⚠ ワイドの控除率22.5%は複勝20%より**2.5pt不利なスタート**。
⚠ 高自信は183R・21開催日のみ（`race_dividends`は2026-06-06以降しか無い）。

**運用の推奨は複勝**。数字が高いからではなく、**3本抜きで崩れない＝
測った数字が信じられる**から。ワイドの93.6%は来年再現するとは言えない。

#### 結論
**「選び方」は正しい方向で、実際に+17ptを稼いでいる。しかし+21pt必要。**
配分・掛け金では1ptも埋まらない（算数）。券種を変えても埋まらない（市場が
全券種を同じ値段にしている）。この筋はここで閉じる。

##### 復元の仕方（同じ手が今後も使える）

`git fetch --unshallow` が必要だった。76世代→209レース）。

#### 🔴 A-2：軸の確度の較正 → **較正の問題ではなかった（解像度の問題）**。直せない

> 🔴 **【2026-08-22 訂正】この節の結論は、より大規模な測定に負けている。**
> 同時期に別セッションが **3,560レース**で同じ量（軸の top3_prob）を測り、
> 的中(軸の複勝)予測の **AUC 0.6041**（市場のみ 0.5708）を得ていた（PR #179）。
> 本節の 0.548 は**本番536レース**での値で、95%CI上限が 0.597。
> **N が6.6倍大きい 0.6041 の方が信頼できる**ので、
> 「軸の確度には解像度が無い」という本節の断定は**取り下げる**。
> 実際の対処も「バッジを削除」ではなく **`race_confidence()`（軸の3着内確率）に差し替え**が
> 採用され、画面には「軸3着内 xx%」と表示されている。
> ⚠ ただし**旧バッジ（手製の式）が情報を持たない**という点は両者一致している
> （本節 AUC 0.483 / #179 側 0.5289）。そこだけは有効。
> 🔑 教訓は残る: **再較正で直るかはAUC（解像度）で判定する**。ただし
> **その AUC 自体を小さいNで測ると、今回のように誤った断定に至る**（North Star #7）。

今朝「0.65で頭打ち」と分かった軸の確度を、較正で直せるかを調べた。
結論は **直せない**。そして調べる過程で、**アプリが見せている「AI xx%」バッジが
実測と無関係**だと判明したので、そちらを削除した。

##### まず切り分け：softmax か Harville か
`fuku_prob = Harville(softmax(total, T=3.5))` なので、どちらが原因かを分けた。
検算として保存済み `win_prob` から Harville を再計算すると、保存された `fuku_prob` と
**中央値 0.000000** で一致（経路の理解が正しいことの確認）。

| | ECE | 5分位（予測/実測） |
|---|---|---|
| 全馬 × 勝率 | **0.0079** | 0.017/0.016 … 0.185/0.195 |
| 全馬 × 3着内 | **0.0205** | 0.062/0.069 … 0.507/0.460 |
| RL1 × 勝率 | 0.0820 | 0.119/**0.243** … 0.378/**0.269** |
| RL1 × 3着内 | 0.1018 | 0.339/**0.477** … 0.795/**0.528** |

⚠ **平均では過信していない**（RL1の3着内は予測0.574 / 実測0.528）。
壊れているのは**傾き**で、下の帯は過小・上の帯は過大。つまり
「全体の水準」ではなく「順序がつくかどうか」の問題だった。

##### 決定的な検査：軸の中での解像度（AUC）
再較正（Isotonic・Platt・温度）は**単調変換**なので、水準は直せても
**順序の情報を作れない**。そこでRL1だけを取り出してAUCを測った（N=536）:

| 予測子 | 対象 | AUC | 95%CI |
|---|---|---|---|
| **fuku_prob（現在の軸の確度）** | 3着内 | **0.548** | [0.502, 0.597] |
| win_prob | 3着内 | 0.551 | [0.505, 0.600] |
| cal_prob | 3着内 | 0.591 | [0.541, 0.639] |
| **市場: -log(単勝オッズ)** | 3着内 | **0.661** | [0.613, 0.706] |
| fuku_prob | 1着 | 0.532 | [0.478, 0.585] |
| 市場: -log(単勝オッズ) | 1着 | **0.694** | [0.647, 0.741] |

（参考）**全馬**なら fuku_prob の AUC は **0.723**。

🔑 **軸に絞った瞬間に情報が消える**。CI下限が0.5に接しており、
「軸が来るかどうか」について現在の確度はほぼ何も言っていない。
**再較正しても、正しい答えは「どの確度でも約0.53」になるだけ**で物差しにならない。

原因は最大値バイアス。`rl_rank==1` は「レース内で最大のスコアを取る」操作の結果なので、
選ばれた後に残るスコアの差はほとんどノイズ。全馬では効いている情報が、
argmax を取った時点で使い切られている。

##### 温度でも直らない（実測）
`win_prob = softmax(total, T=3.5)` は `p' ∝ p^(3.5/T')` で厳密に別温度へ振り直せる。

| T | RL1 3着内ECE | 全馬 3着内ECE | RL1最上位帯（予測/実測） |
|---|---|---|---|
| 3.5（現行） | 0.1101 | 0.0187 | 0.798 / 0.519 |
| 4.5 | **0.0938** | **0.0151** | 0.713 / 0.537 |
| 6.0 | 0.1055 | 0.0292 | 0.624 / 0.583 |
| 12.0 | 0.1903 | 0.0481 | 0.479 / 0.611 |

どの温度でも RL1 の ECE は 0.09 を下回らない。**予想通り、水準を動かしても
順序が無いものは直らない**。（T=4.5 が両方でわずかに良いが、差は小さく
今朝の教訓どおり小さいNで定数を動かす価値はないので**触っていない**）

##### 🔴 副産物：アプリの「AI xx%」バッジは実測と無関係だった（削除した）

`ev_filter` が見ている `fuku_prob` とは別に、画面には金色の
**「AI 87%」**のようなバッジが出ていた。これは `fuku_prob` ではなく

    conf = min(99, max(50, int(60 + (本命の人気順位 - 2) * 4 + スコア差 * 20)))

という**手製の式**だった。本番の実予想536レースで実測した:

| conf帯 | N | 軸の3着内 | 軸の勝率 |
|---|---|---|---|
| 〜70% | 222 | 55.0% | 28.4% |
| 70〜80% | 114 | 50.9% | 27.2% |
| 80〜90% | 97 | 49.5% | 26.8% |
| 90〜100% | 103 | **53.4%** | 25.2% |

**AUC 0.483（95%CI [0.434, 0.534]）＝情報なし。** しかも向きがわずかに逆。
正体は式のとおりで、**本命が人気薄なほど数字が上がる**
（confと軸の人気順位の相関 **+0.382**）。
つまり「AIの自信」ではなく「**AIが市場と食い違っている度合い**」を
自信として見せていた。「AI 96%」と表示されたレースでも軸の3着内は53.4%で、
「AI 62%」の55.0%と変わらない。

2026-08-07⑥の「ROI予測 ~150%」固定値、2026-08-09①の単勝EV表示と同じ型
（**作り話をしない**）なので、同じ判断でバッジを削除した。★推奨ラベルは残す。
`tests/test_axis_confidence_display.py` 新規3テスト（修正前は実際に失敗する）。

##### 判定
- **軸の確度の較正は「直す」対象ではない。** 情報が無いものは較正できない
- `MIN_AXIS_FUKU_PROB = 0.55` は**現状維持**。この閾値の根拠は 2026-08-08② の
  「下位半分はROIが一貫して悪い」であって較正ではない。今朝の分解どおり、
  その差は的中率ではなく**配当側**から来ている（AUC 0.548 と整合する）
- ⚠ **市場オッズの方が解像度が高い（0.661）が、それは買う理由にならない**。
  市場が正確なぶんは配当が縮む（North Star #9）。オッズ帯フィルタは
  2026-07-30 に否定済み

##### この検査手法は再利用できる
**「再較正で直るか」を判定するには、まずAUC（解像度）を見ること。**
AUC≈0.5 なら、どんな較正手法を持ってきても水準が平らになるだけで終わる。
較正（水準）と解像度（順序）は別物で、直せるのは前者だけ。


#### 🔴 C-2：土曜夜の日曜予想は「オッズが半分欠けていた」のではなく**単勝ではない値を掴んでいた**

「土曜夜だけオッズ取得率が46〜48%に落ちる」という既知の課題を調べたところ、
**取得率の問題ではなく、混入していた値が単勝オッズですらなかった**と判明した。

##### まず全世代の取得率を並べた（`latest.json` の git履歴76世代）
`git fetch --unshallow` 済みなので、本番が生成した全世代を直接読める。

| 実行 | オッズ取得率 |
|---|---|
| 金曜夜（→土曜予想） | 99.6〜100% |
| 土朝・日朝の refresh | 100% |
| **土曜夜（→日曜予想）** | **46.2 / 46.9 / 48.0 / 49.6 / 52.0 / 52.0 / 56.4%** |

⚠ **例外なく毎回**。2026-05-30 まで遡って土曜夜の生成だけが落ちている。
かつ直近4回は `data_quality.odds_coverage = 0.0` ＝**専用オッズページからは
1頭も取れていない**。残りの47%は `build_market_odds_from_races()` による
**出馬表側のオッズでの補完**だった（`weekend.py` の fallback）。

##### 🔴 その補完値が単勝オッズではなかった
2026-08-15 土曜夜の日曜予想を、翌朝の確定オッズ（100%取得）と突合した:

| | |
|---|---|
| 1番人気が翌朝と一致したレース | **4 / 17** |
| オッズの log相関 | **+0.24** |
| 土夜/日朝 の比の中央値 | **0.145** |

本物の早期オッズなら一致率は9割方になるはずで、これは別物である。
実物を見ると一目瞭然だった:

```
中京記念   Σ(1/オッズ)=1.26  → 4.1/4.9/7.4/8.7倍   翌朝 3.8/5.9/7.4/7.4倍  ✅本物
長久手特別 Σ(1/オッズ)=3.03  → 2.1/2.1/2.2/2.3倍   翌朝 2.8/43.6/8.3/3.2倍 ❌
大垣特別   Σ(1/オッズ)=7.16  → 全16頭が2.0〜2.2倍  翌朝 12.0/25.1/8.8/113.4倍 ❌
```

##### 🔑 モデルを使わずに判定できる：Σ(1/オッズ)
単勝オッズ盤は控除率20%なので **Σ(1/オッズ) ≈ 1/(1-0.20) = 1.25** になる。
全76世代・2,041レースで測ると**完全に二峰に分かれた**:

| | N | Σ(1/オッズ) |
|---|---|---|
| 正常な盤 | 1,828 | 中央値 **1.259** / 5〜95%点 1.223〜1.279 / **最大 1.577** |
| 壊れた盤 | 213 | 中央値 **8.742** / **最小 1.714** / 最大 62.50 |

**1.577〜1.714 が空白帯**。しかも壊れた213レースは**11世代すべてが土曜夜の生成**で、
金曜夜・日曜朝の生成には1件も無い。

##### 対応：盤ごとの妥当性検査を追加（`_sanitize_odds_book`）
1頭ずつ見る既存の `_sanitize_win_odds`（1.0倍未満を弾く。2026-07-27⑧）では
**全馬が2.0倍という壊れ方は素通りする**。盤全体の Σ を見る検査を
`calc_all` の popularity 導出**前**に追加した（閾値 **1.65**＝空白帯の中間）。

- 壊れていた場合は**そのレースのオッズを丸ごと None** にする。
  半端に残すと popularity（＝base_margin）が誤った順位で確定し、
  「オッズ不明」より悪い状態になるため
- ⚠ **上限のみを見る**。一部の馬しかオッズを持たない部分的な盤は Σ が
  必ず小さくなるので、下限で弾くと正常な部分取得を誤検知する

##### 実データでの効果（2026-08-15 土曜夜）
| | 修正前 | 修正後 |
|---|---|---|
| オッズを持っていたレース | 17 | 2 |
| **翌朝の1番人気と一致** | **4 / 17** | **2 / 2** |

壊れた15レースを無効化し、残した2レースは**両方とも**翌朝と一致した。

##### ⚠ これは封じ込めであって根治ではない
専用オッズページが土曜夜に全滅する**原因そのものは未解明**
（`find_r01_odds` が256件すべて「パラメータエラー」）。金曜夜は同じコードで
成功するので、JRA側で日曜レースのオッズ盤が土曜夜時点ではまだ別の場所にある、
等の可能性がある。今回直したのは「壊れた値が popularity と base_margin を
汚すこと」で、日曜朝の refresh で100%に復旧する点は変わらない。

⚠ **土曜夜の日曜予想は、オッズが無い前提で見ること。**
アプリは `odds_coverage=0.0` で警告を出す（既存機能）。
