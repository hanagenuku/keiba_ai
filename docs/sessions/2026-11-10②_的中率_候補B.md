### 分かったこと

1. **機序は完全に再現した。** P0 の `best_iteration` は 3窓×3シードの**9回すべて 10**。
   窓も内側HOも違うのに1本も動かない。本物の信号を1列注入しても 10〜11 のまま
   （P1 は 79〜208、P2 は 325〜720 に伸びる）。→ 止めているのは信号ではなく**切片**。
   記録にあった「base_margin が土台なので10本で飽和」は**誤り**（`CLAUDE.md` §4 を訂正）。
2. **直しても効かない理由も分かった。** 本番は `Booster.predict()` の既定＝**全木**で予測していて、
   止まったあとの50本が順位の信号を担っている。
   P0 の全木 **0.7879** vs `best_iteration` まで **0.7799**（**+0.0080**）。
   → 順位の面では**すでに「直った状態」で動いていた**。
3. 🔴 **ただしそれは偶然に助けられた状態で脆い。** `requirements.txt` は xgboost の版を
   固定していないので、既定が `best_iteration` までに変わると本番の AUC が 0.008 静かに落ちる。
   → `engine.py` の推論で使う本数を**今の挙動（全木）のまま明示**し、テストで固定した。
   **予想は1つも変わらない**（既定と明示が本番モデルでビット単位で一致することをテストが確かめる）。
4. 🟡 **較正は本当に壊れている**（Brier 0.1826 → 0.1420・LogLoss 0.5461 → 0.4402）。
   ただし**採用基準に入れていない指標**なので採用根拠にしない。実害の大きさも測っていない。
5. 🔑 対照群B-2（本物の信号を注入）で **P0 は P1/P2 の 94% を回収**（+0.0212 vs +0.0226/+0.0223）。
   → 「過去の特徴量検証は学習設定のせいで不当に否定された」とは**読めない**。
   指示書 §1-2 の約束どおり、**閉じた検証（websig・oikiri・D-2 など）は開け直さない**。

## 自分の失敗（記録）

**対照群A-2 を登録した形が構造的に成立していなかった**（同型 family の4度目）。
統計量が `ROI(無作為な軸) − ROI(P0)` なので、P0 に実力がある限り帰無は負になるのが当然で、
「帰無が0中心」という合格線は通りえない。`logic2026/eval.py` の対照群Aを再利用したとき、
**そこに書いてある警告を読んだのに合格線だけ β係数用のものを流用した**。
結果を見てから測定器を足し直していない。読める事実は
「P0 は無作為より +11.92pt 上（並べ替え P=0.0950）」まで。
判定は基準1 に乗っており、この欠陥とは無関係に成立する。

🔑 次に並べ替え対照群を書くときは、**統計量ごとに「何の帰無か」を決めてから合格線を書く**。
A-1（アームの割り当てを入れ替える形）は帰無が構造的に0中心になった（実測 ±1e-6）。
