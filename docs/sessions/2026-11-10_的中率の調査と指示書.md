# 2026-11-10: 的中率を上げる余地を調べ、Claude Code 向けの指示書を書いた

## ユーザーの指示

「現状の予想システムの的中率を上げる方法を探って、改善の余地があればクロードコードへの指示書を書いて」

## 何をしたか

- 既存の記録（`data/stats.json`・`logic2026/RESULTS.md`・撤回表）から現在地と、まだ試していない筋を洗い出した。
- 本番モデルのファイルを調べ（`hitrate/inspect_model.py`）、合成データで機序を再現した（`hitrate/synth_es.py`）。**実データでの測定はしていない。本番は変えていない。**
- 指示書 `hitrate/INSTRUCTIONS.md` を書いた。測る候補は2件:
  - **B**: 学習の early stopping が切片で止まっている件を直すと OOS の順位付けが良くなるか
  - **A**: ◎が4番人気以下になるレースで軸を1番人気に替えると、的中率が上がり回収率は下がらないか

## 分かった事実

- 本番モデルは木61本・`best_iteration=10`。各木の出力の大半は全馬一律の移動（累計 +2.68 logit）で、馬間の差は木1本あたり SD 0.01〜0.06。
- `best_iteration` が常に 10〜11 になるのは、勝率スケールの `base_margin`・`scale_pos_weight`・重みなし logloss の組み合わせで**切片が最適点を通過する時点**が決まるため。合成データでは信号がゼロでも大きくても 10〜11 で止まった。
- したがって「10本で飽和する」という過去の説明（2026-08-24・10-19 ほか）は誤り。`CLAUDE.md` §4 と `docs/ARCHITECTURE.md` の該当箇所を直した。
- ⚠ 直した場合の効果は未測定。合成データでは AUC の差は 0〜+0.003 で、大きくは期待できない。
