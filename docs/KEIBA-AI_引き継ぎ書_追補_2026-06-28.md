## 🔑 最重要トピック（2026-07-27時点）

### ① 🔴 買い目フィルタは大規模検証で否定され、無効化された（最重要）

7/27に「人気×RL乖離マトリクス」による買い目フィルタを導入したが、
翌日の**約2,000レース規模のout-of-sample検証で否定**され、
**2026-07-28にデフォルトOFF**にした。

| 検証結果（2026-03〜06、470R測定） | |
|---|---|
| **本番の主戦場(2-9人気)でのboost回収率** | **71.3%**（552点） |
| 全boost | 84.0%（1,031点） |
| neutral | 61.9% |
| プラスだった開催日 | 15日中5日（33%） |

**本番でboost判定していた2セルが両方とも崩れた**:
- 市場6-9人気×RL4-5: 検証前半164.3% → **後半86.0%**
- 市場2-3人気×RL4-5: 検証では最初から**SUPPRESS(45.9%)**

本番データで見えていたROI 182.8%は、**4開催日・76点の偶然**だった。

**現在の状態**:
- 単勝・複勝は**従来ロジックに復帰**（RL上位3頭から1点／RL上位5頭から2点）
- マトリクスの**測定機能は残っている**（stats.json / divergence_weekly.json）
- `RANK_MATRIX_FILTER=1` で再有効化できるが、**必ず大規模検証をやり直すこと**
  （`KEIBA_買い目フィルタ検証_v1.ipynb`）

⚠ **正直な現状認識**: 「フィルタが効かない」だけでなく、
**現時点で利益の出る単勝戦略は存在しない**。従来ロジックも本番94.8%・
検証neutral 61.9%と控除率を超えられていない。

### ② 残差モデルの raw_margin が2重sigmoidだった（重大バグ・修正済み）

`Booster.predict()` は `output_margin=True` 無しでは**sigmoid適用済みの確率**を返すが、
これを "raw_margin" として扱い更にsigmoidを掛けていた。

| base_margin | 修正前のprob | 本来のprob |
|---|---|---|
| -1.5 | 0.6969 | 0.8328 |
| 0.0 | 0.7225 | 0.9571 |
| +1.5 | 0.7291 | 0.9901 |

sigmoidは単調関数のため**AUCでは検出できず**、較正層(Isotonic)が入っていた
`cal_prob` は結果的に救われていた可能性が高い。ただし較正層を経由しない
`rating`（Gumbelシミュレーション入力）は直接影響を受けていた。

**⚠ 要フォローアップ**: `DEFAULT_GUMBEL_RATING_T = 2.5` は旧（潰れた）スケールを
基準に最適化された値で、修正後の残差モデルに対して未検証。

### ③ オッズ取得失敗が継続的リスクとして残っている

`find_r01_odds()` が全滅する障害が複数回発生（2026-06-28 / 07-05 / **07-26**）。
症状は「オッズ欠損」と「0.1〜0.2倍のゴミ値」が**同時に出る**（同一原因の2症状）。
7/26は420頭中183頭(43.6%)欠損・45頭がゴミ値だった。

- **対症療法は実装済み**: 1.0倍未満を弾くバリデーション（入口＋安全網の2箇所）
- **根本原因は未修正**: 診断ログを追加しただけ。次回発生時にログから特定する
- 🔑 **この種の障害を調査する時は、DBではなく `data/latest.json` のgit履歴を辿ること**
  （`race_predictions` はrefreshで上書きされ、DBには修復後の姿しか残らない）

### ④ 残差学習モデルは引き続き本番稼働中

- `f_popularity` を除外し `logit(市場確率)` を固定ベースラインとして渡す構造
- AUC維持率99.5%（通常0.8017 vs 残差0.7974）
- **⚠ market_correction.py は廃止済み（存在しない）**
