### ✅ 唯一の収穫：レース毎の自信度は市場を上回る

「どの馬が勝つか」では市場に +0.0009 しか勝てないのに、
**「このレースは当てやすいか」では市場を上回る**（AUC 0.6041 vs 市場のみ0.5708）。
市場だけの自信度との相関は +0.507 で言い換えではない。
市場の自信度で4分割した**どの層でもAIの自信度が効く**（0.577〜0.592）。

⚠ **当てやすさであって儲けやすさではない**（最上位帯でも複勝回収91.2%）。
画面には「軸3着内 xx%」として表示済み。**低いから見送る、として使う。**

## 🔑 検証をやるときに必ず置く5つの関門（2026-08-17に確立）

展開の検証で**計測器を9回壊した**。うち7回はこの関門が止めた。
関門が無ければ「37件の勝ち筋を発見」と誤報告するところだった。

1. **対照群**（測りたい性質と無関係な分割）が期待値付近になるか
2. **較正チェック**（層別も。脚質・騎手・コース適性・スピードで各2pt以内）
3. **合格基準を結果を見る前に宣言する**
4. **年をまたいだ再現**（同じ年の中で割っても同じ癖を2回数えるだけ）
5. **核心部分は投入前に単体検算**

さらに:
- 🔑 **プラセボ対照（値のシャッフル）はリーク検出に使えない**。
  本物のシグナルもリークも同じように消えるため（2026-08-08の教訓）
- 🔑 確実なのは**同じ特徴量を別実装で作って値を突合すること**
- 🔑 **集計キーにレース識別子が入っているか毎回確認**（2026-08-03に落として的中率97.7%という嘘を出した）
- 🔑 **払戻の集計では「的中したのに配当が取れていない行」を必ず数える**。
  0円として黙って混ぜると実力を過小評価する方向に静かにずれる（2026-08-18）
- 🔑 **多重比較を申告する**。25マス見れば全部が実力80%でも偶然100%超が出る

### ② 残差モデルの raw_margin が2重sigmoidだった（重大バグ・修正済み）

`Booster.predict()` は `output_margin=True` 無しでは**sigmoid適用済みの確率**を返すが、
これを "raw_margin" として扱い更にsigmoidを掛けていた。

| base_margin | 修正前のprob | 本来のprob |
|---|---|---|
| -1.5 | 0.6969 | 0.8328 |
| 0.0 | 0.7225 | 0.9571 |
| +1.5 | 0.7291 | 0.9901 |

sigmoidは単調関数のため**AUCでは検出できず**、較正層(Isotonic)が入っていた
`cal_prob` は結果的に救われていた可能性が高い。ただし較正層を経由しない
`rating`（Gumbelシミュレーション入力）は直接影響を受けていた。

**⚠ 要フォローアップ**: `DEFAULT_GUMBEL_RATING_T = 2.5` は旧（潰れた）スケールを
基準に最適化された値で、修正後の残差モデルに対して未検証。

`find_r01_odds()` が全滅する障害が複数回発生（2026-06-28 / 07-05 / **07-26**）。
症状は「オッズ欠損」と「0.1〜0.2倍のゴミ値」が**同時に出る**（同一原因の2症状）。
7/26は420頭中183頭(43.6%)欠損・45頭がゴミ値だった。

- **対症療法は実装済み**: 1.0倍未満を弾くバリデーション（入口＋安全網の2箇所）
- **根本原因は未修正**: 診断ログを追加しただけ。次回発生時にログから特定する
- 🔑 **この種の障害を調査する時は、DBではなく `data/latest.json` のgit履歴を辿ること**
  （`race_predictions` はrefreshで上書きされ、DBには修復後の姿しか残らない）

### ④ 残差学習モデルは引き続き本番稼働中

```

    ↑ latest.json / stats.json

    ↓ main checkout → 実行
```
