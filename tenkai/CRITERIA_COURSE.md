# T'-C: コースの物理情報を入れてからペースモデルを測り直す

⚠ **結果を見る前に書いた。** 数字を見てから基準を足さない。

## なぜやり直すか（ユーザー指摘）

前回「条件だけで RMSE 0.827s、馬特徴を足しても改善しない」という結果から
**「ペースはレース条件だけで決まる」と書いたが、これは結論を急ぎすぎている。**

実際に入っていた条件は **4列だけ**だった:

```
PACE_COLS = ['dist', 'surface_num', 'cls', 'n_horses']
```

🔴 **競馬場が入っていない。** 中山芝1600m と 東京芝1600m が同じ入力になっていた。
コースの物理情報（直線長・坂・コーナー・内外回り・ダートの芝スタート・
スタートから1角までの距離）も1つも入っていない。

したがって前回言えるのは
**「この4列の下では、馬特徴の追加価値を確認できなかった」**までであり、
「馬特徴は不要」でも「ペースは条件で決まる」でもない。

## 測る順序

同じ窓・同じ行で、**階段状に**足して測る。

```
M0  いまの4列                    dist, surface_num, cls, n_horses
M1  + 競馬場                     venue（10場）
M2  + コースの静的特徴             直線長・回り・坂の有無と高低差・コースタイプ・
                                コーナーのタイト度・内外回り・ダートの芝スタート
M3  + スタート→1角の距離           course_physical.json の official + stated のみ
M4  + 馬特徴（前回悪化した群）       P(先頭)の分布・過去の通過位置・過去の上がり
```

🔑 **M4 がこの検証の主目的。** 条件側を強くしてから馬特徴を測り直す。
前回の「馬特徴は悪化させる」が、条件の指定不足（＝馬特徴が欠けたコース情報の
代理になっていた）に由来していたのかを切り分ける。

## 出典の扱い（ユーザーの明示指示）

> 約○mと書かれていない距離について、推定値を勝手にfeatureとして採用しないこと。

`course_physical.json` の `distances` は 19組のみ（official 5 / stated 13 / na 1）。
**`web` 由来と未確定は数値として入れない**。該当しない (会場,馬場,距離) は
**欠測(NaN)のまま**渡し、XGBoost の欠測分岐に任せる。
⚠ 欠測を平均値などで埋めない。埋めた瞬間「推定値を採用した」ことになる。

## 窓

学習 ≤ 各窓の train_end / 検定はその後。**2窓**で同符号を要求する。

```
窓A  学習 ≤2025-12-31  検定 2026-01-01〜2026-06-30
窓B  学習 ≤2026-06-30  検定 2026-07-01〜
```

## 事前に決めた判定

1. **M1/M2/M3 は、2窓とも RMSE が下がったものだけ採用する。** 片方だけなら採らない。
2. **M4（馬特徴）は 2窓とも下がったときだけ「効く」と書く。**
   前回と同じく悪化したら「条件を強くしても効かなかった」と書く。
   ⚠ **ただし「馬特徴は不要」とは書かない。** 書いてよいのは
   「この条件セットの下では追加価値を確認できなかった」まで。
3. **改善幅は秒で書く。** RMSE が 0.01s 未満しか動かないものは
   「測定できない大きさ」と書き、採用しない（列を増やすコストに見合わない）。
4. **3分類の精度も併記する**（旧モデルとの比較のため）。ただし判定は RMSE で行う。
5. 🔴 **もし M3 が大きく効いたら（-0.05s 以上）、喜ぶ前に出典を疑う。**
   19組しか無い列が全体の RMSE を大きく動かすのは、その19組が
   特定の会場・距離に偏っていることの裏返しでありうる（＝会場ダミーの代理）。
   その場合は M2（会場・静的特徴あり）との差で見る。
6. **回収率は見ない。** 目的は展開予想そのものの精度。
