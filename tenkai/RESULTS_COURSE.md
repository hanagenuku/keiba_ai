# T'-C: コースの物理情報を入れてペースモデルを測り直した（2026-09-15）

基準は `tenkai/CRITERIA_COURSE.md` に**結果を見る前に**書いた。

## きっかけ（ユーザー指摘）

> 条件だけでRMSE 0.827秒／馬特徴を追加しても改善しない、となったので
> 「ペースは条件だけでほぼ決まる」と結論を急がない方がいいです。
> 今の条件特徴に、距離・コース・芝/ダート・枠・頭数・その他がどこまで
> 入っているのかを確認したい。

確認したら、**入っていたのは4列だけ**だった:

```
PACE_COLS = ['dist', 'surface_num', 'cls', 'n_horses']
```

🔴 **競馬場が入っていない。** 中山芝1600m と 東京芝1600m が同じ入力。
コースの物理情報（直線長・坂・コーナー・内外回り・ダートの芝スタート・
スタート→1角）も1つも入っていない。指摘のとおり、
前回の結果から言えるのは「**この4列の下では**馬特徴の追加価値を確認できなかった」までだった。

⚠ 最後の1つはユーザーが明示的に釘を刺した箇所:
> 約○mと書かれていない距離について、推定値を勝手にfeatureとして採用しないこと。

なので **official と stated だけ**を数値として渡し、それ以外は**欠測(NaN)のまま**
XGBoost の欠測分岐に任せた。平均等で埋めていない。

### 序数 vs one-hot

```
M1  競馬場を序数(venue_idx)   窓A 0.7668   窓B 0.8054
M1h 競馬場を one-hot         窓A 0.7638   窓B 0.7980   ← 両窓とも良い
```
順序の無いカテゴリを序数で入れると **窓B で 0.0074s 損**していた。one-hot を採る。

## 判定（事前登録した基準に照らして）

| | 判定 |
|---|---|
| **M1h 競馬場** | ✅ **採用**。両窓で −0.049〜−0.071s、シード幅（0.004）の12〜18倍 |
| M2h コース静的 | ❌ 不採用。基準1（両窓で改善）に不一致、かつ基準3（0.01s以上）も未達 |
| M3h スタート→1角 | ❌ 不採用。両窓で改善だが 0.004s / 0.0006s で基準3未達 |
| M4h 馬特徴 | ❌ 効かなかった（両窓で悪化） |

## 🔑 なぜコースの物理情報が効かないのか（機序）

**会場を one-hot で入れた瞬間、コースの物理情報はほぼ定数になるから。**
直線長も坂も回りも、会場（＋内外回り）が決まればほぼ一意に決まる。
one-hot は「その会場の前半600mの癖」を丸ごと覚えるので、
物理情報が持つ一般化（未見の会場×距離への外挿）は、
学習データが十分ある限り出番が無い。

⚠ したがって「コースの物理情報は無意味」ではない。正確には
**「いまのデータ量では、会場ダミーと区別できない」**。
新コース・観測の薄い組み合わせでは効きうるが、今回のデータでは測れない。

⚠ `start_to_corner_m` は19組しか埋まっていない。基準5に書いたとおり
「19組が大きく効いたら会場ダミーの代理を疑え」だが、実際には
**M2h の後では 0.004s / 0.0006s しか動かず**、疑う必要すら無かった。

## 🔴 前回の書き方を訂正した

| 前 | 後 |
|---|---|
| 「ペースは**レース条件だけ**で決める」 | 「この条件セットの下では、馬特徴の追加価値を確認できなかった」 |
| 「馬特徴は足すと悪化する」 | 同左（事実）。ただし**「馬特徴は不要」とは書かない** |

条件側を 4列 → 14列に強くしても M4h は両窓で悪化した（+0.0195 / +0.0149）ので、
**「条件の指定不足が原因で馬特徴が効かなく見えていた」わけではなかった**と分かった。
しかしそれは「馬特徴がペースに無関係」を意味しない。いま測れているのは
`P(先頭)の分布・過去の通過位置・過去の上がり` という**特定の作り方**だけである。

## 残っている問い（今回は触っていない）

1. **3分類の閾値を会場ごとにするか。** いまは `表面×距離帯`のパーセンタイル。
   予測が会場を知るようになった以上、「ハイ/スロー」を**その会場の基準**で
   測るべきかもしれない。ただし変えると `f_pace_prob_*` の意味自体が変わるので、
   本体モデルへの影響を測ってからにする。推測で決めない。
2. **枠順**（ユーザーが挙げた項目）はレース単位の量ではないので、
   ここではなく馬特徴側（`draw` は P(先頭) モデルに既に入っている）。
3. 段1の `P(先頭)`（OOS AUC 0.7805）は**ペースには使わないが本体モデルには未測定**。

## 本体モデル（3着内）への波及

会場入りペースにしたので `f_pace_*` の値がまた動く。`tenkai/AB.md` と同じ基準で測った。
検定窓 2026-07-01〜 9,728頭 / 740レース。

```
                                        AUC      Brier    LogLoss
D 現本番（会場なしペースで学習） × 新特徴量    0.7828   0.1844   0.5510
E 新モデル seed=42（採用）× 新特徴量        0.7830   0.1840   0.5503
E 新モデル seed=7                        0.7837   0.1835   0.5489
E 新モデル seed=2026                      0.7829   0.1842   0.5504

  E(3シード平均) − D : AUC +0.0004   最悪シード − D : +0.0001
  Brier  E 0.1839 vs D 0.1844      LogLoss E 0.5499 vs D 0.5510
```

- 基準②（平均で上回る・最悪シードでも下回らない）✅ → 差し替え
- 基準③（Brier/LogLoss も同方向）✅ 3シードとも良い

🔑 **本体の AUC は +0.0004 で、ほぼ動かない。** これは想定どおりで、
2026-08-27 のオラクル測定「**完璧な**ペース予測でも +0.0007」の範囲内。
⚠ D が新特徴量でも 0.7828 のまま（旧特徴量でも 0.7828）なので、
   **食い違いの代償はここでも測定できない大きさ**だった。

**今回の成果はペース予測そのもの**（RMSE -6.0% / 3分類 +4.1pt）であって、
3着内の当てやすさではない。ユーザーの指示「まず予測の精度を上げる。
展開予想の精度をあげる」に対する成果はそちら側にある。

⚠ `cal_prob` のレース別合計は 2.435 → 3.117（理論3.0）に上がった。
   穴マーク（`cal_prob>=0.15`）が付く馬が増える方向。表示のみの変化。
