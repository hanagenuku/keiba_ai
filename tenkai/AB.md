# T'-AB: 展開予想の差し替えが本体モデル（3着内）に何をするか

⚠ **結果を見る前に書いた。** 数字を見てから基準を足さない。

## 何を測るか

2026-09-15 に2つ変更した。どちらも `calc_features_for_xgb` が返す値を動かす。

| 変更 | 動く特徴量 |
|---|---|
| ① 内回り/外回りを分けて引く（PR #256） | `f_straight_match` / `f_course_*` 系（京都・阪神・新潟の芝 407レース） |
| ② ペースを条件だけの実数予測に差し替え | `f_pace_prob_fast` / `f_pace_prob_slow` / `f_pace_x_style` / `f_pace` / `f_pace_fit` / `f_style_total_fit` とその相対列 |

学習側（`build_training_data`）も推論側（`calc_all`）も同じ関数を通るので、
**両方まとめて作り直せばパリティは保たれる**。問題は
**いま本番に載っているモデルは①②の前の値で学習されている**こと。

## 測る3本

学習 ≤2026-06-30 / 検定 2026-07-01〜（本番と同じ構成・134特徴量・residual・
ドリフト注入ON）。同じ検定窓・同じ行で比べる。

```
A  旧モデル × 旧特徴量     ← ①②を入れる前の本番
B  旧モデル × 新特徴量     ← いま main にマージすると起きる状態
C  新モデル × 新特徴量     ← 作り直した場合
```

- **B − A** = 食い違いの代償。
- **C − B** = 作り直す価値。

## 事前に決めた判定

1. **B − A が −0.002 AUC より悪ければ、再学習を必須にする**（本番モデルを差し替える）。
   それより小さければ「食い違いの代償は測定不能」とし、差し替えは②の基準で決める。
2. **C を本番に差し替えるのは、3シード平均で C > B かつ最悪シードでも C >= B のときだけ。**
   `train_xgb` の採用ゲート（旧AUC以上）と同じ向き。
3. **Brier / LogLoss は事前に見る指標として登録する**（数字を見てから選ばない）。
   AUC と符号が食い違ったら「引き分け」と書き、AUC を優先する。
4. **回収率は見ない。** 今回の目的は展開予想の精度で、North Star #9 のとおり
   AUC が上がっても回収率が上がる保証はない。上がったとも書かない。
