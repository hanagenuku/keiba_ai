# T'-AB: 展開予想の差し替えが本体モデル（3着内）に何をするか

⚠ **結果を見る前に書いた。** 数字を見てから基準を足さない。

## 何を測るか

2026-09-15 に2つ変更した。どちらも `calc_features_for_xgb` が返す値を動かす。

| 変更 | 動く特徴量 |
|---|---|
| ① 内回り/外回りを分けて引く（PR #256） | `f_straight_match` / `f_course_*` 系（京都・阪神・新潟の芝 407レース） |
| ② ペースを条件だけの実数予測に差し替え | `f_pace_prob_fast` / `f_pace_prob_slow` / `f_pace_x_style` / `f_pace` / `f_pace_fit` / `f_style_total_fit` とその相対列 |

学習側（`build_training_data`）も推論側（`calc_all`）も同じ関数を通るので、
**両方まとめて作り直せばパリティは保たれる**。問題は
**いま本番に載っているモデルは①②の前の値で学習されている**こと。

## 測る3本

学習 ≤2026-06-30 / 検定 2026-07-01〜（本番と同じ構成・134特徴量・residual・
ドリフト注入ON）。同じ検定窓・同じ行で比べる。

```
A  旧モデル × 旧特徴量     ← ①②を入れる前の本番
B  旧モデル × 新特徴量     ← いま main にマージすると起きる状態
C  新モデル × 新特徴量     ← 作り直した場合
```

- **B − A** = 食い違いの代償。
- **C − B** = 作り直す価値。

## 事前に決めた判定

1. **B − A が −0.002 AUC より悪ければ、再学習を必須にする**（本番モデルを差し替える）。
   それより小さければ「食い違いの代償は測定不能」とし、差し替えは②の基準で決める。
2. **C を本番に差し替えるのは、3シード平均で C > B かつ最悪シードでも C >= B のときだけ。**
   `train_xgb` の採用ゲート（旧AUC以上）と同じ向き。
3. **Brier / LogLoss は事前に見る指標として登録する**（数字を見てから選ばない）。
   AUC と符号が食い違ったら「引き分け」と書き、AUC を優先する。
4. **回収率は見ない。** 今回の目的は展開予想の精度で、North Star #9 のとおり
   AUC が上がっても回収率が上がる保証はない。上がったとも書かない。

## 参考（期待値を先に書いておく）

- 2026-08-27 のオラクル測定では「**完璧な**ペース予測でも +0.0007」。
- 2026-08-26 では展開系29特徴量を**全部抜いても −0.0001**。
- よって **本体AUCはほぼ動かないと予想する**。動かないこと自体は失敗ではない
  （目的は展開予想そのものの精度と、パリティ違反の除去）。
  ⚠ もし +0.005 以上動いたら、喜ぶ前にリークを疑うこと（North Star #8）。

## 事前登録した判定に照らすと

| 基準 | 結果 |
|---|---|
| ① B − A が −0.002 AUC より悪ければ再学習を必須 | **該当せず**（−0.0001）。食い違いの代償は測定できない大きさ |
| ② C > B（3シード平均）かつ最悪シードでも C >= B | **満たす**（+0.0007 / +0.0001）→ 差し替えてよい |
| ③ Brier / LogLoss も同方向か | **同方向**。3シードとも B より明確に良い（Brier −0.0016 / LogLoss −0.0048） |
| ④ 回収率は見ない | 見ていない |

→ **seed=42 を本番に差し替えた。** seed=7 のほうが AUC は高いが、
   数字を見てから選ぶことになるので採らない（`monthly_retrain.py` の既定と同じ 42）。

## 🔑 AUC はほぼ引き分け。動いたのは確率の水準のほう

事前に「本体AUCはほぼ動かないと予想する」と書いたとおりになった
（2026-08-27 の天井測定「完璧なペース予測でも +0.0007」と一致）。
**シードの振れ幅 0.0013 のほうが平均の差 0.0007 より大きい**ので、
AUC の差は引き分けと読むのが正直。

一貫しているのは **Brier / LogLoss で、3シードとも B より良い**（相対 0.9%）。
機序もはっきりしている: `f_pace_prob_slow` の平均が 0.184 → 0.314 と
**分布ごと動いている**ので、旧モデルは順位（AUC）はほぼ保てても
**確率の水準**を外す。C はその分布で学習し直しているので戻る。

## cal_prob の水準（穴マーク閾値 0.15 に効く）

```
旧 model + 旧 calibrator : 平均 0.1901  レース別合計の中央値 2.524  cal>=0.15 40.9%
新 model + 新 calibrator : 平均 0.1833  レース別合計の中央値 2.435  cal>=0.15 39.3%
（実測複勝率 0.2284 / 理論上のレース別合計 3.0）
```
穴マークが付く馬は **40.9% → 39.3%** とわずかに減る。表示だけの変化。

## ⚠ この測定でやらかしたこと（記録）

1. **「隔離したワークスペース」が隔離できていなかった。** `ws/data` を
   リポジトリの `data/` へのシンボリックリンクで作ったため、`train_xgb` の
   保存がリンクを貫通して**リポジトリのモデルファイルを書き換えていた**。
   幸い A/B の測定は `xgb_fukusho_model.pkl`（残差モードでは書かれない名前）を
   読んでおり、md5 で旧モデル（`2b9429fa…`）だったことを確認済み。
   数字に影響は無いが、隔離のつもりが隔離になっていなかったのは事実。
2. **最初、A/B と C を別々のハーネスで測って比べかけた。** base_margin の
   ドリフト注入は行ごとに `rng.choice` を引くので、**行の並び順が違うと
   別の乱数列**になる。実際 AUC が 0.0016 動いた（C の 0.7844 と 0.7828 の差）。
   3本を同じ bm ベクトルで測り直した。
3. **`train_xgb` の採用ゲートに3回目のシードが弾かれていた**のに気づかず、
   seed=2026 として seed=7 のモデルを測っていた（両者の数字が小数点以下4桁まで
   完全一致したことで発覚）。ゲートを外して測り直した。
