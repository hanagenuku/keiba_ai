# T'-G: 物理特徴に「未見コースへの一般化能力」はあるか

⚠ **結果を見る前に書いた。**

## 問い（ユーザー提示の④）

> 会場×実距離の経験値だけで予測 vs 物理特徴から予測 を比較する。
> これなら初めて「物理的なコース情報には、未知・希少なコースへの
> 一般化能力があるのか？」を検証できる。

診断で分かっていること:
- 前半600mのクセの **97%** は「(会場,馬場,実距離) ごとの固定オフセット」
- 会場 one-hot は**学習期に見たコースの癖を丸ごと覚える**ことでそれを再現している
- 手持ちの物理量はそのオフセットを**説明できない**（全部 |ρ|<=0.26）

→ **見たことのあるコースでは物理特徴の出番が無い。** 出番があるとすれば
  **学習期に無かった (会場,馬場,実距離)** を予測するとき。

## 測り方: leave-one-course-out

```
対象     data/course_starts.json に物理データがあり、実データが十分ある
        (会場, 馬場, 実距離) の組み合わせ
手順     その組み合わせを**学習から丸ごと外して**モデルを作り、その組み合わせだけを予測する
A       base4 + 会場 one-hot            ← 会場は知っているが、その距離の癖は知らない
B       A + 物理特徴                    ← 物理構造から推測できるか
```

⚠ A も会場 one-hot を持つので、「同じ会場の別距離」からある程度は推測できる。
   これは意図的。**物理特徴が会場ダミーに**上乗せ**するか**を見たい。

## 物理特徴（`data/course_starts.json` から）

数値は **official + stated のみ**（ユーザー指示）。カテゴリは資料の記述。
```
start_to_first_corner_m   官製+記載の18組のみ。他は欠測のまま
first_corner              1/2/3/4
start_location            向正面/正面スタンド前/ポケット/引込線/コーナー間 …
start_slope               上り/下り
loop                      内回り/外回り/直線
spiral_corner             有無
turf_start                ダートの芝スタート
+ 会場×馬場の共通量        直線長・高低差・1周距離
```

## 事前に決めた判定

1. **全体**: 未見コースの RMSE が **B < A**。
2. **一貫性**: 個別の組み合わせで **B < A が過半**。
3. **大きさ**: 全体の改善が **0.01s 以上**。未満なら「測定できない大きさ」。
4. **対照群**: 物理特徴を組み合わせ間でシャッフルすると効果が消えること。
   消えなければ、効いているのは物理量ではなく「列が増えたこと」。
5. **⚠ 逆向きの確認（前回の反省）**: 本物の効果を注入したら検出できるか。
   物理量に「真のオフセット」を1列足したら B が明確に A を下回ることを確認する。
   下回らなければ計測器が弱すぎる。
6. **セルの大きさ**: 対象は実データ **n>=30レース** の組み合わせ。

## ⚠ 期待値を先に書いておく

物理データは **数値が18組しか無く、残りはカテゴリ**。カテゴリ（スタート地点・
コーナー番号）は会場と強く相関するので、会場 one-hot の上では情報が薄いはず。
**動かないと予想する。** 動いたら、それが「会場ダミーの代理」でないかを疑う。

---

# 結果（2026-09-15）

物理データがあり n>=30R の組み合わせ **46**（対象 2,902レース）。
⚠ うち数値（スタート→1角）が埋まっているのは **17/46**。残りはカテゴリ。

```
A  会場one-hotのみ        0.9161s
B  + 物理特徴(31列)       0.8711s   A比 -0.0450s
注入 真のオフセットを渡す     0.7712s   A比 -0.1449s   ← 計測器は動く
```

| 基準 | 結果 |
|---|---|
| 1 全体で B < A | ✅ |
| 2 個別で B < A が過半 | ✅ 31/46 |
| 3 改善が 0.01s 以上 | ✅ -0.0450s |
| **4 対照群で効果が消える** | **❌** |
| 5 注入を検出できる | ✅ |

## 🔴 基準4: 物理特徴をシャッフルしても同じくらい効く

```
シャッフル24回の A比  平均 -0.0210s  std 0.0235  範囲 -0.0601〜+0.0255
本物の A比                    -0.0450s
本物以上に良かったシャッフル      4/24  →  P ≈ 0.20
```

**31列を足すこと自体で平均 -0.021s 動く。** 本物の -0.045s はその分布の内側。
→ **物理特徴が未見コースへ一般化した証拠にはならない。不採用。**

⚠ 初版は**シャッフル1回**だけ回し、判定式も
`abs(shuf-A) < abs(B-A)` という緩いものだったので「✅」と出していた。
1回の比較では決まらない。**対照群は分布で見る。**

## ⚠ この検証の限界（「無い」とは言っていない）

- 対象が **46組・2,902レース**しかなく、検出力が低い
- **数値が埋まっているのは 17/46 だけ**で、実質カテゴリ（スタート地点・
  コーナー番号）を試している。カテゴリは会場と強く相関するので、
  会場 one-hot の上では情報が薄い

→ 言えるのは「**この検証では一般化能力を確認できなかった**」まで。
   数値のカバーが 17/46 → 46/46 になれば、初めて検出力のある検定になる。
   それが `docs/course_data_wanted.md` の中身。

## §18 感度検査（本データを見る**前**に通した）

ユーザー指示: 「既知の人工的な差を入れた場合、本当に差を検出できるか」。
通らなければ本データは読まずに中止する、という順序でコードに書いた。

```
注入  early := 0.0015 * s2c + 組内のばらつき
      （組間の差だけを s2c の一次関数に差し替える。組内のばらつきは実データのまま）
      s2c 160〜948m → 組間の差は 1.182s まで開く

  A  会場one-hotのみ      0.7733s
  B  + 物理特徴           0.7257s   A比 -0.0475s
  対照 シャッフル24回      平均 -0.0007s (std 0.0086)
  → P=0.040  ✅ 検出できる
```

## 本データ

```
  A  会場one-hotのみ      0.8459s
  B  + 物理特徴           0.8306s   A比 -0.0153s
  注入 真のオフセット       0.7345s   A比 -0.1114s  （到達不能な上限）
  対照 シャッフル24回      平均 +0.0412s (std 0.0224)
```

| 基準 | |
|---|---|
| 1 B < A | ✅ |
| 2 改善が 0.01s 以上 | ✅ -0.0153s |
| 3 シャッフルと区別できる | ✅ P=0.040（24回すべてが本物に届かず） |
| 4 感度検査を通っている | ✅ P=0.040 |

**到達可能な上限（-0.1114s）の 13.7% を取れている。**

## 🔑 何が変わったのか

| | g1（第1版DB） | g2（第2版DB） |
|---|---|---|
| 数値が埋まっている組 | 17/46 | **65/69** |
| 対照群の平均 | **-0.0210s** | **+0.0412s** |
| 対照群の std | 0.0235 | 0.0224 |
| 本物 | -0.0450s | -0.0153s |
| P | 0.20 ❌ | **0.040 ✅** |

g1 では**列を足す操作そのものが平均 -0.021s 動いていた**（欠損だらけの列でも
木が分岐に使えてしまう）。数値が埋まると対照群は +0.041s（＝悪化）側に寄り、
本物との距離がはっきりした。**本物の改善幅はむしろ小さくなったのに P は通った**。

⚠ P=0.040 は 24回シャッフルの**下限**（1/25）。「0/24 が本物に届かなかった」
以上のことは言えない。より細かい P と列の切り分けは `tenkai/g3.py`。

## ⚠ これが意味しないこと

- **予想が良くなったわけではない。** これはペースモデルの話で、
  本体モデル（3着内）は 会場one-hot -0.0003 / 展開特徴 -0.0006 と効かない
- **市場に勝てる話でもない。** ②（`zansa/RESULTS.md`）で市場残差に
  発走地点の偏りは無いと確認済み。ユーザーの⑤（盲点が見つかったら本体に戻す）は
  発動しない
- 言えるのは「**学習に出てこないコースのペースを、物理構造から推定できる**」まで
