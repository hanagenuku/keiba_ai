## 🔴 見つかった defect ①: ペースモデルは学習と推論で入力が別物だった

`train_pace_model.py` は19特徴量で3分類するが、そのうち6つがこの経路にある:

```
              学習時                        推論時
running_style そのレースの実際の脚質      →  過去走からの推定
agari3f       そのレースの実測値         →  **定数 36.0 / 1.5**（レース前なので無い）
  → escape_count / front_count / front_density
     avg_agari3f / std_agari3f / escape_avg_pos・escape_avg_pop
```

**推定脚質と実際の脚質の一致率は 39.8%。**

### 精度への影響（学習2025 / 検定2026・完全OOS・2,014レース）

```
無作為（3分類）                          33.3%
① 学習=実際 / 検定=実際                  52.80%   ← これが報告されてきた数字
② 同一レースで揃えて                      53.18%
③ 学習=実際 / 検定=推論時入力              50.45%   ← 🔴 **これが本番の実力**
④ 学習=推論時入力 / 検定=推論時入力         52.88%   ← 揃えるだけで +2.43pt
```

## 🔑 4分類ラベル自体が表現として悪い

3分類の精度で測ると作り直しても 52.69% で ④ と変わらない。理由は
**ラベルが距離帯×表面のパーセンタイルなので、距離そのものが最重要特徴量
（13.7%）になってしまい、展開の精度を測れていない**こと。

→ **前半3F を実数で予測して測り直す**方針に切り替えた。ここで defect ② を踏んだ。

## 🔴🔴 見つかった defect ②: 目的変数 `first_3f` が同じ距離で二峰だった

実数で測り直して最初に出た検定期 RMSE は **2.2590s** で、
**学習期の平均を答えるだけ（1.5288s）より悪かった**。
誤差の大きい順に並べると原因がすぐ出た:

```
ダート1700m  予測 29.7s / 実測 36.7s   ← 7秒ずれる
```

`race_history.first_3f` は「**記録された先頭3区間の和**」だった。
JRAのラップタイムは「スタート→最初の200m標識」が端数区間になるが、
**その端数を記録する回と記録しない回がある**:

```
ダート1700m  n=9  lap 7.1-11.1-12.4-…   → first_3f 30.05s  (248R)  先頭100mを記録
             n=8  lap 11.5-12.1-13.1-… → first_3f 35.53s  (101R)  記録しない
                                            差 5.48s（前半3F の std は 1.85s）
```

しかも端数を記録する割合は **2025-07 の 25.4% → 2026-08 の 0%** へ変わっている。
＝ **学習期と検定期で目的変数が別の量**になっていた。

### 直し方

`early_pace_seconds(lap_times, distance)` を新設。区間の**本数**から端数の有無を
判定し、どちらも「最初の200m標識からの3区間」に揃える（1700m ならどちらも 100m→700m）。

```
              修正前の差      修正後の差
ダート1700m    +5.48s   →    -0.18s
ダート1900m    +6.16s   →    +0.08s
検定期 RMSE    2.2590s  →    0.8459s
```

⚠ **最初の直し方は間違っていた。** `distance % 200` から端数の有無を決めたが、
   それは「端数が存在しうるか」であって「記録されているか」ではない。二峰は
   残った（+5.36s）。**本数**で判定して初めて揃った。

## 🔴 訂正: レース構成の特徴量は、正しい目的変数では**悪化させる**

初版はこの表を根拠に「③ は ⑤（反則版）の 2.3倍良い」と書いた:

```
【初版・壊れた目的変数での数字。無効】
① 条件だけ                     RMSE 1.5730s
③ + 作り直した連続量             RMSE 1.5071s   Δ -0.0659s
⑤ 反則: そのレースの実際の脚質      RMSE 1.5447s   Δ -0.0283s
```

**揃えた目的変数で測り直すと符号が反転した**（2窓・完全OOS）:

```
                        窓A(検定2026H1)   窓B(検定2026H2)
学習期の平均を答える           1.3617s          1.4262s
① 条件だけ                  0.8272s          0.8325s   ← 最良
② + P(先頭)由来              +0.0145          +0.0077
③ + 過去の通過位置            +0.0121          +0.0167
④ + 過去の上がり              +0.0130          +0.0051
⑤ + 全部                   +0.0151          +0.0210
```

**2窓ともプラス（＝悪化）で、どの群も片方だけでも改善しない。**
初版の -0.0659s は、二峰に割れた目的変数のうち「どちらの峰か」を
レース構成の特徴量が間接的に言い当てていた（＝時期の代理）だけだった。

⚠ 窓か目的変数かを切り分けるため、**両方の目的変数を両方の窓で**回して確認した。
   符号を決めていたのは目的変数のほうで、窓ではない。

## 🔑 結論: ペースは**レース条件だけ**で決める

```
PACE_COLS = ['dist', 'surface_num', 'cls', 'n_horses']
```

✅ 副産物として、**学習時と推論時の入力が構造的に同一**になる。
   defect ①（実際の脚質 vs 推定脚質・一致率 39.8%）が起こせなくなる。

⚠ `cond`（馬場状態）は**推論時つねに「良」**（出馬表に載っていない既知の
  パリティ違反、2026-08-26 に記録済み）。古い違反を直しながら新しい違反を
  入れないよう**外した**。外すコストは RMSE **+0.011s** だけ
  （0.8292→0.8404 / 0.8316→0.8417）。当日の馬場が取れるようになったら戻せる。

## 段1: 各馬の P(先頭に立つ) — これは残す

過去走のみから作る（`shift().expanding()` で当該レースを除外）。
159,552頭・学習〜2026-06-30 / 検定 9,551頭で **OOS AUC 0.7805**。

```
市場人気だけ        0.6148      過去の通過位置   0.7409
過去の逃げ率だけ      0.7118      騎手の逃げ率     0.5683
全部              0.7757〜0.7805
```

⚠ **ペース予測には使わない**（上の表のとおり悪化するため）。
   残す理由は別で、ユーザーの「逃げそうな馬は距離が持つか／逃げたことで他の馬に
   どう影響するか」に答えるには**馬ごとの量**が要るから。
   本体モデル（3着内）への寄与は別途 A/B で測る（→ `tenkai/AB.md`）。

段2のレース単位特徴量（`P_gap`＝単騎逃げ / `P_ent`＝やり合い / `n_can_lead` …）も
同じ扱い。旧実装では「逃げ馬2頭」が `escape_count=2` の一値になり、
単騎に近い(0.80/0.10)のと やり合い(0.45/0.45) が区別できなかった。
