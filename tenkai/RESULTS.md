## 🔴 見つかった defect: ペースモデルは学習と推論で入力が別物だった

`train_pace_model.py` は19特徴量で3分類するが、そのうち6つがこの経路にある:

```
              学習時                        推論時
running_style そのレースの実際の脚質      →  過去走からの推定
agari3f       そのレースの実測値         →  **定数 36.0 / 1.5**（レース前なので無い）
  → escape_count / front_count / front_density
     avg_agari3f / std_agari3f / escape_avg_pos・escape_avg_pop
```

**推定脚質と実際の脚質の一致率は 39.8%。**

### 精度への影響（学習2025 / 検定2026・完全OOS・2,014レース）

```
無作為（3分類）                          33.3%
① 学習=実際 / 検定=実際                  52.80%   ← これが報告されてきた数字
② 同一レースで揃えて                      53.18%
③ 学習=実際 / 検定=推論時入力              50.45%   ← 🔴 **これが本番の実力**
④ 学習=推論時入力 / 検定=推論時入力         52.88%   ← 揃えるだけで +2.43pt
```

## 🔑 4分類ラベル自体が表現として悪い

3分類の精度で測ると作り直しても 52.69% で ④ と変わらない。理由は
**ラベルが距離帯×表面のパーセンタイルなので、距離そのものが最重要特徴量
（13.7%）になってしまい、展開の精度を測れていない**こと。

**前半3F を実数で予測して測り直した**（同じ窓・2,082レース・前半3F std 1.85s）:

```
① 条件だけ（距離・表面・馬場・頭数・クラス）   RMSE 1.5730s  R² 0.2891
② + 既存の脚質カウント（推論時版）           RMSE 1.5439s  R² 0.3151   Δ -0.0290s
③ + 作り直した連続量                     RMSE 1.5071s  R² 0.3474   Δ -0.0659s
④ + 両方                              RMSE 1.5053s  R² 0.3490   Δ -0.0677s
⑤ 反則: そのレースの**実際の脚質**（天井）     RMSE 1.5447s              Δ -0.0283s
```

🔑 **③ は ⑤（事後の正解を知っている反則版）の 2.3倍良い。**
展開が説明する分散 **2.6% → 5.8%** で倍以上。
「逃げ／先行／差し／追込」の4分類は、正解を知っていても連続量に負ける。

## 設計（2段構え）

### 段1: 各馬の P(先頭に立つ)

過去走のみから作る（`shift().expanding()` で当該レースを除外）。
159,800頭・学習〜2025-06 / 検定 50,342頭で **AUC 0.7757**。

```
市場人気だけ        0.6148      過去の通過位置   0.7409
過去の逃げ率だけ      0.7118      騎手の逃げ率     0.5683
全部              0.7757
```

### 段2: レース単位の「隊列争い」

`P(先頭)` の**分布の形**で表す。ここがユーザーの
「逃げ馬が何頭いるか、人気の先行馬がやり合えば差しが決まる」の実装。

- `P_gap` = 最大 − 2番目 → **単騎逃げ**か
- `P_ent` / `P_hhi` → **やり合い**か
- `n_can_lead` = 過去に1度でもハナを切った頭数（平均でなく最小で見る）
- `n_front` / `pos_mean` / `pos_min` / `pos_std`
- `ag_mean` / `ag_min`（最終スピード）/ `pop_of_leader`

🔑 旧実装では「逃げ馬2頭」は `escape_count=2` の一値になり、
   単騎に近い(0.80/0.10)のと やり合い(0.45/0.45) が区別できなかった。
