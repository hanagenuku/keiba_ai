# O': 「推」マークの回収率で pace_bonus を測り直した（PR #247 の自己検証）

2026-09-14。基準は結果を見る前に `osusume/CRITERIA.md` に登録。
**本番のモデル・DB・latest.json・買い目には一切触れていない（読み取りのみ）。**

## なぜ測り直したか — 私の測定ミスの自認

P'（2026-09-13・PR #247）で pace_bonus を既定OFFにした根拠は
**3着内AUC（全馬の順位精度）**と**押し上げられた馬全体**だった。どちらも
「平均的に順位が良くなるか」を測っている。

ユーザーが指していたのは別の量だった。画面に出る**「推」マーク**は
`AI順位 ≤ 人気−3` かつ `AI順位 ≤ 8` かつ `sim_ev ≥ 1.2` の上位2頭で、
**1レースに0〜2頭しか出ない極めて選択的な集合**である。

🔑 **私は ROI 型の仮説を AUC 型の基準で閉じた。** pace_bonus が全馬の平均順位
精度を下げながら、同時に「推の集合」の回収率を上げていることは論理的にありうる。
North Star #9 は「的中率と回収率は別物」だが、その一段手前に
**「AUCとROIは別物」「全馬と選択された部分集合は別物」**がある。
結論は変わらなかったが、**閉じ方が間違っていた**ので測り直した。

## Step 0 計測器の検算（ここで一度止まった）

本番 `race_predictions` から pace_bonus を復元できるか。
`win_prob = softmax(total, T=3.5)` なのでレース内で `3.5·ln(win_prob) = total + const`。
`cal_prob` は pace_bonus が乗る**前**の生マージンの単調変換。よって
`rank(total − pb)` が `rank(cal_prob)` と一致しなければ復元は失敗している。

```
素の順位一致           81.6% / 91.9%   ← 低すぎる
原因: cal_prob の 32.6% が同点（キャリブレーターの床）
ペア一致で測り直し（同点ペアを除く）
  error_tags ON期(〜08-31)  補正なし 97.09% → pb を引くと 97.38%
  error_tags OFF期(09-01〜) 補正なし 98.47% → pb を引くと 99.47%
```
pb を引くと一致が上がる＝復元は正しい。ただし error_tags が乗っていた期間は
器が濁るので、**全期間と09-01以降を必ず分けて出す**ことにした。

  言えるのは「ONが良いとは言えない」までで、「OFFが良い」も言えない。

## 🔴🔴 Step 6 決定打: シャッフルが本物と完全に同じ

🔑 **機序が確定した。** 選ばれる頭数が ON 684 / SHUF 758 / OFF 536。
pace_bonus の効果は「どの馬を押し上げるか」ではなく
**順位に揺らぎを足すと `AI順位 ≤ 人気−3` に引っかかる馬が増える**という
選択幅の話で、同じ大きさの雑音なら中身を問わず同じ効果が出る。

⚠ P' Step 2 では 10+人気で符号反転の対照が本番を上回った（96.9% vs 68.3%）。
  今回は NEG が OFF と同じ。**2つの測定が食い違うこと自体が、この N では
  帯別のセルに分解能がない証拠**。
