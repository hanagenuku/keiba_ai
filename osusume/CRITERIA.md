# O': pace_bonus は「推」マークの回収率を上げていたか（結果を見る前に登録）

登録 2026-09-14。PR #247 をマージした**後**に書いている。
つまりこれは「自分の判断が間違っていたかを確かめる」ための事前登録である。

## なぜ измерить のか（私の測定ミスの自認）

P'（2026-09-13）で測ったのは **3着内AUC（全馬の順位精度）** と
**押し上げられた馬**全体（人気帯6セル）だった。どちらも「平均的に順位が良くなるか」。

ユーザーが指しているのは別の量である。画面に出る **「推」マーク**は
`ai_rank <= 人気-3` かつ `ai_rank <= 8` かつ `sim_ev >= 1.2` の上位2頭で、
**1レースに0〜2頭しか出ない極めて選択的な集合**。

🔴 pace_bonus が「全馬の平均順位精度」を下げながら、同時に
   「推の集合」を良くしていることは論理的にありうる。
   North Star #9 は「的中率と回収率は別物」だが、ここではもう一段手前の
   **「AUCとROIは別物」「全馬と選択された部分集合は別物」**が効く。
   私は ROI 型の仮説を AUC 型の基準で閉じた。それが誤りだったかをここで測る。

## 腕

- ON  : 本番そのまま（rl_rank / win_prob / 実オッズ）
- OFF : pace_bonus を除いた反実仮想
        ai_rank = rank(cal_prob)（＝生マージンの単調変換。定義上 pace_bonus 前）
        pn_OFF  = softmax((3.5*ln(win_prob) - pb)/3.5) をレース内で正規化
- 対照: pb の符号を反転した腕 / pb をレース内シャッフルした腕

## データ

`race_predictions`（2026-06-27〜09-13・749レース・9,784頭）に実オッズと実着順。
⚠ 2026-08-31 以前は error_tags 補正が乗っており復元が濁る（ペア一致 97.4%）。
  09-01 以降は 99.5%。そこで**必ず全期間と09-01以降を分けて出す**。

## 判定（結果を見る前に確定）

推の**単勝回収率・複勝回収率**を ON と OFF で比べる。

1. N: 推マークが ON/OFF とも 200点以上（満たさなければ「判定不能」と書く。
   小さいNの好成績を根拠にしない＝North Star #7）
2. 向き: ON − OFF が単勝・複勝**とも**プラス
3. 対照: 符号反転・シャッフルの腕が ON を上回らない
4. 頑健性: 上位3本の配当を抜いても向きが保たれる
5. 期間: 全期間と09-01以降で符号が同じ

- 1〜3 を満たす → **PR #247 を revert する**（pace_bonus を既定ONに戻す）
- 1〜3 のうち一部のみ → 「開いたまま」とし、次の週末以降で N を積む
- 1 を満たさない → 判定不能。閉じたとも開いたとも書かない
- 2 が逆（OFF の方が良い）→ #247 は正しかったと確認

⚠ 「100%を超えたか」は採用基準に入れない。ここで問うのは
   **ON と OFF のどちらが良いか**であって、儲かるかではない。
   100%超を主張するなら別途 Step 4（日ブロックCI下限>100%）が要る。
