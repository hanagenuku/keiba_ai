## アーム（結果を見る前に固定）

本番と同一構成: **134特徴量・`residual=True`・ドリフト注入ON**・同一ハイパラ。

| | 中身 |
|---|---|
| **M** | 市場単独（人気順位 → base_margin のみ。AI 特徴量なし） |
| **A** | 本番同型 134特徴量 |
| **A+X** | A に下記 X を足す |

CLAUDE.md の標準ゲート（市場単独 / AI単独 / AI×市場の三者比較）を**必ず当てる**。
2026-09-22 の Step 1 はこれを書き忘れ、測定後に当てる羽目になった。

## X の定義（3列だけ。事後に増やさない）

| 列 | 定義 |
|---|---|
| `x_rank` | 指数のレース内順位（1 が最上位。同値は平均順位） |
| `x_z` | 指数のレース内 z 値 |
| `x_gap` | **市場人気順位 − `x_rank`**（＋なら指数が市場より高く評価） |

⚠ 指数の**生値は使わない**。記事ごとにスケールが動く可能性を排除できていないため
  （レース内で正規化した3列だけにする）。

## 合格基準（すべて満たさなければ不採用）

1. **3窓すべてで ΔAUC > 0**（A+X − A）
2. **3窓平均 ΔAUC >= +0.002**、かつ**シード std の2倍以上**（3シード×3窓）
3. **Brier / LogLoss も同方向**（3窓とも）
4. **乖離の方向別**（`x_gap` が ＋/0/− の3群）で、**AI強気側だけで改善が出た場合は
   まず計測器を疑う**（2026-08-31 `corr(gap, 符号つき誤差) = -0.1213`）
5. **(a) 全行と (b) 部分集合の両方**で 1〜3 を満たす

## 対照群（North Star #11 の2つの形以外で書かない）

- **対照群A＝並べ替え分布**: レース内で指数をシャッフル 200 回。
  合格は `|mean(Δ_shuffle)| < 2*std/sqrt(200)`。実測の Δ は並べ替え P で報告する。
  **1回の引きの大小比較は書かない。**
- **対照群B＝注入の復元**: 目的変数に既知の効果を注入し、
  `注入後 − 注入前 = 注入量`（許容差 1e-3。これは代数恒等式の検算なので厳しくてよい）。

## 感度検査（本データを読む前に通す）

**計測器が動くことを先に示す。** 通らなければ本データを読まずに中止する。

- `x_rank` 単独の3着内 AUC が **0.5 を明確に超える**（部分データで 60.2%→15.0% の
  単調性が出ているので通る見込み。通らなければパースか結合が壊れている）
- 指数を**完全にランダムな順位**に置き換えたとき ΔAUC ≈ 0 になる

## 回収率も必ず出す（North Star #9）

AUC が上がることと回収率が上がることは別。複勝（`fukusho_payout`）で
**3本抜き・前後半・日ブロック bootstrap の95%CI**を併記する。
⚠ **AUC が通っても「儲かる」とは書かない。**

## 中止基準（先に決めておく）

- 感度検査が通らない → 本データを読まずに中止（パース/結合の修正が先）
- 基準1〜3のどれかが未達 → **不採用として閉じる**。X の定義・期間・推定仕様を
  変えて測り直さない（P3-01 / Betting Policy Step 1 と同じ扱い）
- 「DBにだけ多い」「双方に食い違い」が**1レースでも**出たら、原因を説明できるまで
  測定に進まない（2026-09-24 の部分データでは両方 0 だった）
