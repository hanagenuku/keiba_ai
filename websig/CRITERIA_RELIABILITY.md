# 事前登録カード: 蓄積した web 見解から「信頼できる情報源」を見極める基準

- 作成: 2026-10-23
- 対象: `data/web_findings_log.json`（`src/product/web_log.py`）に積まれる朝の web 見解
- 🔴 **このカードを書いた時点で見たのは「母数と構造」だけ**（情報源ごとの言及頭数・
  序列の有無・方向の有無）。**効果（グレード別の3着内率・回収率）は一度も計算していない。**
  カードを固めてから測る順序を守るため、ここに明記する

---

## 0. なぜこのカードを開いたか

ユーザー要望:
> そのＷＥＢ情報を蓄積し、結果と照らし合わせ信頼度の高いものを最終的に見極めたい

3段のうち前2段は 2026-10-22（CLAUDE.md row 35）で実装済み:

| 段 | 状態 |
|---|---|
| ① 蓄積 | ✅ `web_log.record()`。上書きしない・結果が無いレースを空で埋めない |
| ② 結果照合 | ✅ `web_log.attach_results()`。着順・3着内・複勝払戻・確定馬場 |
| ③ **信頼度の見極め** | ❌ **基準が無い。これをここで固める** |

## 1. 🔴 まず算術: **この台帳だけでは信頼度を測れない**

| | |
|---|---|
| 台帳の増えるペース | 週2日 × 10R/11R のみ ＝ **年間100件程度**（実測: 5開催日で97件） |
| 情報源あたりの言及レース | **1〜4レース**（実測） |
| 比較対象: `oikiri`（昨日の測定） | **838記事 / 印 6,575頭 / 対象レースの全馬 60,527頭 / 4,283レース**を**1セッションのうちに**取得（⚠ 「30分」は `websig` の 811記事・134,874頭 の実測値で、`oikiri` の所要は記録していない） |
| その差 | 台帳で `oikiri` と同じ N に達するのは **約10年後** |

🔑 **信頼度は「蓄積を待って」測るものではなく、「過去分を一括で取って」測るもの。**
`yosounohone` が1日で測れたのは sitemap に 2019-02 まで過去記事があったからで
（判定表の問い①）、台帳の蓄積ペースとは無関係。`websig` も sitemap から
**811記事・134,874頭を30分**で取っている。

→ **台帳の役割は2つに限定する。**

| 役割 | 中身 |
|---|---|
| (a) 記録 | 朝の見解と結果が**手作業なしで残る**（row 35 のとおり。これ自体が価値） |
| (b) **選別** | 「**どの情報源に測定予算を使うか**」を決める。効果の判定はしない |

🔴 **台帳の率（例「3着内 10/50」）を信頼度として読まない。** 理由は §2 の型の違い。

## 2. 情報源の型ごとに測定器が違う（共通の的中率1本では測れない）

実データ97件で確認した構造（効果ではない）:

| 型 | 情報源 | 1レースあたり言及頭数 | 序列 | 同レース対照群 | 測れるか |
|---|---|---|---|---|---|
| **型1 選別型** | `yosounohone` | **3頭** | ★（note の文中） | ✅ 同レースの印なし | ✅ `oikiri` で測って**不採用で閉じた** |
| **型2 全馬型＋序列あり** | `umasiru` | 中央値 **13.5頭** | note に 評価 S/A/B/C が **26/27** | ❌ 無い → **帯の間**に取る | 🟡 `grade` を構造化すれば測れる |
| **型3 全馬型＋序列なし** | `keibanomiryoku` | 中央値 **15.5頭** | 自由文のみ（評価記号 **2/51**） | ❌ 無い | 🔴 **測らない**（§2.3） |
| **型4 going** | `bloodline-trackbias` | — | — | 確定馬場との突合 | 🟡 §5 の形でだけ |

### 2.1 型1（選別型）の推定量
`oikiri/eval.py` と**同じ**。言及馬 M の3着内率 − **同レースの非言及馬** C の3着内率。
新しい定義を作らない。

### 2.2 型2（全馬型＋序列あり）の推定量
同レース対照群が構造的に存在しない（全馬にメモが付くので「印なし」が居ない）。
よって **レース内のグレード帯の差**で測る:

- 最上位帯（例 S・A）の3着内率 − 最下位帯（例 C・D）の3着内率
- 帯が3つ以上あるときは**すべての境界で単調**であること（基準3）

✅ これは**レース内で変わる量**なので、2026-09-15 の「レース内で一定の属性は市場が
何をしていようが構造的に0に潰れる」には当たらない。

### 2.3 🔴 型3 は測らないと**先に**決める
ほぼ全馬に**方向も序列も無いメモ**が付く情報源には、**当たり外れの概念が無い**。
全馬に言及すれば3着内率は母集団の3着内率（約20%）そのものになる。

🔴 **だから「keibanomiryoku の3着内率が20%だった」を「当たっていない」と読まない。**
読んでよいのは「**測れる形になっていない**」まで（2026-09-18 P3-02・2026-09-25 の
`closed_unmeasured` と同じ扱い。「効かないと分かった」とは書かない）。

測りたくなったら、先に情報源側の序列を `said.grade` に構造化して記録する
（§4）。それが溜まる前に測定予算を使わない。

## 3. 台帳が答える問い ＝ 「測定予算を使う価値があるか」（合格すれば per-source カードを書く）

🔴 これは**効果の合格線ではなく、測れるかどうかの線**（feasibility）。

| # | 問い | 線 | 読む場所 |
|---|---|---|---|
| F1 | **過去分が取れるか** | sitemap/月別アーカイブが history.db の全期間（2023-01-07〜）をカバー | 実地調査（判定表の問い①） |
| F2 | **レース内で変わる量か** | 序列（`grade`）または方向（`direction`）が**言及の 80% 以上**に付く | `summarize()` の `with_grade` / `with_direction` |
| F3 | **型が判別できるか** | `mentions_per_race` ÷ 出走頭数 が **0.5 以下**なら型1、超えれば型2/3 | `summarize()` の `mentions_per_race` |

  持っていた）。効果を見て決めた線ではない
- F1〜F4 の**どれかが落ちたら測定予算を使わない**。status は `rejected`（測って不採用）
  ではなく **`closed_unmeasured`** にする

## 5. 型4（going）の推定量 ── ベースラインを必ず置く

🔴 **「収集時点の馬場 == 確定馬場」は予想の精度ではない**（馬場が動かなかった率。
実測 21/21 = 100%）。採点できるのは `expected` が状態名を名乗ったときだけ。

| # | 基準 | 線 |
|---|---|---|
| G1 | ベースライン超え | **「常に『良』と答える」戦略の的中率**を上回る（確定馬場は良に強く偏る。2026-08-27 実測で良 110,908 / 稍重 25,676 / 重 12,719 / 不良 5,189 ＝ 良が **71.8%**）|
| G2 | 標本 | 採点できた件数 **>= 300** |
| G3 | 用途 | 🔴 **本体モデルへの寄与は期待しない**（馬場バイアスは4回否定済み）。用途は `f_track_cond` のパリティ違反（推論時つねに 0.0＝良／良以外は 27.2%）と `going.py` の穴（R1前・前日夜）を埋めることだけ |

⚠ 現状 `expected` が状態名を名乗るのは **11件中9件**（`bloodline-trackbias`）。
G2 に達するには約15年。→ §1 と同じ結論で、**過去記事の一括取得**が前提になる。

## 6. per-source カードが使う採用基準 ── `oikiri/CRITERIA.md` をそのまま使う

🔴 **新しい合格線を発明しない。**（F1〜F4 を通った情報源について書くカードに、
以下をそのまま写す）

| # | 基準 | 合格線 |
|---|---|---|
| 1 | 主効果 | 型1: M − C >= **+5.0pt** ／ 型2: 最上位帯 − 最下位帯 >= **+5.0pt** |
| 2 | 標本 | **N(M) >= 1,000** |
| 3 | 単調性 | 帯の**すべての境界で**単調 |
| 4 | 市場統制 | 市場人気3分位の**各分位内で**同符号、かつ平均 >= **+3.0pt** |
| 5 | 安定性 | 前半・後半で基準1が**両方とも** >= +5.0pt |
| 6 | **回収率（判定指標）** | 複勝1点で **100% 超**、かつ **3本抜きでも100%超** |
| 7 | 本番への上乗せ | 本番同型（134列・残差・ドリフト注入ON・3窓×3シード）で **ΔAUC が3窓とも正** |

### 市場比較ゲート（CLAUDE.md の標準。書き忘れない）
- **市場単独 / 信号単独 / 市場＋信号** の複勝AUC 3者比較
- **乖離の方向別**（信号が市場より高く見ている / 一致 / 低く見ている）
- 🔴 信号が市場より強気な側で改善が出たら**まず計測器を疑う**

## 7. 事前の見積り（結果を見る前に書いておく）

🔴 **調教評価という次元は昨日 天井を測った。**

| 記録 | 内容 |
|---|---|
| 2026-10-22 `oikiri` | ★あり **33.61%** vs 同レースの印なし **19.74%** ＝ **+13.87pt（1.70倍）**・N=6,575・単調性も市場統制も安定性も通った。🔴 **それでも複勝回収 85.02%**（控除率20%で +5.0pt）／**市場単独 0.8060 → 市場+★ 0.8059（−0.0001）** で不採用 |
| 2026-09-25 `websig` | kayochin は 134,874頭・全レース全馬・連続量で ΔAUC +0.002〜0.004・対照群健全でも**複勝回収 79.7% → 79.1% と悪化** |
| 2026-08-18 | **OPだけAIの上乗せがマイナス（−0.0039）**。`keibanomiryoku` は重賞中心＝この母集団と一致 |
| 2026-08-03 / 08-17 | 市場人気だけ 複勝AUC 0.8248 vs AI 134列 0.8252（**+0.0004**）／別年 +0.0009 |

🔑 **`umasiru` / `keibanomiryoku` の調教メモは `oikiri` と同じ次元**（追い切りの評価）。
別の情報源・別の評価だから自動的に同じ結果とは言えないが、**事前見積りは
「3着内率は動くが市場の上では何も足さない」**（North Star #9）。

→ 🔴 **だから per-source カードを書く前に、基準6（複勝回収率）と市場比較ゲートで
落ちる可能性が高いことを先に書いておく。** 落ちたらそう記録して閉じる。

## 8. 落ちたときに書く文（先に決める）

- **F1〜F4 で落ちた場合**:
  > この情報源は、信頼度を測れる形になっていない（序列も方向も無い／過去分が取れない）。
  > 🔴 **効かないと分かったのではない。測っていない。** status は `closed_unmeasured`。
- **基準1〜5 で落ちた場合**:
  > 信号は無い。status を `rejected` にし、**定義・閾値・期間・結果変数を変えて
  > 測り直さない**。
- **基準6（回収率）または市場比較ゲートで落ちた場合**:
  > 3着内率は動くが、市場の上では何も足さない（`oikiri` と同じ結末）。
  > **web 情報は無意味ではない。この情報源のこの評価が、市場の上では足さない。**
