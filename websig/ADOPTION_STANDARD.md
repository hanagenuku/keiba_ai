# web 情報源を予想に反映する基準（v2・2026-11-11 ユーザー決定）

> ユーザー決定（2026-11-11）: 「**的中率（3着内率）や順位付けの精度で判定する基準に替える**」。
> それまでの判定指標は「複勝回収率 100% 超」だった。これは一度も達成されたことがなく、
> そのままではどの情報源も永久に反映されなかった（`docs/sessions/2026-11-10_web収集の拡大.md`）。
>
> 🔴 この文書は**基準を先に固める**ためのもの。書いた時点で、この基準での測定は1件もしていない。
> 🔴 以後、情報源ごとのカード（`CRITERIA*.md`）はこの基準を**そのまま写す**。情報源ごとに線を動かさない。

## 1. 何が変わったか

| | v1（〜2026-11-10） | v2（2026-11-11〜） |
|---|---|---|
| 判定指標 | 複勝回収率 100% 超（3本抜きでも） | **順位付けの精度（AUC）と ◎ の的中率** |
| 回収率 | 合否を決める | **合否は決めない。必ず報告し、大きく悪化したら止める**（§3-4） |
| 確率の当てはまり（Brier/LogLoss が全窓で改善） | 必須（kayochin はここで落ちた） | 必須にしない。報告はする（確率は後段の較正器が当て直すため） |

🔴 変わらないこと: 的中率と回収率は別物（North Star #9）。**この基準を通っても「儲かる」とは言えない。**
記事・商品で「web 情報を入れたので回収率が上がる」と書かない。

## 2. 前提条件（1つでも欠けたら測らない。status は `closed_unmeasured`）

| # | 条件 | 理由 |
|---|---|---|
| P1 | **過去分が取れる**（history.db の期間と重なる記事が残っている） | 学習データが作れない情報は特徴量にできない（North Star #3） |
| P2 | **当日の予想生成より前に取れる**（公開時刻を記事から読み、発走後公開の分は落とす） | 推論時に無い値で学習するとリーク（North Star #8） |
| P3 | **レース内で変わる量**（序列・評価・印） | レース内で一定の量は順位付けに効かない |
| P4 | **取得してよい**（robots・規約） | — |
| P5 | 学習と推論が**同じ関数**で値を作る（`src/features/web_signals.py`） | 学習/推論パリティ |

## 3. 合格基準（すべて満たしたら採用）

測り方は本番同型: 134列・`residual=True`・ドリフト注入ON・`train_xgb` を再利用・3窓 walk-forward × seed 42 / 7 / 2026。
腕は **A＝現行** と **X＝現行＋その情報源の列** の2つ。

| # | 基準 | 合格線 |
|---|---|---|
| 1 | 順位付け（AUC） | **3窓すべてで ΔAUC > 0**、かつプール平均 **+0.002 以上**、かつシード std の2倍以上 |
| 2 | ◎の的中率 | ◎（各レースでスコア1位の馬）の複勝的中率が、プールで **A を下回らない**（Δ >= 0） |
| 3 | 対照群 | **A＝並べ替え分布**（その列をレース内でシャッフルした腕 XR。ΔAUC の帰無が0中心）／**B＝注入の復元**（North Star #11 の形） |
| 4 | 回収率のガード | ◎の複勝回収率が A より **2.0pt を超えて悪化しない**（3本抜きでも）。⚠ 2.0pt はこの規模（約3,000レース）の回収率の標準誤差と同程度に置いた。これより細かい差は判定できない |
| 5 | 市場比較 | 市場単独 / 信号単独 / 市場＋信号 の AUC を並べて報告する（合否には使わない） |

- 基準1の線（+0.002・std×2）は 2026-08-24 のアンサンブル検証・2026-09-25 の websig と同じ。新しく作っていない。
- Brier・LogLoss・回収率は**必ず報告する**。合否には使わない（基準4のガードを除く）。
- 測定は1回。落ちたら定義・期間・閾値を変えて測り直さない。

## 4. 採用したあと

- `data/source_registry.json` の status を `adopted` にし、`card`・`results`・`measured.delta_auc_mean`・`feature_cols` を埋める
  （`src/utils/source_registry.py` が4つ揃っていない採用を無効化する。ここは変えていない）。
- 本番モデルを**その列を入れて再学習**し、較正器を当て直す。`model_registry.save_version` で旧版を残す。
- 反映は**上流の特徴量として**入れる。出力を後から書き換える層にしない。
- **取れなかったレース・馬は欠損（NaN）のまま**通す。0 や平均で埋めない。
- 採用後も台帳の結果照合は続ける。**2窓続けて ΔAUC が負になったら外す**（外す基準も先に決めておく）。

## 6. 「信頼できる情報だけで予想が完結する」への道筋

1. 広く集める（2026-11-10〜。全レース・馬場／追い切り評価／予想家の印）
2. 台帳で結果と照合し続ける（自動）
3. 過去分が取れる情報源から順に、この基準で測る
4. 通ったものだけ特徴量として入れる。通らなかったものは集め続けるが、予想には入れない
5. 採用後も外す基準（§4）で見張る
