# 事前登録カード: kayochin 能力指数の確認測定（基準 v2・未読の窓で1回）

- 作成 2026-11-11。基準は `websig/ADOPTION_STANDARD.md`（v2）を**そのまま**使う。線を動かさない。
- 🔴 このカードを書いた時点で、下の窓で kayochin を入れたモデルの数字は**1つも見ていない**。

## 0. なぜ測るか

2026-09-25 の測定（`websig/RESULTS.md`）で kayochin 指数は ΔAUC +0.00227（3窓とも正）だったが、
当時の基準（Brier が全窓で改善・回収率）で不採用になった。2026-11-11 にユーザーが基準を
「的中率と順位付けの精度」に替えた。**結果を見たあとで基準を替えたので、既読の窓では採否を決めない。**
既読の評価窓は 2026-03-01〜08-16。ここでは **2026-08-22 以降だけ**を使う。

## 1. 窓（walk-forward・3つ）

| 窓 | 学習の末尾 | 評価 | レース数（history.db・結果を見る前に数えた） |
|---|---|---|---:|
| W1 | 2026-08-21 | 2026-08-22〜09-20 | 299（10開催日） |
| W2 | 2026-09-20 | 2026-09-21〜10-18 | 227（10開催日） |
| W3 | 2026-10-18 | 2026-10-19〜11-08 | 185（6開催日） |

- early stopping は学習期間の末尾42日（内側ホールドアウト）。評価窓は学習にも停止にも使わない。
- 予測は**全木**（本番と同じ）。シード 42 / 7 / 2026。
- ⚠ これらの窓は、別の問い（再学習・学習設定・◎の差し替え）では既に読まれている。**kayochin を足した腕では読まれていない。**
- ⚠ **窓が小さい。** 1窓あたり約2,500〜4,000頭で、窓ごとの ΔAUC の誤差は効果の見込み（+0.002）と同程度かそれ以上。
  本当に +0.002 の効果があっても「3窓すべて正」を偶然で外す確率が小さくない。これは基準を緩める理由にはしないが、
  読み方を §5 に先に決めておく。

## 2. 腕

| 腕 | 列 |
|---|---|
| A | 本番と同じ134列 |
| X | A ＋ `f_ws_kayochinkeiba_rank` / `f_ws_kayochinkeiba_z`（`src/features/web_signals._ranks_and_z` で作る。本番と同じ関数） |
| XR | X の2列を、**レース内で指数を並べ替えて**作り直したもの（対照群A・30回・seed 42） |
| XZ | X の2列の代わりに、既知の信号 `z = y + N(0, 1.8)` とそのレース内順位を入れたもの（対照群B） |

- ハイパーパラメータは本番（`max_depth=6, lr=0.05, mcw=10, scale_pos_weight=(1-r)/r`）。`hitrate/eval_b.py` の P0 の学習関数を再利用する。
- `residual=True` 相当（`base_margin`）・ドリフト注入ON・行と `base_margin` は全腕で同一配列。
- 指数が無い馬は **NaN のまま**渡す（0 や 5.0 で埋めない）。A の134列は本番どおり `fillna(5.0)`。
- 🔴 **リーク防止**: 指数は、記事の公開時刻がレース当日の 08:50 JST より前の行だけ使う。落とした件数を印字する。
- 対照群A を 200回ではなく **30回**にするのは計算時間のため（1回＝3窓の学習）。合格は `|mean(ΔAUC_XR)| < 2*std/sqrt(30)`。

## 3. 合否（`ADOPTION_STANDARD.md` §3 のとおり。全行で判定する）

| # | 基準 | 合格線 |
|---|---|---|
| 1a | 窓ごとの ΔAUC（X−A・3シード平均） | **3窓すべて > 0** |
| 1b | プール ΔAUC（3シード平均） | **+0.002 以上**、かつ 3シードの std×2 以上 |
| 2 | ◎（スコア1位）の複勝的中率（プール・3シード平均） | **X >= A** |
| 3 | 対照群A（XR の帰無が0中心）／対照群B（XZ の ΔAUC が **+0.01 以上**＝計測器は既知の信号を拾える。`roi(bonus=5)` の差がちょうど +5.00pt） | 両方通過 |
| 4 | ◎の複勝回収率（プール・3シード平均） | X − A >= **−2.0pt**（3本抜きでも） |

報告だけするもの（合否に使わない）: Brier・LogLoss・単勝回収率・指数がある行だけの ΔAUC・市場単独／指数単独の AUC・窓ごとの被覆率。

## 4. 中止条件（AUC・的中率・回収率を読む前に印字して判定）

1. 特徴量列が本番の134列と一致しない
2. A のプール AUC が 0.77〜0.81 の外（記録: 同時期の本番同型で 0.787〜0.788）
3. A の `best_iteration` が 7〜15 の外（切片で止まる本番の挙動を再現していない）
4. いずれかの窓で、指数が1頭以上付いたレースの割合が 60% 未満
5. 指数単独（z）の評価窓 AUC が 0.70 未満（突合が壊れている。記録は 0.77〜0.80）
6. 公開時刻のフィルタ後に、当日 08:50 以降公開の行が1件でも残る
7. 対照群B の注入列 z 単独の AUC が 0.63〜0.68 の外

該当したら結果を読まずに破棄し、原因を直してカードを書き直す（測定回数に数えない）。

## 5. 結果の読み方（先に決める）

| 結果 | 判定 |
|---|---|
| 1a〜4 をすべて満たす | **採用**。別PRで ①当日朝に指数を取る経路 ②指数つきで本番モデルを再学習 ③較正器の当て直し を行い、実測を添えて報告してから本番に入れる |
| 1b は満たす（プール +0.002 以上・std×2 以上）が、1a だけ落ちる（負の窓がある） | **保留**。今は採用しない。収集は続け、**未読の評価窓が新しく3つ（各10開催日以上）溜まった時点で1回だけ**同じカードで測り直す。それで落ちたら閉じる |
| 1b を満たさない、または 2・4 を満たさない | **不採用（v2 でも）**。定義・期間・閾値を変えて測り直さない。収集は続ける |
| 3 が通らない | 計測器の不具合。結果を採用にも不採用にも使わない |

## 6. 採用になった場合に守ること（先に書く）

- web の2列は学習でも推論でも **NaN を NaN のまま**通す。既存の `fillna(5.0)` の対象に入れない（入れると「順位5位・z=5」という嘘の値になる）。
- 指数は開催日の朝の予想生成より前に取り、取れなかった日は NaN で通す（予想を止めない）。
- 「web 情報を入れたので回収率が上がる」と書かない。
